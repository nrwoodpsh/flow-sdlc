# 내보내기

**고친 것을 내보내는 순서**

**고친 것은 push 전까지 안 붙는다.** 마켓 소스가 github이라 `/reload-plugins`는 캐시(`~/.claude/plugins/cache/flow-sdlc/flow/{버전}/`)를 다시 읽는다 — 작업 트리를 보지 않는다. **훅도 마찬가지다.**

| 순 | 무엇 | 어떻게 |
|:--|:--|:--|
| 1 | **검사** | 문서를 고쳤으면 `python3 scripts/lint-docs.py` · 훅을 고쳤으면 `bash scripts/tests/hooks.test.sh`. **`바꿀 때 같이 고칠 곳`을 함께 훑는다** — 검사가 안 잡는 연쇄가 대부분이다 |
| 2 | **커밋** | **`git status`로 미추적을 먼저 본다** — 새 파일을 안 담으면 버전만 올라가고 **반쪽이 나간다. 에러가 안 난다.** 버전은 여기선 무관하다(내 기계에서만 산다). `plugins/flow/**`가 바뀌었으면 3으로 갈지 묻는다 |
| 3 | **내보낸다** | **HEAD 버전을 먼저 본다** — 작업 트리가 이미 올라가 있으면 다시 올리지 않는다. 아니면 `bump-version.sh` → 같은 커밋에 포함 → push(사람이). **여기가 분기다** — 안 내보내면 2에서 끝이다 |
| 4 | 받는 쪽 | `/plugin marketplace update flow-sdlc` → `/reload-plugins`. **`project` 스코프는 프로젝트마다 따로** |

**훅을 고쳤으면 되돌려서 실패하는지도 확인한다** — 안 잡히면 그 케이스는 아무것도 안 지킨다. `hooks.test.sh`는 `guard-danger`·`drift-hook`만 본다. **`check-drift-hook.sh`는 케이스가 없어 손으로 확인한다.**

**2의 물음**

```
플러그인이 바뀌었습니다. 팀에 내보낼까요?
  내보낸다      → bump-version.sh 실행 후 같은 커밋에 포함
  아직 아니다    → 그대로 커밋 (버전 안 올림)
  1.0 을 찍는다  → bump-version.sh major
```

- **버전이 캐시 키다** — 안 올리면 설치측이 옛 디렉터리를 계속 쓴다. **push는 성공하고 에러도 안 난다.**
- 등급을 나누지 않는다 — 설치측은 **같나 다르나만** 본다. `major`는 `1.0`을 찍을 때고, **기준은 사람이 정한다.**

**커밋 메시지**

```
타입(범위): 한국어 한 줄 요약 [flow N.N.N]

- 바꾼 것이 여럿이면 **왜** 를 불릿으로

Co-Authored-By: …
```

- **타입**: `feat` · `fix` · `docs` · `refactor` · `perf`
- **범위**: 고친 자리 — `flow` · `commands` · `setup` · `spike` · `readme` · `guide` · `ref`. 없으면 새로 짓는다
- **`[flow N.N.N]`은 버전을 올린 커밋에만** 붙인다.

## 경계

- **push 는 하지 않는다** — 사람이 외부 툴로 한다. 훅이 막는다.
- **버전을 임의로 올리지 않는다** — 위 물음으로 사용자에게 확인한다.
- 커밋 범위가 모호하면 `git add -A` 하지 않고 묻는다.
