# flow — 워커 오케스트레이션

`00.concept.md` 의 **능력 12** 설계다. `04.redesign.md` 의 **T7** 이 여기고 결함 **D7** 도 여기서 닫힌다.
구조 원칙은 `01.architecture.md` 를 따른다 — **강제력 등급을 섞지 않고, 약속을 기계라고 적지 않는다.**

## 출발점은 이 리포가 겪은 사고다

지금 작업 자체가 오케스트레이션으로 돌아갔고 한 번 죽었다(`00.diagnosis/review-v2-resume.md` 1절).
설계 입력은 "무엇이 좋아 보이나" 가 아니라 **무엇이 살아남았나**다.

| | 무엇 | 그래서 |
|:--|:--|:--|
| 살아남음 | repo 안의 파일 — 진단 3건·리뷰 4건이 `doc/00.diagnosis/` 에 | **정본은 repo 안이다** |
| 낡음 | 태스크 기록 — 마지막 태스크가 `ready` 인데 일은 이미 끝나 있었다 | **저장된 상태를 판정으로 쓰지 않는다** |
| 사라짐 | 워커 scratchpad(`/private/tmp/…`) · 워커가 넘긴 `reportPath` | **scratchpad 를 리포트 정본으로 삼지 않는다** |
| 죽음 | `orca` 실행 경로(심볼릭 링크) — 코디네이터가 디스패치 불가 | **실행 층은 우리 것이 아니다. 우리가 만들면 같이 죽는다** |

네 줄이 아래 결정 거의 전부의 근거다. **새 규약을 발명한 자리는 하나(한도)뿐이고, 나머지는 이미 있는
정본을 워커 축으로 읽은 것이다.** 능력 12 가 "핵" 인데 새로 만들 것이 적은 이유는 그 정본들이
원래 한 워커를 전제로 쓰여 있었을 뿐이기 때문이다.

## 경계 — flow 는 계획과 판정, 환경은 실행

**판정 기준을 한 줄로 둔다: 프로세스를 알아야 하는 것은 밖이다. flow 가 아는 것은 파일뿐이다.**

근거는 위 표의 마지막 줄이다. 이번에 죽은 것은 설계도 산출물도 아니라 실행 층이었고,
flow 가 그 층을 가졌다면 flow 째로 죽었다. 사용자 결정(*"밖의 도구를 대체하지 않는다"*)과 같은 결론이
사고에서도 나온다.

flow 가 남기는 것 — **거의 다 이미 있다.**

| 산출 | 어디에 | 새로 만드나 |
|:--|:--|:--|
| 분할 계획 — 배타 단위 목록·의존 순서 | task 문서의 `## 3. File Map` + 유닛·task 번호 | **이미 있다** |
| 워커 지시서 — 대상·읽을 것·착지처·금지 | task 문서 + `topology` 의 `loads` | **이미 있다.** 형식은 열린 질문 1 |
| 수렴 규약 — 무엇을 어디에 쓰고 무엇이 완료인가 | 유닛 스파인 `4.build/NN`·`5.verify/NN` | 이미 있다 |
| 판정 규약 — 누가 무엇을 판정하나 | `entry`·`exit.content` 의 `who` | 이미 있다 |
| 자원 한도 | `workflow.config.json` | **없다 → 만든다** |

안 하는 것 — 프로세스를 띄우고·죽이고·다시 띄우는 것 · 워커↔코디네이터 메시지 전달 · 생존 감시 ·
워크트리 분리 · 모델 API 호출 · 큐·락. 전부 환경(Orca · Claude Code 의 위임 도구 · CI 매트릭스)이다.

## 일 가르기 — 능력 9 와 같은 입력, 반대 방향의 계산

같은 계산이 아니다. **묻는 것이 반대다.**

| | 능력 9 (영향 범위) | 능력 12 (일 가르기) |
|:--|:--|:--|
| 묻는 것 | 이걸 고치면 어디가 깨지나 | 누가 무엇을 쓰나 |
| 방향 | 의존을 따라 **넓힌다** | 소유를 **가른다** — 교집합이 비어야 한다 |
| 입력 | 코드 그래프 + File Map 의 `[Mod]` | task 문서 File Map 전부 |
| 산출 | 회귀 표면(읽을 곳) | 배타 집합(쓸 곳) |

- **그래서 순서가 있다. 능력 9 가 능력 12 의 선행 조건이다.** 영향 범위를 먼저 뽑지 않으면 `[Mod]` 가
  빠지고, 빠진 경로는 소유 집합에 없어 두 워커가 같은 파일을 고친다. **이 리포 작업에서 실제로
  조심한 지점이 이것이고**, 조심으로 막았다는 것은 곧 기계가 없었다는 뜻이다.
- **단위는 task 다. 유닛이 아니다.** 근거: 소유의 정본이 File Map 이고 그것은 task 문서의 절이다
  (`topology` 의 `gate.fileMap` 이 이미 그 정규식을 갖는다). 유닛으로 가르면 굵어서 병렬이 거의 안 되고,
  파일보다 잘게 가르면 소유를 적어 둔 정본이 없다.
- **의존 순서도 이미 있다** — 유닛 번호가 의존 순서(`procedures/design/system.md`), task 번호가
  스파인(`traceability/unit-state`). **번호가 곧 배정 순서다.** 새 그래프를 만들지 않는다.
- **겹치면 계획을 고치지 않고 직렬로 돌린다.** 겹침을 없애려고 File Map 을 손대는 것은 쓰기 게이트의
  판정 근거를 바꾸는 것이다. 병렬은 편의고 게이트는 근거다.

**겹침 없음을 기계가 사전에 막지 못한다** — 워커를 띄우는 것이 도구 호출이 아니라 훅이 볼 시점이 없다.
그러나 **사후 방어는 이미 기계다**: 워커가 남의 소유 파일을 쓰면 그 경로는 자기 task 의 File Map 에
없으므로 `gate-source-write.sh` 가 막는다(`unitResolution: declared-file-map`). **새 훅을 만들지 않는다.**

## 판정 독립성 — 워커 축이 더하는 것은 판정자가 아니라 신뢰의 근거다

판정자는 그대로다. `exit.content` 의 `who: gatekeeper` 이고, 판정자 정본은 `grades.content.judges` 다.
늘리지 않는다 — 그 정본이 스스로 적어 둔 대로 **판정자를 늘리는 비용은 도구 권한**이고, 워커를 띄워야
하는 쪽은 도구가 필요하니 판정자가 될 수 없다.

워커 축에서 새로 생기는 위반은 둘이고 **둘 다 판정자 문제가 아니다.**

| 새 위반 경로 | 무엇이 문제인가 | 결정 |
|:--|:--|:--|
| 워커의 완료 보고가 판정을 대신한다 | 코디네이터가 보고를 근거로 다음을 띄운다 = 자기 보고가 게이트다 | **보고는 캐시, 파일이 정본** |
| 코디네이터가 직접 판정한다 | 진행하는 쪽이다 — 능력 2 정면 위반 | 판정은 `gatekeeper` 가. **코디네이터 에이전트를 만들지 않는다** |

- **`traceability/unit-state` 가 이미 그 문장을 갖고 있다** — *"상태의 정본은 파일이고 README 는 캐시다."*
  **워커 리포트를 README 와 같은 등급으로 내린다.** 새 규칙이 아니라 같은 규칙의 대상 확장이다.
  근거는 실측이다 — 이 리포에서 태스크 기록이 사실과 어긋났다.
- 전환 게이트를 두 번 돌리지 않는다. `next.md` 가 이미 정했다 — *"이미 걸었으면 결과를 받아 쓰고, 없으면
  여기서 건다."* **워커 축에서는 결과가 파일로 없으면 없는 것이다.** 보고로 있다고 하면 없는 것으로 센다.
- **워커가 워커를 판정하게 하지 않는다** — 아래 버린 안.

## 거둬들이기 — 새 자리를 만들지 않는다

리포트가 흩어지면 아무도 안 읽는다. 그런데 **모으는 자리를 새로 만들면 정본이 둘이 된다**(능력 7).

| 무엇 | 어디에 모으나 | 근거 |
|:--|:--|:--|
| 국면 산출 | 유닛 스파인 그대로 — `4.build/NN.md`·`5.verify/NN.md`·`6.review/` | 착지처가 이미 정해져 있다. 워커가 자기 국면의 정본 자리에 쓴다 |
| 런 단위 종합 | **`/flow:sync`** | 색인·요약의 정본이 이미 `sync` 다. 오케스트레이션 전용 요약을 두면 정본이 둘 |
| 국면 밖 판단 — 왜 그렇게 했나·버린 시도 | task 문서의 `History` 절 | `next.md` 가 이미 재개 때 그것을 읽는다 |

- **거둬들이기는 수집이 아니라 계산이다.** 워커에게 결과를 물어 모으는 것이 아니라, **파일을 세서**
  어디까지 됐는지 계산한다 — `unit-state` 그대로다. 워커가 죽었든 살았든 답이 같다.
- 이 리포에서 실제로 읽힌 것은 `doc/00.diagnosis/*.md` 였다. **repo 안이라서 읽혔다.**

## 죽어도 이어가기 — 상태를 저장하지 않고 계산한다

| 규칙 | 근거 (실측) |
|:--|:--|
| 워커 산출은 repo 안에 쓴다 | scratchpad 가 비워졌다. `reportPath` 는 죽은 경로였다 |
| 상태를 저장하지 않는다. 파일에서 계산한다 | 저장된 태스크 상태가 낡았다 — 완료를 기록하기 전에 런이 죽었다 |
| 재개는 계획 복원이 아니라 **같은 계산의 반복**이다 | 죽은 시점의 계획을 복원할 필요가 없다 → **원장이 필요 없다** |

재개용 새 커맨드도 새 파일도 없다. `next` 가 파일에서 계산하는 것이 이미 그 일이다.

**못 잡는 것** — 코디네이터가 죽고 워커가 살아 있는 경우(고아 워커). flow 는 프로세스를 모른다.
**재개 전에 사람이 남은 워커를 정리한다** — 약속이다. 기계로 적지 않는다.

## 자원 한도 — 값은 사람이, 자리는 flow 가

- **값은 `workflow.config.json` 에 사람이 적는다.** 근거: 모델명·비용은 낡는 값이고, 앞선 판이 그것을
  규모 게이트 3벌에 하드코딩했다(`01.architecture.md` 의 정리 표 — *"낡는 값은 본문에서 뺀다"*).
  동시 수는 사용자의 구독·기기 제약이라 우리가 기본값을 정할 수 없다.
- **flow 가 정하는 것은 값이 아니라 규칙 둘이다.**
  ① 한도를 넘는 계획을 내지 않는다 — 배정 목록을 한도 안으로 자르고, 나머지는 다음 차례로 둔다.
  ② **판정자를 진행자보다 싼 등급으로 내리지 않는다.** 판정이 유일한 게이트라 거기가 약해지면
  나머지 층이 다 무의미하다. 역할↔등급 대응은 사용자 결정이다(열린 질문 2).
- **등급은 약속이다.** 띄우는 것이 환경이라 flow 가 한도를 못 막는다.

## 강제력 등급 — 이 능력에서 기계인 것은 하나다

| 무엇 | 등급 | 무엇이 그렇게 만드나 |
|:--|:--|:--|
| 워커가 남의 소유 파일에 쓰는 것 | **기계** | `gate-source-write.sh` — File Map 에 없는 경로면 막는다. **새 훅 없음** |
| 위 기계의 범위 | — | `declared-file-map` 모드일 때만. fallback·`Bash` 밖 경로·MCP 는 밖(`grades.machine` 의 `우회` 가 정본) |
| 분할에 겹침이 없다 | 약속 | `next` 가 계획할 때 계산한다. 안 해도 아무도 모른다 |
| 워커 산출의 내용 충족 | **분리 판정** | 기존 `exit.content` 의 `who: gatekeeper`. **발동 자체는 약속** |
| 워커 보고를 판정으로 쓰지 않는다 | 약속 | 거둬들이기가 파일을 세니 repo 에 없는 것은 없는 것이 된다 — **완화지 기계가 아니다** |
| 산출이 repo 안에 있다 | 약속 | 워커가 scratchpad 에 쓰는 것을 막는 훅은 없다 |
| 동시 수·모델 한도 | 약속 | 띄우는 것이 환경이다 |
| 지시서에 모델명이 박히지 않는다 | **기계**(신설) | 새 `lint` 검사. 한도를 강제하는 게 아니라 정본이 갈라지는 것을 막는다 |

## `next` 가 든다 — 새 커맨드를 만들지 않는다

| 근거 | |
|:--|:--|
| 새 국면이 아니다 | 산출물이 없고 착지처가 없다. 위상에 노드를 더하면 진입·퇴장이 빈 노드가 늘고 **그 병이 D7 이다** |
| `next` 가 이미 대부분을 든다 | 파일 계산 · 게이트 위임 · 재시도 상한 · 정지 자리 · 되돌아가기. 그리고 *"대상 목록이 새로 정해질 때 멈춘다 — 도메인·유닛을 어떻게 나눌지는 판단이다"* 가 이미 본문에 있다 |
| 늘리는 비용이 실재한다 | 커맨드마다 매니페스트 `description` · `## 연결` · `entry`/`exit` · `lint` 대상이 붙는다 |

**대신 본문을 늘리지 않는다.** `next.md` 는 146줄이고 여기에 가르기·지시서·거둬들이기를 다 적으면
앞선 판 `run`(297줄)을 넘는다. `01.architecture.md` 가 이미 답을 정했다 — **커맨드 본문도 조각으로 가른다.**

| 조각 | 무엇 | 왜 이 묶음인가 |
|:--|:--|:--|
| `procedures/next/parallel.md` | 가르기 판정 · 지시서 형식 · 한도 읽기 | 가르기와 지시서는 **항상 같이 실린다**(`diag-B` 3-e 기준 — 소비자가 같으면 나누지 않는다) |
| `procedures/next/collect.md` | 거둬들이기 · 재개 계산 | 시점이 다르다. 병렬로 안 돌려도 재개는 쓴다 |
| `traceability/references/ownership.md` | 소유 집합 계산 · 겹침 판정 | 스파인 계산이라 `traceability` 것이다. 소비자가 `next`(배정)와 `design`(유닛 계획) 둘이다 |

**조건부 로드다.** 병렬로 안 돌리는 기본 경로에서는 안 실린다 — 능력 6.

## 버린 안

| 안 | 왜 버렸나 |
|:--|:--|
| `/flow:orchestrate` 새 커맨드 | 새 국면이 아니다. 진입·퇴장이 빈 노드를 늘리는 것이고 그 병이 D7 이다 |
| 런 원장 파일 (`.run/ledger.json`) | **저장된 상태는 낡는다.** 이 리포에서 실제로 낡았다(태스크 `ready` ↔ 일은 끝) |
| claim·lock 파일 + 만료 | 워커가 죽으면 락이 남아 재개를 막는다. 만료를 다루면 런타임을 만드는 것이고 그건 환경의 일 |
| 워커끼리 교차 판정 | 배선이 워커 수의 제곱으로 늘고 판정자 정본이 인스턴스로 흩어진다. 판정자는 **에이전트 종류**로 갈린다 |
| 코디네이터 에이전트 신설 | 판정자가 될 수 없고(도구가 필요하다) 진행하는 쪽이다. 그 자리는 `next` 를 돌리는 세션이다 |
| flow 가 워커를 직접 띄운다 | **죽은 것이 실행 층이다.** 사용자 결정과도 어긋난다 |
| 워커 리포트를 scratchpad 규약으로 | 이번에 비워졌다 |
| 겹침을 없애려고 File Map 을 자동 조정 | 쓰기 게이트의 판정 근거를 병렬 편의로 고치는 것이다 |

## 한계 — 이 설계로 못 하는 것

- **레거시 첫날엔 소유 게이트가 유닛 단위가 아니다.** File Map 을 쓰는 task 문서가 하나도 없으면
  `any-unit-has-task` 로 떨어져 "요구 태그 있는 task 가 하나라도 있나" 만 본다(`topology` 가 스스로 적은
  거친 바닥). **그 상태에서 병렬은 서로 덮을 수 있다.** 병렬을 권하지 않는 구간이다.
- **같은 파일을 두 task 의 File Map 에 둘 다 적어 두면 훅은 둘 다 통과시킨다.** 겹침 판정은 약속이다.
- **워커가 게이트를 안 부르고 "통과"라 보고하는 것은 못 막는다.** 완화는 파일을 세는 것뿐이다.
- **동시 수·모델 한도 초과를 못 막는다.** 워크트리 분리·프로세스 감시·재시작도 전부 환경이다.
- **조각 미적재 위험이 워커 수만큼 곱해진다.** `01.architecture.md` 가 위험 칸에 둔 그 위험(판단·절차형
  조각을 안 읽고 지나가는 것)에 새 방어를 만들지 않는다. 워커가 셋이면 세 번 일어날 수 있다.
- **repo 밖에서만 존재한 판단은 사라진다.** 이 리포에서도 `doc/` 에 적힌 것만 남았다.
