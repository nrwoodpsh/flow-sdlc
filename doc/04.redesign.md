# 재설계 — 능력 대조와 작업 목록

잣대는 `00.concept.md` 의 **능력 11개**다. 근거는 워커 3명의 전수 조사(`00.diagnosis/redesign-W1~W3`)이고,
**아래 결함은 전부 내가 직접 재확인한 것만** 실었다. 확인 못 한 것은 `미확인`이라 적는다.

## 작업 목록

순서 원칙 — **검사기를 먼저 세운다**(회귀 방어가 없으면 고친 것이 다시 샌다) → 치명 → 구조 → 정리.
각 T 는 **단위 테스트까지 끝내고 하나씩 확인받는다.**

| T | 무엇 | 닫는 것 | 검증 |
|:--|:--|:--|:--|
| **T1** | 검사 신설 — ① `who` 대조(판정자가 진행자면 실패) ② 조각 배선(SKILL.md 가 "반드시 읽는다" 한 조각이 `topology.loads` 에 있나) ③ `skill-duplication` 대상을 조각·커맨드까지 | D3·D4·D6 의 **재발** | `lint.test.py` 픽스처 3쌍 · 되돌림 확인 |
| **T2** | `setup` 에 **소스 경로 확정 단계** 신설 — 코드 위치를 스캔해 `drift.sourceGlobs` 를 채우고, 돌려서 확인하는 실행 키 목록에 넣는다 | **D1** | 스크래치 레거시 repo(`lib/`·`backend/`)로 두 기계가 켜지는지 실측 |
| **T3** | `legacyExempt` 채우는 절차 — 누가 언제 채우나. `build` 가 면제 밖 파일에서 막힐 때 그 자리에서 등록을 제안 | **D2** | 첫 유닛 생성 후 레거시 파일 쓰기가 과차단 안 되는지 실측 |
| **T4** | `review` 판정자를 `gatekeeper` 로 · `entry.content` 를 **퇴장 조건**으로 재획정 | D3·D5 | T1 의 `who` 검사 + `entry-grade-parity` |
| **T5** | `service-boundary` 를 `build`·`design` 배선에 넣고, SKILL.md 의 "반드시 읽는다" 목록과 대조 | **D4** | T1 의 배선 검사 |
| **T6** | **역추출 조각 신설** — `prd.md` 본문의 절차를 조각으로 내리고 `prd` 가 싣는다. 역추출 요구가 코드와 맞나 보는 층 | D8 · 능력 8 | 레거시 repo 에서 역추출 → ID 발급 경로 실측 |
| **T7** | `next` 라우팅 — 레거시 행 복원 · `spike`·`publish`·`setup` 도달 간선 · 역방향 간선 | D7 · 능력 5 | 도달 불가 유형 0 을 검사로 |
| **T8** | 정리 — `skills-map` 2건 · 에이전트 배선 정본 · 12개 SKILL.md 의 `어느 조각을 읽나` 표를 `topology` 로 접기 | D9 · 능력 7 | `lint.py` 전체 |

**T9 앞에 반드시 있어야 하는 것** — **이 판을 한 번도 설치해 돌려본 적이 없다.** 지금까지 검증은 전부 정적이다
(`lint` 26 · 훅 371 · 생성물 대조). 커맨드 11개가 Claude Code 에 뜨는지, `setup` 이 실제로 도는지 아무도 안 봤다.
T9 에 넣지 말고 **T2 직후에 한 번** 설치해 보는 편이 낫다 — 뜨지 않는 파일이 있으면 그 뒤 작업이 전부 헛돈다.
