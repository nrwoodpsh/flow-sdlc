# 00.requirement — 시스템 요구

> 대상: yt-digest 전체 · `/flow:prd sys legacy` 역추출 산출. 착지: `doc/00.ref/00.architecture/`
> **정본이 아니다** — 코드에 구현된 사실을 옮긴 것이라 전부 `상태: 확인 필요`다. 사람 검수 전까지 확정하지 않는다.
> 읽은 범위: `src/` · `lib/` 전량 (진입점 4 · 18줄) · `package.json` · `.gitignore`. 스케줄러·큐·환경변수·DB 스키마는 리포에 없다.

## 목표

**목표는 역추출로 뽑히지 않는다.** 코드는 무엇을 하는지만 말하고 왜 하는지는 말하지 않는다.

| 목표 (통제 못 함) | 이걸 위해 우리가 하는 것 (요구가 됨) |
|:--|:--|
| 유튜브 채널의 새 영상을 요약해 전달한다 — 추정 (`package.json:2` `description` · `README.md:3`) | 확인 필요 — 목표와 요구를 잇는 근거가 코드에 없다. 사람이 채운다 |

- **이 표는 검수 대상이다.** 한 줄뿐인 것은 목표가 하나라서가 아니라 코드에 하나만 적혀 있어서다.

## 요구

역추출한 횡단 제약이다. 판정 질문은 *"도메인을 하나 더 추가하면 여기에도 걸리나"* 였고, **걸리는 것만 올렸다.**

| ID | 종류 | 요구 | 완료 기준 (측정 가능) | 측정 방법 | 상태 |
|:--|:--|:--|:--|:--|:--|
| ~~SYS-1~~ (deprecated) | — | ~~현행: HTTP API 는 인증을 요구하지 않는다~~ — **표본 대조에서 내렸다**(20260809). 근거로 단 `src/api/routes.ts:2` 는 라우트 이름을 핸들러 이름 문자열에 매핑한 객체뿐이고, 서버·핸들러 심볼·미들웨어가 리포에 없다. 확인된 것은 *인증이 구현돼 있지 않다* 이지 *API 가 인증 없이 응답한다* 가 아니다 — 그 문장을 참으로 만들 실행 경로가 없다. `확인 필요` 절의 의도 불명으로 옮겼다 | | — | ~~취소~~ |
| SYS-2 | 기능 제약 | 현행: 외부 호출이 실패하면 예외를 던져 중단한다 — **확인** `src/collector/channel.ts:5` · `src/summarizer/summarize.ts:6` | | — | 확인 필요 |

- **살아남은 `SYS-*` 가 하나인 것이 결과다.** 코드에 인증·로깅·에러 코드·시각 규약이 없어 올릴 횡단 제약이 없다. 억지로 만들지 않았다.
- **`SYS-2` 에서 "부분 결과를 남기지 않는다" 를 뺐다** — 근거로 단 두 줄은 `throw` 문이라 그 절을 지지하지 않는다. 남길 저장 계층 자체가 없어 공허하게 참일 뿐이라, 결정된 규약인지 저장소 부재의 부수 효과인지 코드로 못 가른다.
- **ID 는 재편하지 않는다.** `SYS-1` 은 번호를 비우지 않고 취소 표기로 남긴다 — 다음 발급은 `SYS-3` 부터다.
- **역추출 요구에는 `완료 기준`·`측정 방법` 게이트가 걸리지 않는다** — 코드가 하는 일을 옮긴 것이다. 사람이 `상태` 를 비우면 그때부터 신규와 같은 게이트를 받는다.
- **재시도는 횡단이 아니다.** `summarize` 는 최대 3회 부르고 `fetchNewVideos` 는 즉시 던진다 — 규약이 아니라 모듈마다 다른 처리다. SYS-2 는 *실패가 예외로 끝난다* 까지만 말한다.

## 외부 의존

| 무엇 | 무엇에 쓰나 | 쿼터·상한 | 우리 요구와 맞나 | 죽으면 | 대비 |
|:--|:--|:--|:--|:--|:--|
| 유튜브 Data API v3 (`search`) | 채널의 새 영상 목록 — 확인 `src/collector/channel.ts:4` | **확인 필요** — 쿼터 값이 코드·설정·환경변수 어디에도 없다. API 키를 싣는 자리조차 없다 | **현행** — 호출 횟수를 막는 코드가 없다. `slice(0, 100)` 은 받은 응답을 자르는 것이라 쿼터를 아끼지 못한다. 실제로 무엇이 상한인지는 운영 값을 봐야 안다 | 수집 정지 — `res.ok` 가 false 면 예외 | 없음 — 재시도·큐·캐시가 코드에 없다 |
| LLM (제공자 미상) | 자막 요약 — 확인 `src/summarizer/summarize.ts:4` | **확인 필요** — `callLLM` 이 `declare` 선언뿐이라 제공자·모델·쿼터가 코드에 없다 | **현행** — 입력을 12,000자로 자르고 실패하면 **최대 3회까지 부른다**(최초 1회 + 재시도 2회 — `for (i = 0; i < 3; i++)`) | 요약 불가 — 3회째 실패 후 예외 | 최대 3회 호출 — 확인 `src/summarizer/summarize.ts:3` |
| 자막 소스 (미상) | 영상 자막 — 확인 `lib/youtube/transcript.ts:1` | **확인 필요** — 스텁이라 외부 호출이 없다 | **현행** — 빈 문자열을 돌려준다. 아직 아무 데도 안 붙었다 | — | — |

- **쿼터 ÷ 1회 사용량 계산을 못 했다.** 세 줄 모두 쿼터 값이 코드에 없어 나눌 숫자가 없다. 값을 넣어 계산하는 것은 사람 몫이고, 그 전에는 `충돌` 인지 `OK` 인지 말할 수 없다.
- **숫자를 지어 넣지 않았다.** 유튜브 공식 쿼터를 기억으로 적으면 그건 코드 근거가 아니라 내 추측이고, 계산 결과가 요구 판정으로 굳는다.

## 범위 밖

시스템 레벨이 아니라 **도메인 레벨에서 뽑을 것**이다. 새 도메인을 더해도 걸리지 않아 `SYS-*` 로 올리지 않았다.

- `DAILY_LIMIT = 100` — 영상 목록을 100건으로 자른다 (`src/collector/channel.ts:2`)
- 요약 입력 12,000자 절단 · 최대 3회 호출(최초 1 + 재시도 2) (`src/summarizer/summarize.ts:3-4`)
- `GET /digest/:channelId` · `POST /digest/refresh` 두 엔드포인트의 동작 (`src/api/routes.ts:2`)

도메인 문서가 아직 없다 — `doc/00.ref/01.domain/` 에 `00.common.md` 템플릿만 있다. 위 셋은 도메인이 생긴 뒤 `/flow:prd domain` 이 가져간다.

## 확인 필요

### 코드와 주석이 어긋난 것 — 요구로 확정하지 않는다

어느 쪽이 의도인지 코드에 없다. 둘 다 적고 사람에게 넘긴다.

| 위치 | 주석이 말하는 것 | 코드가 하는 것 |
|:--|:--|:--|
| `src/collector/channel.ts:1-6` | "쿼터 때문에 **하루** 100건으로 막아 뒀다" | 응답 배열을 100개로 자른다. **하루 단위 상태도 호출 횟수 제한도 없다** — 같은 채널을 100번 부르면 100번 나간다 |
| `src/api/routes.ts:1` | "최근 요약을 돌려준다" | 요약을 저장하는 계층이 코드에 없다. 무엇을 돌려주는지 읽을 자리가 없다 |
| `src/collector/channel.ts:2` | 상수 이름 `DAILY_LIMIT` — 하루 단위 상한 | 응답 배열의 길이 상한이다. 이름이 주석과 같은 뜻으로 어긋나 있다 |

### 의도 불명 — 요구 표에 올리지 않았다

- **HTTP API 에 인증이 없는 것이 결정인가** — `~~SYS-1~~` 이 여기로 내려온 항목이다. `src/api/routes.ts:1` 주석은 "인증 없음(내부용)"이라고 말하지만, 요청을 처리하는 코드가 없어 그것이 현행 동작인지 아직 안 만든 것인지 코드로 못 가른다
- `src/api/routes.ts:2` 의 핸들러 `getDigest` · `refresh` — **문자열일 뿐 그 이름의 심볼이 리포에 없다.** 라우트를 실제로 물리는 서버 코드도 없다
- **네 함수를 부르는 쪽이 리포에 없다** — 파이프라인을 잇는 코드가 없어 **실행 진입점은 0** 이다. `getTranscript` 가 늘 `''` 를 돌려주므로 이어 붙여도 요약 입력이 항상 빈 문자열이 된다
- `lib/youtube/transcript.ts:1` — `return ''` 스텁. 자막을 어디서 가져올지 정해진 것이 없다
- `src/summarizer/summarize.ts:8` — `callLLM` 이 `declare` 선언뿐이라 구현이 없다
- `src/collector/channel.ts:4` — **요청 URL 에 `key=` 가 없다.** Data API v3 는 키 없이 호출이 성립하지 않는다. 키를 싣는 자리도 환경변수도 리포에 없다
- `src/collector/channel.ts:4` — `channelId` 를 이스케이프 없이 URL 에 보간한다. 입력 검증 규약이 없다
- `src/collector/channel.ts:6` — `slice(0, 100)` 이 101번째부터를 **아무 신호 없이 버린다.** 페이지네이션도 잘렸다는 표시도 없다
- `package.json:3` 의 `build: tsc -p .` — **`tsconfig.json` 이 없다.** 지금 상태로는 빌드가 안 된다
- `package.json:3` 의 `test: vitest run` — 테스트 파일이 하나도 없다
- 요약 재호출에 백오프가 없고 실패 종류(4xx·5xx·타임아웃)를 가르지 않는다

### 답이 있어야 다음으로 가는 것

- **세 외부 의존의 쿼터·요금.** 위 `외부 의존` 표의 판정이 전부 `확인 필요`다 — 숫자가 들어와야 `OK` 인지 `충돌` 인지 갈린다
- **인증 없음이 의도인가.** 결정이면 배포 경계(무엇이 이 API 에 닿나)를 함께 정하고 요구를 `SYS-3` 으로 새로 발급한다. 결정이 아니면 요구가 아니라 결함이다 — `~~SYS-1~~` 을 내린 이유가 이 갈림이다
- **`DAILY_LIMIT` 이 쿼터 보호인가.** 주석대로 쿼터를 아끼려는 것이 의도로 확정되면 그 제약은 도메인이 아니라 **`SYS-*` 로 올라온다.** 지금 도메인 레벨로 내린 것은 *코드가 하는 일* 기준이라, 의도가 정해지면 레벨 판정이 뒤집힌다
- **요약을 어디에 보관하나.** 저장 계층이 없어 `GET /digest` 가 무엇을 읽는지 코드에 없다. `doc/00.ref/02.db-schema/` 도 비어 있다
- **목표 표를 사람이 채운다** — 위 `목표` 절
