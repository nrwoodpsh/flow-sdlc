## 상태 — 파일에서 계산

```
[/flow:next] collect/00.quota — 파일에서 계산

  0.requirement ✅   1.design ✅   3.contract ✅
  2.task/   00.quota-counter   01.fetch-guard
  4.build/  (없음)                          ← 00·01 둘 다 미착수
  5.verify/ (없음)

  계산한 상태: 명세        README: "아직 유닛 없음"  ← 낡았다
```

**소스가 문서와 어긋난다.** `src/collector/channel.ts` 는 이미 task 01 구현이 들어간 채 커밋돼 있는데(`createQuotaCounter` import·요청 전 소비·`MAX_ITEMS_PER_CALL`), `src/collector/quota.ts`·양쪽 `*.test.ts`·`4.build/`·`5.verify/` 는 워킹트리에서 삭제된 상태다. 스파인 파일이 정본이므로 **둘 다 미착수로 센다.** 다만 지금 리포는 `quota.ts` 가 없어 `channel.ts` 의 import 가 깨져 있다 — 워커가 01을 받으면 "이미 다 되어 있는 코드"를 보게 된다.

## 병렬 판정 — 배정할 수 있는 것은 1

| 무엇 | 결과 |
|:--|:--|
| 한도 (`orchestration`) | `maxWorkers: 2` · `worker: sonnet` / `judge: opus` — 판정자가 진행자보다 높다, 통과 |
| 소유 겹침 (`File Map`) | **비었다** — `quota.ts`·`quota.test.ts` ↔ `channel.ts`·`channel.test.ts` |
| **순서 의존** | **걸린다** — 아래 |

소유는 안 겹치는데 순서가 걸린다. 세 겹이다.

1. **번호가 곧 순서다.** `2.task/00` 이 안 끝났는데 `01` 을 같이 돌리지 않는다.
2. **01의 Verification 이 00의 산출을 부른다.** `01.fetch-guard` 의 Logic 이 `counter.tryConsume` 을 쓰고 `channel.ts` 가 `./quota` 를 import 한다 — `quota.ts` 가 없으면 01의 `npm test` 는 통과할 길이 없다. 게이트를 통과 못 할 워커를 띄우는 것은 워커를 버리는 것이다.
3. **`npm test` 가 리포 전체를 돈다.** `vitest run` 에 설정 파일이 없어 `*.test.ts` 를 전부 수집한다. 두 워커가 동시에 돌리면 서로의 작성 중 테스트가 상대 판정에 섞인다 — `File Map` 밖에서 생기는 겹침이라 소유 계산이 못 잡는다.

**두 번째 워커 자리는 비워 둔다.** 채울 후보가 없다 — 유닛이 `00.quota` 하나뿐이고 그 안의 task 둘이 앞뒤로 묶여 있다. 억지로 01을 붙이면 게이트에서 막히거나 판정이 오염된다.
