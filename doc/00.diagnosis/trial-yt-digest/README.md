# 실전 시연 — 레거시 프로젝트에 v2 를 깔아 돌려 봤다

**정적 검사가 못 보는 것을 보려고 실제로 돌렸다.** `lint` 37 · 훅 420 · `plugin validate` 가 전부 통과하는
상태에서도 결함이 나왔고, 고쳐 둔 것이 실전에서 작동하는지도 여기서 처음 확인됐다.

`logs/` 에 회차별 원문과 산출물 사본이 있다. `/tmp` 는 이 프로젝트에서 이미 한 번 비워졌으므로 repo 에 남긴다.

## 어떻게 돌렸나

**설치하지 않았다.** `flow@setting-ai`(0.6.0)가 실제로 쓰이는 중이라 이름이 겹친다.

```
claude --plugin-dir <v2>/plugins/flow --allowedTools … --max-budget-usd … -p "/flow:…"
```

**동명 플러그인이 공존한다 — 실측으로 확인했다.** `flow@setting-ai`(enabled)와 `flow@inline`(경로 로드)이
`claude plugin list` 에 나란히 뜬다. 이전 조사에서 *"문서에 규칙이 없다"* 로 남았던 불확실이 이걸로 닫혔다.
**그래서 커맨드 접두를 `/flow-sdlc:` 로 개명할 필요가 없다**(529곳 치환을 접었다).

대상은 유튜브 채널 요약 시스템을 **레거시 형태로** 만든 것이다 — 코드만 있고 문서·테스트·설정이 없다.
코드에 판단이 박혀 있다: 쿼터 100건 · 자막 12,000자 절단 · 3회 재시도 · 인증 없는 API.

| 회차 | 무엇 | 결과 |
|:--|:--|:--|
| 01 | `/flow:next` — 권한 없이 | 레거시 판정·`setup` 라우팅 ✓ · **위상 정본을 못 읽음** |
| 01b | `/flow:next` — `Read` 허용 | 정본 읽고 판정이 정밀해짐 ✓ |
| 02 | `/flow:setup` | 전부 생성 ✓ · **`lib/` 를 찾아 `sourceGlobs` 에 채움** |
| 03 | `/flow:prd sys legacy` | 역추출 + 대조 3층 ✓ · **잘못 뽑은 요구를 스스로 내림** |

## 찾은 결함 — `${CLAUDE_PLUGIN_ROOT}` 읽기가 권한에 매달린다

01 에서 커맨드가 이렇게 보고했다.

> 위상 정본(`flow.topology.json`)을 읽으려 했으나 **권한이 없어 거절됐다.**

`--allowedTools Read` 를 열어 다시 돌리니 읽혔다(01b). **경로 문제가 아니라 순수 권한 문제다.**

| 어디 | 무슨 일이 나나 |
|:--|:--|
| 헤드리스(`claude -p` · CI) | Read 를 명시로 열지 않으면 **정본 없이 판정한다.** 커맨드가 절반만 답한다 |
| 대화형 | 매 세션 승인을 물을 것으로 보인다 — **추측이다.** 대화형은 아직 안 재봤다 |

**아키텍처 결함은 아니다** — 읽히면 설계대로 작동하고, 오히려 01b 의 답이 01 보다 정확했다
(`no-units` 면제로 게이트가 빠져 있다는 것까지 짚었다). *정본은 데이터* 전제가 실측으로 지지된 셈이다.

**고칠 방향** — `/flow:setup` 이 프로젝트 `.claude/settings.json` 에 플러그인 루트 읽기 허용을 심는다.
못 하면 그 한계를 설계 문서에 적는다. **능력 12 구현이 같은 벽에 부딪히므로 먼저 정리한다.**

## 고쳐 둔 것이 실전에서 작동했다

### D1 — `setup` 이 `lib/` 를 찾아냈다

```
drift.sourceGlobs = ["src/**", "lib/**"]
```

v1 기본값(`src/**`·`app/**`)만 남았다면 `lib/youtube/transcript.ts` 는 영원히 *소스 아님*으로
게이트 밖이었다. `setup` 은 **게이트를 직접 돌려 확인한 것까지 보고했다** —
안쪽 `lib/…` → `allow(no-units)` · 바깥 `_trial/…` → `allow(not-source)`.
*"실행 키는 돌려 보고 적는다"* 가 지시서가 아니라 실행에서 지켜졌다.

그 밖에 `setup` 이 채운 것: `contract.gate`=`tsc`(TS 감지) · `build`·`test`=`package.json` 에서 읽음 ·
`.githooks/pre-commit` 설치 + `core.hooksPath` 설정 · `templates.flowVersion`.
비운 것과 이유도 보고했다(`test.browser` — 프론트 없음 · `publish`·`theme` · `gate.legacyExempt` — 기본은 면제 없음).

### D8 — 역추출 3층이 잘못 뽑은 요구를 내렸다

`reverse-check` 가 설계대로 돌았다: **앵커 13/13 실재 · 표본 6/6 전수(`verifier` 격리 판정).**

| 판정 | 무엇이 일어났나 |
|:--|:--|
| **근거 없음 → 요구를 내림** | `SYS-1`(*"API 는 인증을 요구하지 않는다"*)을 취소했다. 근거로 단 `routes.ts:2` 는 **문자열 맵뿐**이라 그 문장을 참으로 만들 실행 경로가 없다 |
| **어긋남 → 문장을 코드에 맞춤** | `SYS-2` 에서 *"부분 결과를 남기지 않는다"* 를 뗐다 — 근거 두 줄은 `throw` 문이라 그 절을 지지하지 않는다 |

*"이 국면에서 진실은 코드다"* 가 세 곳에서 적용됐다. **살아남은 요구가 하나뿐인 것이 결과다** —
*"코드에 인증·로깅·에러 코드·시각 규약이 없어 올릴 횡단 제약이 없다. 억지로 만들지 않았다."*

**레벨 판정도 맞았다** — *"재시도는 횡단이 아니다"* 로 3회 재시도를 `sys` 에서 뺐다(모듈마다 다른 처리다).
하드코딩 값은 버려지지 않고 `외부 의존` 표와 `코드에 박힌 값` 목록으로 갔다.

### 심지 않은 버그를 찾아냈다

> `channel.ts:1-6` — 주석은 *"하루 100건으로 막아 뒀다"* 인데 **응답 배열을 100개로 자르는 것뿐이다.**
> 하루 단위 상태도 호출 횟수 제한도 없다 — 같은 채널을 100번 부르면 100번 나간다.

`reverse-extract` 의 *"버그도 동작이다 — 코드와 주석이 어긋나면 둘 다 적고 요구로 확정하지 않는다"* 가
그대로 적용됐다. **이 불일치는 시나리오에 의도해 넣은 것이 아니다.**
그리고 *"실행 진입점은 0"* 이라고 짚었다 — 네 함수를 부르는 코드가 리포에 없다.

## 커맨드가 스스로 밝힌 한계

숨기지 않은 것을 그대로 적어 둔다. 이 태도가 이 프로젝트가 내내 강제한 것이다.

- 01 — *"정본을 못 읽었다. 이 한 걸음은 확실하고 그다음은 정본을 읽어야 안다"* 로 범위를 갈랐다
- 03 — *"`gatekeeper` 판정은 수정 **전** 문서 기준이다. 이후 수정은 요구를 줄인 방향이라 판정을 뒤집지
  않지만 **재판정은 돌리지 않았다**"* — 실제 순서 결함을 스스로 신고했다

## 아직 안 돌린 것

| 회차 | 무엇이 판정되나 |
|:--|:--|
| `design` | 시스템 레벨에서 정지하나(`design.next` 가 레벨을 몰라 `build` 를 주는 별건이 여기서 드러날 것이다) |
| **`build`** | **쓰기 게이트가 실제로 막나.** 유닛이 생긴 뒤 File Map 밖 쓰기 · D2 면제 판정 셋(allow/ask/deny) |
| `verify`·`review` | `verifier`·`reviewer` 격리 · `critical` 차단 |
| `sync` | 문서가 없던 프로젝트에서 무엇을 갱신하나 |
| **`commit`** | **가드가 `push` 를 막나** · v2 가 없앤 `--no-verify` 경로가 실제로 없나 |
| `spike`·`publish` | 미실행 |

**훅의 런타임 발화**는 `setup` 이 심은 `pre-commit` 과 쓰기 게이트를 `build`·`commit` 회차에서 봐야 확정된다.
