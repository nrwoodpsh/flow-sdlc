## `/flow:prd domain collect` — 레벨·대상 선언

```
[/flow:prd] 레벨: 도메인   대상: collect
            산출: doc/00.ref/01.domain/01.collect.md  (요구·확인 필요 절만)
            ID 형식: COLLECT-N  ← 도메인 레벨 발급 0건. COLLECT-1 부터
```

- 원격 없음(로컬 `main` 단독) — 번호 충돌 위험 없다.
- `COLLECT-QUOTA-1,2`는 **기능 레벨**이라 별개 축이다. 이 도메인 요구가 그 부모가 된다.
- **`legacy`를 안 붙였다** — 신규 인터뷰 모드로 간다. 코드에서 뽑아 올리는 게 목적이면 `/flow:prd domain collect legacy`라고 말해 주면 절차를 바꾼다.

## 이미 답이 있는 것 — 인터뷰에서 건너뛴다

| 어디서 | 무엇 |
|:--|:--|
| `00.architecture/00.requirement.md` `범위 밖` | 시스템 요구가 **도메인으로 내려보낸 것 셋**: `DAILY_LIMIT=100` 자르기 · 요약 12,000자 절단·최대 3회 호출 · `GET /digest/:channelId`·`POST /digest/refresh` |
| `SYS-2` (확인 필요) | 외부 호출 실패는 예외로 끝난다 — 횡단이라 여기 복사하지 않고 참조만 |
| `collect/00.quota/0.requirement.md` | 하루 호출 상한 · UTC 자정 창 · 카운트 규칙 — **이미 확정된 기능 요구** |

## 질문 1 — 경계: `collect`는 어디까지인가

이 답이 나머지 전부의 범위를 정한다. 코드에 모듈이 넷 있는데, 시스템 요구가 내려보낸 세 항목이 **서로 다른 모듈**에 흩어져 있다.

| 모듈 | 무엇 | `collect`인가? |
|:--|:--|:--|
| `src/collector/channel.ts` | 채널의 새 영상 목록을 가져온다 | 확실히 그렇다 |
| `lib/youtube/transcript.ts` | 영상 자막을 가져온다 (지금은 `''` 스텁) | **묻는다** |
| `src/summarizer/summarize.ts` | 자막을 요약한다 (LLM) | **묻는다** |
| `src/api/routes.ts` | 요약을 밖으로 내보낸다 | **묻는다** |

셋 중 하나를 골라 주세요.

- **A. 가져오기만** — 영상 목록 + 자막까지가 `collect`. 요약은 `summarize` 도메인, 조회는 `digest` 도메인으로 따로 뗀다
- **B. 영상 목록만** — 자막도 별개 도메인
- **C. 전부 한 도메인** — 수집·요약·조회가 다 `collect`. 도메인이 하나뿐인 프로젝트가 된다

> **C를 고르면 `SYS-*` 판정이 흔들린다** — 시스템 요구는 *"도메인을 하나 더 추가하면 걸리나"*로 이미 판정해 뒀고, 도메인이 하나면 그 판정을 검산할 대상이 없다. 되돌리려면 ID를 다시 매겨야 하니 여기서 정하는 게 싸다.

답을 받으면 **목적 → 액터 → 기능 → 업무 규칙(`DR-*`) → 완료 기준·측정 방법 → 의존 → 범위 밖** 순으로 이어 묻고, 착지 전에 `gatekeeper`에게 레벨 판정과 **외부 쿼터 대조**를 넘긴다.

> 쿼터 대조가 이번 판의 관문이다 — 시스템 레벨에서 세 외부 의존이 **전부 `확인 필요`**로 남았다(쿼터 값이 코드·설정 어디에도 없다). 유튜브 Data API v3의 **실제 일일 쿼터 값**을 아신다면 지금 알려 주세요. 없으면 `확인 필요`로 두고, 그 상태로는 `gatekeeper`가 다음 국면을 막습니다.
