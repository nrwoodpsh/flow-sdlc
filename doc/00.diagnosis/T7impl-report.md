# T7 구현 1~3 — 검사 2종 신설 + D7 라우팅

범위는 `05.orchestration.md` 구현 목록의 **1·2·3번**이다. 검사를 먼저 세우고 그 검사가 잡는 것을 고쳤다.
`doc/01.architecture.md`·`doc/02.skills-map.md`·`guide/**`·`agents/**`·`next.md` 외 커맨드는 손대지 않았다.

## 검사 1 — `procedures-wired`

**무엇이 없었나.** `read-order-wired` 는 없는 절차 파일을 조용히 건너뛴다(`if not os.path.isfile(p): continue`).
`command-loads-parity` 가 보는 것은 `loads` 뿐이고 `procedures` 는 다른 키다.
**배선 13건이 전부 디스크에 있었던 것은 지켜져서가 아니라 우연이다.**

세 곳을 양방향으로 대조한다 — 걸리는 것 다섯 가지.

| 무엇을 잡나 | 어긋남의 모양 |
|:--|:--|
| 선언 → 디스크 | `commands.*.procedures` 가 없는 파일을 가리킨다 (오타면 그 커맨드는 절차를 안 읽는다) |
| 디스크 → 선언 | 어느 커맨드도 안 싣는 절차 파일이 남아 있다 — 배포만 되고 안 읽힌다 |
| 선언 → 본문 | 싣는다고 적어 두고 본문이 그 경로를 한 번도 안 가리킨다 |
| 본문 → 선언 | 본문이 가리키는데 `procedures` 에 없다 — 그 자리에서는 안 실린다 |
| `## 연결` 의 `절차 조각` 행 | 행이 있으면 선언과 낱낱이 같아야 한다 (빠진 것·초과) |

- **`## 연결` 에 행이 있는 것까지는 요구하지 않는다.** `design` 은 레벨이 어느 절차를 읽는지 가르므로
  그 표를 `## 절차` 안에 둔다(`design.md:63-66`). 행을 무조건 요구하면 조건부 구조를 가진 커맨드가
  **늘 읽는 것처럼** 적게 된다. 요구하는 것은 *본문 어딘가가 그 경로를 가리키는 것*이고,
  행이 있으면 그 행이 정확한지까지 본다.
- 현 리포에서는 **대상 33건 · 실패 0**이다. 신설 시점에 고칠 것이 없었다 — 값어치는 재발 방어다.

## 검사 2 — `route-reachable`

**도달 불가 정의** — 이 검사의 값어치가 여기 있어서 판정 기준을 데이터로 못 박았다.

> **사용자가 커맨드 이름을 몰라도 그 국면에 닿을 수 있나.**

이름을 알고 치는 사람은 어디든 간다. 그건 위상이 아니라 기억이다. 제품이 책임지는 것은
*모르는 사람이 도착하는 길*이고 그 길의 정본이 `commands.*.next` 다.
그래서 **진입점에서 `next` 간선을 따라 닿지 않으면 도달 불가**다.

| 무엇 | 어떻게 정하나 | 근거 |
|:--|:--|:--|
| 진입점 | `commands.<이름>.entryPoint: true` — **데이터가 정본이다** | 스크립트에 손으로 열거하면 v1 화이트리스트처럼 낡는다 |
| 지금 진입점 | `next` 하나 | 사용자가 이름을 몰라도 부르는 유일한 자리다 |
| 진입점을 늘리는 비용 | `$entryPoint-why` + **`after` 가 비어 있을 것** | 앞에 와야 하는 국면이 있는 커맨드는 시작점이 아니다 — 선언으로 검사를 끄는 길을 막는다 |
| 되돌아가는 간선 | `X.after` 에 `Y` 가 있으면 `Y.next` 에 `X` 가 있어야 한다 | `after` 가 실패 시 되돌아가는 앞 국면이다(`next.md` · `gate-timing` 이 같은 뜻으로 읽는다). 짝이 없으면 **편도 되돌림** — 되돌아가면 다시 앞으로 못 온다 |
| 반대 방향(앞으로만 있는 간선) | **요구하지 않는다** | `setup.next` 는 `prd`·`design` 인데 `design.after` 는 `prd` 뿐이다. 지름길은 있어도 되돌아갈 자리는 요구를 만든 국면이라 다르다 — 대칭을 요구하면 아무것도 안 만드는 국면으로 되돌아가라고 적게 된다 |

**모든 커맨드를 `next.next` 에 요구하지 않는다.** `next.md` 는 각 커맨드의 `after`·`next` 를 읽어
제시한다고 적으므로 라우터는 한 홉이 아니라 그래프를 본다. 한 홉을 요구하면 `next.next` 가
커맨드 목록의 사본이 되고, 그 사본은 낡는다.

## 고친 것 — D7

| 무엇 | 어디 | 왜 |
|:--|:--|:--|
| `next.next` 에 `setup`·`spike`·`publish` 추가 | `flow.topology.json` | 본문은 `/flow:setup` 을 안내하고 유형 칸에 `불확실`(→ `spike`)을 출력하는데, 라우터 가드레일은 *"위상 정본에 있는 것만 부른다"* 였다 — **본문이 데이터에 없는 길을 안내하고 있었다** |
| `sync.next` 에 `publish` 추가 | 같음 | `publish.after` 는 `sync` 인데 `sync.next` 에 `publish` 가 없었다 = 편도 되돌림. 검사가 잡은 유일한 실제 위반이다 |
| `next` 에 `entryPoint: true` · `$entryPoint-why` | 같음 | 도달 가능성을 계산할 출발점의 정본 |
| 레거시·불확실 라우팅 복원 | `traceability/references/level.md` — `코드부터 들어올 때 — 첫 커맨드` 절 | v1 `ask.md` 에 있던 행이다. `next.md` 는 유형 `레거시` 를 출력하면서 갈 곳을 아무 데도 안 적었다 |
| 유형→갈 곳을 조각으로 위임하는 한 줄 | `commands/next.md` `갈 곳을 정한다` | `next.md` 의 `legacy` 언급 0건을 닫는다. **표를 여기 옮겨 적지 않는다** — 정본은 `level` 조각이다 |

- **`level.md` 가 자연스러운 자리인가 — 그렇다.** 그 파일은 이미 `버그·작은 변경 → /flow:design` 이라는
  상황→커맨드 행을 갖고 있고(`절차를 건너뛰는 경로`), `next` 가 `traceability/level` 을 이미 싣는다.
  새 조각을 만들면 라우팅 정본이 둘로 갈리고 배선·표·검사가 통째로 따라붙는다.
- **역방향 간선은 새로 적지 않았다.** 무엇을 다시 도나의 정본은 `revert-scope` 고 어느 국면으로
  돌아가나는 `after` 다. 세 번째 표현을 만들면 정본이 셋이 된다 — 대신 **둘의 짝이 맞나를 검사로** 옮겼다.

## 되돌림 확인 — 고친 것을 일부러 되돌려 실패시켰다

리포 사본(`--root`)에 대고 돌리고 원복했다. 워킹트리에는 남아 있지 않다.

| 되돌린 것 | 결과 |
|:--|:--|
| `next.next` 에서 셋 빼고 `sync.next` 에서 `publish` 뺌 | 실패 3 — `publish`·`setup` 도달 불가 + `publish` 편도 되돌림 |
| `next.entryPoint` 삭제 | 실패 1 — *진입점이 없다* (조용히 통과하지 않는다) |
| `publish` 를 `entryPoint` 로 선언해 검사를 끄려 함 | 실패 3 — 이유 없음 + `after` 가 있음 + 편도 되돌림 |
| `commands.verify.procedures` 에 오타 | 실패 5 — 다섯 갈래가 전부 걸린다 |
| `## 연결` 절차 행에서 한 줄 뺌 | 실패 1 — 연결 절 절차 행 어긋남 |
| 디스크에 안 실리는 절차 파일 추가 | 실패 1 — 아무도 안 싣는 절차 |
| `design.md` 본문에서 절차 경로 지움 | 실패 1 — 본문이 안 가리킨다 |
| topology 는 있고 `commands` 가 빈 루트 | **대상 0건**으로 표시된다 — `⚠️ 검사가 아무것도 안 봤다`, `--strict-targets` 면 exit 1 |

**`spike` 는 이 검사가 안 잡았다** — `design.next` 에 이미 있어서 진입점에서 `next→design→spike` 로 닿는다.
`next.next` 에 넣은 것은 라우터가 **직접 제시**할 수 있게 한 것이고, 그 축은 데이터가 아니라 산문이라
기계가 못 본다. W1 이 셋을 같이 묶었지만 셋의 성질이 같지 않다.
