## 남은 것

**(1) 검사 두 개가 아직 대상 0건이다 — 그중 하나는 구조 문제다.**

| 검사 | 왜 0건인가 |
|:--|:--|
| `output-sections-exist` | 프로젝트 템플릿(`plugins/flow/project-template/doc/00.ref/03.templates/`)이 아직 없다 — 템플릿 층의 몫 |
| `output-required-sections` | 같음. **더하여 아래 구조 문제** |

**`lint.py` 의 `_declared`·`_out_sections`·`_out_blocks` 는 `ctx.skills()`(= `plugins/flow/skills/*/SKILL.md`)만 본다.** v2 는 출력 형식을 조각(`references/*.md`)으로 내렸으니, **템플릿이 생겨도 이 검사는 계속 0건**이다. 스캔 범위를 조각까지 넓혀야 그 검사가 산다 — 검사기 수정은 이 과제 범위 밖이라 손대지 않았다.

`output-template` frontmatter 를 지금 선언하지 않은 것도 같은 이유다. 템플릿이 없는 상태에서 선언하면 절 이름 대조가 전부 FAIL 로 뜬다.

**(2) `flow.topology.json` 배선은 커맨드 층 워커가 마쳤다.** 같은 파일을 동시에 쓰지 않으려고 나는 손대지 않았고, 지도의 `커맨드가 무엇을 싣나` 표가 그 값의 원본이 됐다. 대조해 보니 `skills` 14개의 조각 목록이 **실제 파일과 0건 불일치**이고 `pending` 도 비었다.

**(3) 조건 로드가 topology 에서 무조건 로드와 구별되지 않는다.** `topology` 의 `commands.build.loads.fragments` 는 `testing/llm-cost`·`code-graph/query`·`impact-analysis/regression-surface`·`doc-template/task-doc` 를 나머지와 같은 배열에 담는다. 지도는 이 넷을 **조건**으로 적었다 — LLM 기능일 때·기존 코드를 고칠 때·task 문서를 고칠 때만 읽는다. 조건을 데이터로 표시하지 않으면 `build` 의 로드가 항상 최대치(971줄)로 읽히고, 순수 신규 구현에서 626줄로 끝나는 이득이 데이터에 안 남는다. `loads.fragments` 를 `always`/`when` 으로 가르는 것을 권한다 — 판단은 커맨드·인프라 층의 몫이라 내가 고치지 않았다.

`testing/llm-cost` 는 커맨드 **본문**에서도 언급이 없다. topology 에는 있으니 로드는 되지만, 어느 상황에 읽으라는 문장이 커맨드에 없다 — `testing/SKILL.md` 의 판정표가 그 조건을 갖고 있어 치명적이지는 않다. `theme-apply` 의 두 조각과 `ops-doc/authoring` 이 커맨드 본문에 없는 것은 정상이다 — 사용자 직접 호출·유형 조건이다.

**(4) description 등급(자율/호출 전용)을 frontmatter 비표준 필드로 두지 않았다.** 설계가 "구현 전 확인"으로 남긴 항목이고(`review-v2-design-2.md` M12) 대조할 검사기도 아직 없다. 지금은 `누가 쓴다` 문장이 커맨드 층 실물과 맞는지만 확인했다 — 일곱 개가 틀려 있어 고쳤다(`code-graph` 는 `verify` 를 주장했는데 안 쓰고, `default-reference` 는 `전부` 라 적었는데 4개 커맨드가 안 쓴다).
