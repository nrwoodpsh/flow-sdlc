# flow — 콘셉 정의

**이 문서는 `01.architecture.md` 의 전제다.** 그쪽은 *어떻게 만드나*(강제력 등급·정본 데이터화·검사기)이고,
여기는 **무엇이어야 하나**다. 지금까지 이 층이 문서로 없었다 — v1 진단도 v2 설계도 *v1 의 결함*에서 출발했고,
**제품이 무엇인지에서 출발한 문서가 없다.** 재설계의 잣대가 필요해서 먼저 적는다.

## 한 문장

**flow 는 LLM 이 개발자일 때 개발 생애주기가 흩어지지 않게 붙잡는 오케스트레이터다.**

붙잡는 대상은 코드가 아니라 **인과**다 — 어떤 요구 때문에 이 코드가 있고, 그게 검증됐나.

## 왜 필요한가 — LLM 이 개발자일 때 깨지는 것

도구가 아니라 **제약**에서 출발한다. 이 셋이 없으면 flow 는 프롬프트 모음일 뿐이다.

| 제약 | 무엇이 깨지나 | 오케스트레이터가 하는 일 |
|:--|:--|:--|
| **컨텍스트 한계** | 코드베이스를 다 못 읽는다. 세션은 끝난다 | 무엇을 언제 싣나를 정하고, **상태를 파일에 둔다** |
| **환각** | 그럴듯하고 틀린 것을 만든다 | 자연어는 사람이, 계약은 기계가 — **이중 게이트** |
| **자기 검증 편향** | 자기가 놓친 것은 검증에서도 놓친다 | **진행하는 쪽과 판정하는 쪽을 가른다** |

세 제약은 세션이 끊기면 전부 악화된다. 그래서 **재개 가능성**이 부수 기능이 아니라 축이다 — 아래 5번.

## 주 사용 상황은 레거시 변형이다

**사용자가 확정한 제품 요구다.** 신규 생성이 아니라 **이미 돌고 있는 시스템을 분석해 변형·개조하는 것**이
주 상황이다. 이 한 줄이 나머지를 다 바꾼다.

| 신규 전제일 때 | 레거시 전제일 때 |
|:--|:--|
| 요구 → 설계 → 코드 | **코드 → 요구 역추출** → 설계 → 코드 |
| 문서가 코드보다 먼저 있다 | **문서가 없거나 낡았다.** 현행 파악이 첫 일이다 |
| 새로 만드니 영향 범위가 없다 | **공유 코드를 건드린다.** 회귀 표면이 매번 있다 |
| 첫날부터 사슬을 채울 수 있다 | **첫날엔 사슬이 비어 있다.** 강제하면 사람이 훅을 끈다 |
| 우리 관례를 깐다 | **남의 관례가 이미 있다**(husky·CI·자체 문서 규약) |

- **레거시가 예외 경로가 아니라 기본 경로다.** 신규는 레거시의 특수한 경우(기존 코드가 0인 경우)로 다룬다.
- **"점진 도입"이 타협이 아니라 요구다.** 전부 갖추기를 요구하면 아무도 못 쓴다.

## 갖춰야 하는 능력 — 이 표가 재설계의 잣대다

각 항목은 **없으면 무엇이 무너지나**로 정당화한다. 정당화가 안 되면 목록에서 뺀다.

| # | 능력 | 없으면 | 레거시에서 더 필요한 것 |
|:--|:--|:--|:--|
| 1 | **국면 분할과 전환 판정** | 국면 이름만 남고 아무 때나 아무 것이나 한다 | 진입 지점이 여러 개여야 한다 — 코드부터 들어오는 경로 |
| 2 | **판정 독립성** | 진행하려는 쪽이 자기 조건을 판정한다 = 게이트가 없다 | 같음 |
| 3 | **강제력의 정직한 표시** | *"4겹"* 이라 적고 실제로 1겹이 된다 | 같음. **경로별로**(사람/AI) 적어야 한다 |
| 4 | **추적 축** — 요구 ID → 설계 → task → 코드 → 검증 | *"요구를 다 덮었나"* 를 영원히 알 수 없다 | **역추출한 요구에도 ID 가 붙어야** 한다 |
| 5 | **재개 가능성** — 어디까지 됐나를 **파일에서 계산** | 세션이 끊기면 처음부터다 | 같음 |
| 6 | **컨텍스트 예산** — 무엇을 언제 싣나 | 매 턴 비용이 새고, 길어서 안 읽힌다 | 레거시는 읽을 것이 많아 위임이 필수다 |
| 7 | **정본 단일성** — 사실마다 정본 하나, 기계가 대조 | 복제가 낡고, 맞추는 비용이 변경을 막는다 | 같음 |
| 8 | **현행 파악 정본** — 지금 상태(스키마·구조)를 문서로 | AI 가 없는 컬럼·없는 모듈을 믿는다 | **레거시의 첫 산출물이 이것이다** |
| 9 | **영향 범위 계산** — 고치기 전 호출부 전수 | 조용한 회귀. 테스트가 없으면 안 잡힌다 | **매 변경마다** 필요하다 |
| 10 | **점진 도입과 면제** | 첫날 전 커밋이 막혀 사람이 훅을 끈다 | 레거시 전용 요구 |
| 11 | **남의 관례와 공존** | 그 프로젝트의 lint·테스트 훅을 죽인다 | 레거시 전용 요구 |

**5번이 이번에 실측됐다.** 오케스트레이션 런이 죽었을 때 살아남은 것은 **repo 의 파일과 태스크 기록**이었고,
그 둘로 어디까지 됐는지 복원했다. 재개 가능성은 이론이 아니라 이 프로젝트가 자기 몸으로 겪은 요구다.

## 무엇이 아닌가 — 경계

넣지 않는 것을 적어 두지 않으면 매번 다시 논의한다.

| 아닌 것 | 왜 |
|:--|:--|
| **CI/CD 파이프라인** | 배포는 사람과 배포 시스템의 일이다. flow 는 커밋 전까지 |
| **프로젝트 관리 도구** | 일정·공수·담당자를 다루지 않는다. 다루는 것은 **인과**다 |
| **코드 생성기** | 무엇을 만드나는 설계가 정한다. flow 는 그 순서와 판정을 든다 |
| **런타임 에이전트 허브** | 실행 중인 시스템을 조율하지 않는다. **개발 과정**을 조율한다 |
| **스택·프레임워크 특화 규약** | 스택 무관이 원칙이다. 특화는 프로젝트에 위임 |

## 이 정의로 무엇을 대조하나

재설계는 이 순서로 판정한다.

1. **현 v2 의 각 요소가 위 능력 11개 중 무엇을 담당하나.** 아무 것도 담당하지 않으면 **뺄 후보**다.
2. **능력 중 담당자가 없는 것.** 그게 **새로 필요한 것**이다.
3. **한 능력에 담당자가 둘이면** 정본 단일성(7번) 위반이다 — 합칠 후보.
4. **레거시 렌즈로 다시 본다.** 신규를 전제해 레거시에서 성립하지 않는 자리를 지목한다.

**판정에 근거를 붙인다.** *"수렴했다"* 는 근거가 아니다 — 어느 파일 어느 줄이 그렇게 만드나를 적는다.

## 정해진 것

| # | 질문 | 결정 |
|:--|:--|:--|
| 1 | flow 로 flow 를 개발하나 | **아니다.** 이 리포는 flow 커맨드를 쓰지 않는다 — v1 규칙을 잇는다 |
| 2 | 오케스트레이션이 제품에 들어가나 | **들어간다.** 아래 능력 12 로 승격한다 |
| 3 | 0.5 에 넣을 범위 | **능력 전부.** 미루는 것 없이 닫고 내보낸다 |

### 능력 12 — 워커 오케스트레이션 (제품 범위)

**`next` 가 커맨드를 이어 돌리는 것까지가 아니라, 일을 갈라 워커에게 맡기고 거둬들이는 것까지가 flow 의 일이다.**
이름이 *SDLC 오케스트레이터* 인 이상 여기가 핵이다.

| 무엇 | 없으면 | 어디서 왔나 |
|:--|:--|:--|
| **일 가르기** — 겹치지 않는 단위로 쪼갠다 | 워커가 같은 파일을 고쳐 서로 덮는다 | 능력 9(영향 범위)와 같은 계산이다 |
| **판정 독립성의 확장** | 워커가 자기 산출을 자기가 판정한다 | 능력 2를 워커 축으로 넓힌 것 |
| **거둬들이기** — 워커 결론을 하나로 | 리포트가 흩어져 아무도 안 읽는다 | — |
| **죽어도 이어가기** — 상태를 파일에 | 런이 죽으면 처음부터다 | 능력 5. **이 프로젝트가 겪었다** |
| **자원 한도** — 모델·동시 수 | 비용이 통제되지 않는다 | 사용자 제약(Opus 2 + Fable 1) |

- **밖의 도구(Orca 등)를 대체하지 않는다.** flow 는 *무엇을 어떻게 가르나* 를 정하고, 띄우는 것은 그 환경이 한다.
