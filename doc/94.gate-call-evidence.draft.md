## ❌ 의도 7 — 「반드시 부른다」를 강제하는 것이 없다

**반드시 부른다** — 이름만 부르고 안 부르면 게이트가 없는 것이다"* 로 적었다.
**`01.architecture.md` 가 금지한 형태가 정확히 이것이다 — "4겹이라 적고 1겹".**

**이번에는 지켜졌다**(12라운드가 실제로 돌았다). 문제는 **지켜졌는지 검증할 방법이 없다**는 것이고
실측이 그 증거를 남겼다:

```
4.build/03.skill-store    gatekeeper 0건 · BLOCK 0건
4.build/04.candidate      gatekeeper 0건 · BLOCK 0건
5.verify/03 · 04          같음
```

**"안 불렀다" 와 "불렀지만 안 적었다" 를 구별할 수 없다.** 그리고 그 열린 BLOCK 은
`doc/flow-feedback/README.md` 에만 있는데, 그 폴더가 스스로 *"`doc/01.work/` 의 참조 통제 밖 —
프로젝트가 여기를 읽지 않는다"* 고 선언했다. **다음 세션이 규약대로 읽으면 왜 멈췄는지 모른다.**

## ❌ 의도 8 — 규칙이 세는 것과 막으려던 것이 어긋났다

`revert-scope` 의 정지 사유: **같은 실패 3회 반복 · 진전 없음 · 자기 수정 범위 초과.**
실측의 3라운드: **1차 코드 결함 · 2차 문서 잔여물 · 3차 실행 기록** — 회차마다 다른 항목이 닫혔다.
`gatekeeper` 자신이 판정에 적었다: *"여기서는 그 신호가 없다 — 반복이 아니라 수렴이다."*

**인과가 나쁘다:**

```
게이트가 꼼꼼할수록 → 라운드가 늘고 → 상한에 빨리 닿고
                   → 사람이 게이트를 덜 부르고 → 의도 7 이 악화된다
```

**게이트를 좋게 만드는 것이 게이트를 죽이는 구조다.**

### §5 가 값/비용이 가장 좋다

문서가 *"제약 위반으로 실패시켜"* 라고 적었는데 실제 기제가 달랐고 **세 번 갈렸다**
(구현자 → `gatekeeper` → 실측). 테스트가 **무인자 `toThrow()`** 라 셋 다 통과했다.

```
✗ toThrow()                              뭐든 던지면 통과
✓ toThrow(/NOT NULL constraint failed/)  문서의 서술이 테스트로 고정된다
```

**한 줄로 "문서 사실 오류" 가 "테스트 실패" 가 된다.**

### §2 를 그대로 넣으면 안 된다 — 판정 독립성이 대가다

제안이 *"앞 판정에서 충족으로 본 것은 다시 열지 마라"* 를 조각에 넣자는 것인데,
그러면 **2차가 1차의 누락을 못 잡는다.**

```
✅ 넣을 수 있는 것    "2차에는 무엇이 바뀌었는지 diff 를 함께 준다"     (입력을 좁힌다)
❌ 넣으면 안 되는 것  "앞 판정이 통과시킨 것은 다시 보지 마라"          (판정을 좁힌다)
```

**§2 의 진짜 답은 §3 이다** — BLOCK 8건 중 **2건이 기록 문제**로 약 340k(전체의 21%)를 썼다
(위 「게이트 비용 실측」). 기록 정합을 스크립트로 잡으면 라운드가 줄고, 그것이 비용을 줄이는 정공법이다.

### §4 는 트레이드오프가 있다

`4.build` 의 이탈 줄을 **링크만**으로 좁히면 그 문서를 읽는 사람이 이탈 내용을 모른다.
**드리프트하는 것은 값이다** — 이번에 어긋난 것도 값(`endOn: "재직중"`)이었다.
**대안**: 이탈 줄에 *무엇을* 이탈했는지만 적고 **왜·증거는 링크로 가리킨다.**

### §7 은 절반만 적용한다

```
✅ "실물을 CI 에서 빼면 무엇이 회귀로 안 잡히는지 「미검증」에 적는다"
❌ "실물을 한 번은 돌려라"      ← 비용·비결정성이 규약으로 들어온다
```

실물을 돌린 것은 **그 세션의 판단**이었고 결함을 잡았다. 판단을 규약으로 바꾸면 매 유닛에 LLM 비용이 붙는다.

## 피드백 01 — `prd` 자리 표에 `업무 규칙` 절이 없다

**별건이라 여기 붙인다.** 출처: `flow-trial/doc/flow-feedback/01.prd-domain-rule-slot.md`
(20260819 · `01.profile` prd). **문서 결함 하나이고 값/비용이 좋다 — 표 한 줄이다.**

### 무엇이 났나

`/flow:prd func` 가 기능 요구를 쓰다 **도메인 규칙(`DR-*`)을 발급해야 하는 상황**에 닿았고
`gatekeeper` 가 BLOCK 으로 잡았다(정확한 판정이다). 되돌아가 `/flow:prd domain` 으로
`DR-4` 에 축을 더했다. **그런데 그 작업이 규약상 허용되는지 문서로 확인할 수 없었다.**

| 어디 | 무엇이라 적혀 있나 |
|:--|:--|
| `commands/prd.md` 자리 표 | `domain` 행의 `/flow:prd` 자리 = **"도메인 파일의 `요구`·`확인 필요` 절만"** |
| `usecase/rule-level.md` | *"도메인 문서의 **업무 규칙** 절 → `DR번호`"* |
| `traceability/conflict.md` | *"**`DR번호`** 발급: 도메인 문서의 **업무 규칙** 절"* |

**`업무 규칙` 절이 prd 쪽에도 design 쪽에도 없다.** 자리 표를 배타적으로(`~만`) 읽으면
**`DR-*` 를 아무도 못 쓴다.**

### 왜 조용히 지나가지 않았나

`gatekeeper` 를 부르면서 *"내가 `업무 규칙` 절을 고친 것이 규약 위반인지 판정하라"* 를
명시적으로 넘겼고, **위반 아님**으로 답하며 근거 셋을 댔다.

- `commands/prd.md` **자신**이 인터뷰 표에서 `domain` 열의 `업무 규칙` 을 ✓ 로 켠다 —
  **묻기는 하라면서 쓸 자리는 안 준 셈이다**
- 같은 문서가 *"업무 규칙을 어느 레벨에 두나는 `rule-level` 이 정본"* 으로 넘긴다
- 자리를 나눈 취지가 *"남의 절을 건드리면 상대가 덮어쓴다"* 인데, `업무 규칙` 은
  design 의 절 목록(배포 단위·경계·용어·업무 흐름)에 없어 **충돌 상대가 없다**

**즉 동작은 맞고 문서만 비어 있다.** 다만 **판정자를 부르지 않았으면 그냥 막혔거나,
확신 없이 지나갔을 자리다** — 의도 7 과 같은 가족이다.

### 제안 — 표 한 줄

```markdown
| 레벨 | `/flow:prd` 의 자리 | `/flow:design` 의 자리 |
|:--|:--|:--|
| domain | 도메인 파일의 **`요구`·`업무 규칙`·`확인 필요` 절** | 같은 파일의 `배포 단위`·`경계`·`용어`·`업무 흐름`·**`유닛 계획`** |
```

- **`유닛 계획` 도 design 쪽에 빠져 있다.** 실측에서 그 절이 낡은 것을 발견하고도
  *"`/flow:design` 의 자리라 안 고쳤다"* 로 넘겼는데, 근거가 자리 표가 아니라
  `id-system.md` 의 한 줄이었다.
- **`~만` 이라는 배타 표기가 문제의 핵심이다.** 열거가 불완전한데 배타로 읽히면
  빠진 절은 아무도 못 쓴다. **열거를 완성하거나 배타 표기를 뺀다.**

### 함께 기록 — 게이트가 실제로 작동한 자리 둘

**둘 다 flow 의 결함이 아니라 flow 가 잡아낸 것이다.**

| 무엇 | 어느 층이 잡았나 |
|:--|:--|
| 기능 레벨에 도메인 규칙을 두려 한 것 (`R4`) | `gatekeeper` 1차 BLOCK — **문서가 스스로 `확인 필요` 에 *걸린다* 로 적어놓고 올리지 않은** 모순 |
| 도메인 규칙의 예시가 자기 알고리즘과 모순 (`node` → `nodejs`) | `gatekeeper` 2차 BLOCK — **규칙을 레벨 이동만 하고 검산하지 않은** 것 |

**1차 BLOCK 을 반영하면서 새 결함이 들어갔고 2차가 그것을 잡았다.**
되돌아가기가 2회 났다는 사실 자체가 값이다 — `revert-scope` 가 상한을 정하는데
**상한을 세는 것은 부르는 쪽**이라 커맨드가 자동으로 세지 않는다(의도 8 과 같은 자리).
