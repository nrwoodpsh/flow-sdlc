# 영향 분석

"이걸 고치면 저기가 깨지나" — 바꾸려는 코드에 **의존하는 모든 곳**을 변경 *전에* 찾는다. 테스트가 없는 곳의 회귀, 즉 **초록불을 뚫는 회귀**를 예방한다.

## 발동 판정

| 이 상황이면 | |
|:--|:--|
| 기존 함수·클래스·타입·엔드포인트·DB 컬럼을 **고친다** | **필요하다** |
| 여러 task 가 쓰는 **계약을 고친다** | **필요하다** |
| 요구 ID·화면 번호를 **재발급해 참조를 고친다** | **필요하다** |
| **새 파일만 만든다** | 불필요하다 |

절차·판정·출력은 `references/regression-surface.md` 에 있다. 고치기 전에 읽는다.

## 남의 정본을 옮겨 적지 않는다

| 무엇 | 정본 |
|:--|:--|
| 그래프 질의·모드·정확도·`여기서 끊음` | `code-graph` 의 질의 조각 |
| 서비스 경계를 넘는 호출을 코드로 못 찾는다는 것 | `code-graph` 의 서비스 경계 조각 |
| 유닛을 넘으면 `explorer` 에 위임한다는 판정 | `default-reference` 의 위임 조각 |

## 경계

- **못 찾았다고 "영향 없음"으로 단정하지 않는다.** 동적 호출·리플렉션·문자열 라우팅은 grep 에 안 잡힐 수 있다 — 불확실한 것은 `확인 필요` 로 적는다.
- **초록불이 안전을 뜻하지 않는다.** 영향처에 테스트가 없으면 통과해도 회귀가 가능하다 — 사람에게 **미검증 목록**을 반드시 보고한다.
- 이 스킬은 **분석과 리포트**다. 발견한 영향을 근거로 자율 수정하지 않는다.
