# 코드리뷰 층 구성

한 도구로는 다 못 잡는다. **종류가 다른 오류를 층으로 나눠** 잡고, 겹치는 것은 한 번만 보고한다.

## 시작 전 확인

어느 층을 돌릴 수 있는지 먼저 본다. **없는 층은 건너뛰고 리포트에 적는다** — 멈추지 않는다.

| 확인 | 없으면 |
|:--|:--|
| `contract-gate` 설정 (`contract.gate`) | 1층 생략. 타입 오류가 안 걸린다 |
| `ocr` CLI | 2층 생략. **룰 검출이 빠지고 LLM 판단만 남아 오탐이 는다** |
| `joern` | 3층은 `code-graph`의 축소 모드로 — 흐름 추적은 못 한다 |
| `ponytail` 플러그인 | 4층은 `code-audit` 체크리스트만. **지울 목록은 못 만든다** |
| `claude-security` 플러그인 | 5층 생략. 취약점은 LLM 판단만 |
| `codex` 플러그인 *(`deep`일 때만)* | 6층 생략 — `"codex 미설치 — 설계 의심 층 생략"`을 적는다 |

**이전 회차를 먼저 읽는다.** `6.review/`의 미해결 `critical`·`high`가 이번 리포트에 이어져야 한다.

## 층 — 무엇이 무엇을 잡나

| 층 | 도구 | 잡는 것 | 성격 |
|:--|:--|:--|:--|
| 1 | `contract-gate` | 타입·컴파일 | 결정론 |
| 2 | **OCR** (open-code-review) | NPE·스레드 안전·XSS·SQLi — **알려진 패턴**. 줄 단위 | 결정론+LLM |
| 3 | `code-graph` | **어디까지 번지나** — 교차 파일 영향 | 결정론 |
| 4 | `code-audit` + **ponytail** | **우리 규약**(계약 정합·명명·범위·테스트) + **과설계 삭제 목록** | 체크리스트 + 플러그인 |
| 5 | `claude-security` | 취약점 + **자체 반박** | LLM |
| 6 | **codex** `adversarial-review` | **"이 방식이 맞나"** — 설계 선택·트레이드오프·숨은 가정 | 외부 LLM |
| 7 | `verifier` | critical·high **반증** | LLM |

- **1~4는 서로 다른 것을 본다.** 2는 *패턴*, 3은 *범위*, 4는 *우리 약속과 적정함*.
- **4층의 두 도구는 결과물이 다르다** — `code-audit`은 *"과설계인가?"* 를 판단하고, ponytail은 ***"이걸 지워라"* 목록**을 만든다.
- **6은 다른 모델이라 값이 있다.** 우리 층은 전부 Claude라 같은 곳을 놓친다.

## 절차

### 1단계 — 층을 돈다

| 단계 | 층 | 언제 |
|:--|:--|:--|
| **일반** (`/flow:review`) | **1·2·3·4·5** | 매번 |
| **deep** (`/flow:review deep`) | 일반 + **6** | 설계가 의심스러울 때 · 릴리스 전 |

codex는 **유료 + 코드가 외부로 나간다.** 그래서 기본에서 뺐다 — 보내기 전에 알린다.

### 2단계 — 겹친 것을 합친다

위치(파일:라인)가 같고 내용이 같은 뜻이면 같은 문제로 본다.

- **한 줄로 합치고 `출처`에 둘 다 적는다** — `OCR + claude-security`.
- **여러 층이 같이 짚은 것은 신뢰도가 높다** — 재확인에서 뒤집힐 확률이 낮다.

### 3단계 — 등급을 매긴다

| 등급 | 뜻 | 조치 |
|:--|:--|:--|
| **critical** | 보안·데이터 손실·컴파일 오류 | **하드 차단** |
| high | 머지 전 필수 수정 | 사람 판단 |
| medium | 개선 권장 | 리포트 |
| low | 참고 | 리포트 |

- 임계는 `workflow.config.json`의 `review.severity` (기본 `critical`).
- **룰 기반(1·2·5)이 낸 critical만 하드 차단**이고, **LLM 단독 판단은 등급과 무관하게 리포트**다 — 오탐으로 사람을 지치게 하지 않는다.

### 4단계 — critical·high를 반증한다 (7층)

`verifier`에 넘긴다. **자기 발견을 자기가 확인하지 않는다.** 뒤집히면 등급을 내리고 사유를 적는다.

### 5단계 — 회차가 쌓일 때

`6.review/`는 회차로 쌓인다. **최신만 보면 이전 critical이 묻힌다.**

```
6.review/00.코드리뷰.20260729.md   critical 2  → 1 해결, 1 미해결
        01.코드리뷰.20260805.md   critical 1  (새 것)
        02.코드리뷰.20260812.md   critical 0  ← 최신만 보면 "깨끗함"
```

| 누가 | 무엇을 보나 |
|:--|:--|
| **새 리뷰를 쓸 때** | 이전 회차의 미해결을 **먼저 읽어 이번 리포트에 이어 적는다** |
| **`gatekeeper`** | **전 회차의 미해결 critical 합계** |
| **`/flow:commit`** | 같음 — 미해결 critical이 있으면 알린다 |

`상태`는 셋뿐이다 — `미해결` · `수정됨(NN회차)` · `보류(사유)`. 해결됐으면 그 회차 문서의 칸을 갱신하고 **지우지 않는다.**

## 출력 형식

`6.review/NN.코드리뷰.YYYYMMDD.md`에 `06.review` 템플릿으로 적는다. **판정이 첫 절이다.**

```markdown
## 판정

차단: 2건   critical 미해결 — src/UserMapper.java:42 · SessionFilter.java:18
리포트: 5건  high 1 · medium 3 · low 1
이전 회차 미해결: 1건 — 6.review/00

## 발견 (severity 순)

| severity | 위치 | 내용 | 근거 | 재확인 | 상태 |
|:--|:--|:--|:--|:--|:--|
| critical | UserMapper.java:42 | 문자열 연결로 SQL 조립 | OCR + claude-security | 확인됨 | 미해결 |
| high | LoginCtl.java:88 | 없는 계정과 있는 계정의 응답이 다르다 | 문서에 없음 — 계정 열거 | 확인됨 | 수정됨(02회차) |

## 안 본 주제

- 6 설계 의심 — codex 미설치
- 3 흐름 추적 — joern 없음, 축소 모드로 2홉까지만
```

`critical`이 없고 이전 회차도 깨끗하면 `차단: 0건`으로 적고 넘긴다. **`안 본 주제`를 비우지 않는다.**

## 경계

- **고치지 않는다.** 발견과 위치만 반환한다 — 수정은 `/flow:build`.
- **critical만 하드 차단.** high 이하로 진행을 막지 않는다.
- **LLM 단독 추측은 리포트만.** 근거(파일:라인·룰 이름)가 없으면 등급을 매기지 않는다.
- **자기 발견을 자기가 확인하지 않는다** — critical·high는 `verifier`가 본다.
- **도구가 없다고 멈추지 않는다.** 빠진 층을 적고 나머지로 진행한다. **"안 봤다"를 "문제없다"로 적지 않는다.**
- **이전 지적을 반복해 올리지 않는다** — *"그건 이래서 괜찮다"* 로 정리된 것은 그 판단을 인용한다.
- **회차를 합치거나 지우지 않는다** — 이력이다.
- **`review.severity`를 리뷰가 바꾸지 않는다** — 프로젝트 설정이다.
- **codex에 코드를 보내기 전에 알린다** — 외부 전송이다.
