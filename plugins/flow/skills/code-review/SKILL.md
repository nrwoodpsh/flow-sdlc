# 코드리뷰

한 도구로는 다 못 잡는다. **종류가 다른 오류를 층으로 나눠** 잡고, 겹치는 것은 한 번만 보고한다.

**고치지 않는다.** 발견과 위치만 돌려준다 — 수정은 구현 국면의 일이다.

## 어느 조각을 읽나

| 이 상황이면 | 반드시 읽는다 |
|:--|:--|
| 리뷰를 **돌린다** — 어느 층을 켜고 무엇을 건너뛰나 | `references/layers.md` |
| 발견에 **등급을 매긴다** · 차단할지 정한다 · 이전 회차를 잇는다 | `references/severity.md` |
| 구현 중 **스스로 점검한다** · 우리 규약을 지켰나 본다 | `references/checklist.md` |

`/flow:build` 는 체크리스트만 쓴다. `/flow:commit` 은 미해결 critical 이 있나만 보므로 등급 조각까지다.

## 층을 이름으로 부른다

번호로 부르지 않는다 — 층이 하나 늘면 밖에서 번호로 가리킨 줄이 조용히 어긋난다.

`계약` · `패턴` · `범위` · `규약·적정함` · `취약점` · `설계 의심` · `반증` 이 층 이름이다. 무엇이 무엇을 잡나는 `layers.md` 에 있다.

## 경계

- **critical 만 하드 차단한다.** high 이하로 진행을 막지 않는다.
- **LLM 단독 추측은 리포트만.** 근거(파일:라인·룰 이름)가 없으면 등급을 매기지 않는다.
- **자기 발견을 자기가 확인하지 않는다** — critical·high 는 `verifier` 가 본다.
- **도구가 없다고 멈추지 않는다.** 빠진 층을 적고 나머지로 진행한다. **"안 봤다"를 "문제없다"로 적지 않는다.**
- **이전 지적을 반복해 올리지 않는다** — *"그건 이래서 괜찮다"* 로 정리된 것은 그 판단을 인용한다.
- **회차를 합치거나 지우지 않는다** — 이력이다.
- **`review.severity` 를 리뷰가 바꾸지 않는다** — 프로젝트 설정이다.
- **외부 모델에 코드를 보내기 전에 알린다** — 외부 전송이다.
