# 코드 감사 체크리스트 (스택 무관)

구현·리뷰에서 스택과 무관하게 통과해야 할 **명확한 게이트 항목**이다. 스택·도메인 특화 룰은 `CLAUDE.md` 와 프로젝트 패턴 문서에 위임한다.

## 가독성·구조

- [ ] 중복 코드 — 3회 이상 반복 로직은 추출 검토
- [ ] 함수 단일 책임 — 한 함수가 두 가지 이상 하지 않는가
- [ ] 의미 있는 식별자 — `temp`·`data2`·`flag` 금지
- [ ] 데드 코드 — 이번 변경으로 쓰이지 않게 된 import·변수 정리
- [ ] 범위 준수 — 요청 밖 기능·미요청 추상화가 없다 (과설계 금지). **ponytail 이 있으면 지울 목록까지** 받는다 — 없으면 판단만
- [ ] 수술적 변경 — 무관한 동작 코드·형식을 임의로 개선하지 않는다 (기존 스타일 유지, 무관한 죽은 코드는 삭제 말고 언급만)

## 정합성

- [ ] DTO 필드가 계약 타입과 일치
- [ ] 에러 코드가 계약 레지스트리와 일치
- [ ] 명명 규칙이 `CLAUDE.md` 와 일치

## 오류 처리·경계

- [ ] 외부 입력 전수 검증 (사용자·외부 API·파일)
- [ ] **발생 불가능한 시나리오에 과도한 방어 코드 금지** (토큰·복잡도 낭비)
- [ ] Null·빈 값·0·음수 경계값 처리

## 테스트

- [ ] `Verification` 명령이 Exit 0
- [ ] 완료 기준 항목마다 단위 테스트 하나 이상

## 보안 (간이)

- [ ] 외부 입력의 SQL·HTML·셸 escape
- [ ] 권한 체크 (인증 + 자원 접근권)
- [ ] 민감 정보(비밀번호·토큰·개인정보) 로깅 금지

> **코드에 박힌 비밀값**(하드코딩된 키·토큰)은 여기서 안 본다 — `claude-security` 가 스캔한다(`취약점` 층). 이 체크리스트는 **우리 규약을 지켰나**를 보고, 그쪽은 **위험한 값이 있나**를 본다.

## 경계

- **범용 코딩 룰("클린 코드로 짜라")은 넣지 않는다** — 토큰 낭비다. AI 는 이미 표준을 잘 따른다. 여기는 **명확한 게이트 항목**만 둔다.
- 발견은 리포트만 한다. 이 체크리스트로 자동 수정하지 않는다.
