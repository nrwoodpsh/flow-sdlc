# 층 — 무엇이 무엇을 잡나

| 층 | 도구 | 잡는 것 | 성격 |
|:--|:--|:--|:--|
| `계약` | `contract-gate` | 타입·컴파일 | 결정론 |
| `패턴` | **OCR** (open-code-review) | NPE·스레드 안전·XSS·SQLi — **알려진 패턴**. 줄 단위 | 결정론+LLM |
| `범위` | `code-graph` | **어디까지 번지나** — 교차 파일 영향 | 결정론 |
| `규약·적정함` | 체크리스트 + **ponytail** | **우리 규약**(계약 정합·명명·범위·테스트) + **과설계 삭제 목록** | 체크리스트 + 플러그인 |
| `취약점` | `claude-security` | 취약점 + **자체 반박** | LLM |
| `설계 의심` | **codex** `adversarial-review` | **"이 방식이 맞나"** — 설계 선택·트레이드오프·숨은 가정 | 외부 LLM |
| `반증` | `verifier` | critical·high **반증** | LLM |

- **앞 네 층은 서로 다른 것을 본다.** `패턴` 은 *패턴*, `범위` 는 *번지는 폭*, `규약·적정함` 은 *우리 약속과 적정함*이다.
- **`규약·적정함` 의 두 도구는 결과물이 다르다** — 체크리스트는 *"과설계인가?"* 를 판단하고, ponytail 은 ***"이걸 지워라"* 목록**을 만든다.
- **`설계 의심` 은 다른 모델이라 값이 있다.** 우리 층은 전부 Claude 라 같은 곳을 놓친다.

## 없으면 어떻게 되나

어느 층을 돌릴 수 있는지 먼저 본다. **없는 층은 건너뛰고 리포트에 적는다** — 멈추지 않는다.

| 확인 | 없으면 |
|:--|:--|
| `contract.gate` 설정 | `계약` 생략. 타입 오류가 안 걸린다 |
| `ocr` CLI | `패턴` 생략. **룰 검출이 빠지고 LLM 판단만 남아 오탐이 는다** |
| `joern` | `범위` 는 `code-graph` 의 축소 모드로 — 흐름 추적은 못 한다 |
| `ponytail` 플러그인 | `규약·적정함` 은 체크리스트만. **지울 목록은 못 만든다** |
| `claude-security` 플러그인 | `취약점` 생략. 취약점은 LLM 판단만 |
| `codex` 플러그인 *(`deep` 일 때만)* | `설계 의심` 생략 — `"codex 미설치 — 설계 의심 층 생략"` 을 적는다 |

**이전 회차를 먼저 읽는다.** `6.review/` 의 미해결 critical·high 가 이번 리포트에 이어져야 한다.

## 어느 층을 도나

| 단계 | 층 | 언제 |
|:--|:--|:--|
| **일반** | `계약`·`패턴`·`범위`·`규약·적정함`·`취약점` | 매번 |
| **deep** | 일반 + `설계 의심` | 설계가 의심스러울 때 · 릴리스 전 |

codex 는 **유료이고 코드가 외부로 나간다.** 그래서 기본에서 뺐다 — 보내기 전에 알린다.

## 겹친 것을 합친다

위치(파일:라인)가 같고 내용이 같은 뜻이면 같은 문제로 본다.

- **한 줄로 합치고 출처에 둘 다 적는다** — `OCR + claude-security`.
- **여러 층이 같이 짚은 것은 신뢰도가 높다** — 재확인에서 뒤집힐 확률이 낮다.

## 출력 형식

`6.review/NN.코드리뷰.YYYYMMDD.md` 에 적는다. **판정이 첫 절이다.**

```markdown
## 판정

차단: 2건   critical 미해결 — src/UserMapper.java:42 · SessionFilter.java:18
리포트: 5건  high 1 · medium 3 · low 1
이전 회차 미해결: 1건 — 6.review/00

## 발견 (severity 순)

| severity | 위치 | 내용 | 근거 | 재확인 | 상태 |
|:--|:--|:--|:--|:--|:--|
| critical | UserMapper.java:42 | 문자열 연결로 SQL 조립 | OCR + claude-security | 확인됨 | 미해결 |
| high | LoginCtl.java:88 | 없는 계정과 있는 계정의 응답이 다르다 | 문서에 없음 — 계정 열거 | 확인됨 | 수정됨(02회차) |

## 안 본 주제

- 설계 의심 — codex 미설치
- 범위 — joern 없음, 축소 모드로 2홉까지만
```

critical 이 없고 이전 회차도 깨끗하면 `차단: 0건` 으로 적고 넘긴다. **`안 본 주제` 를 비우지 않는다.**
