# 등급 · 차단 · 회차

| 등급 | 뜻 | 조치 |
|:--|:--|:--|
| **critical** | 보안·데이터 손실·컴파일 오류 | **하드 차단** |
| high | 머지 전 필수 수정 | 사람 판단 |
| medium | 개선 권장 | 리포트 |
| low | 참고 | 리포트 |

- 임계는 `workflow.config.json` 의 `review.severity` 이고 기본값은 `critical` 이다.
- **룰 기반 층(`계약`·`패턴`·`취약점`)이 낸 critical 만 하드 차단**이고, **LLM 단독 판단은 등급과 무관하게 리포트**다 — 오탐으로 사람을 지치게 하지 않는다.

## critical·high 를 반증한다

`verifier` 에 넘긴다. **자기 발견을 자기가 확인하지 않는다.** 뒤집히면 등급을 내리고 사유를 적는다.

## 회차가 쌓일 때

`6.review/` 는 회차로 쌓인다. **최신만 보면 이전 critical 이 묻힌다.**

```
6.review/00.코드리뷰.20260729.md   critical 2  → 1 해결, 1 미해결
        01.코드리뷰.20260805.md   critical 1  (새 것)
        02.코드리뷰.20260812.md   critical 0  ← 최신만 보면 "깨끗함"
```

| 누가 | 무엇을 보나 |
|:--|:--|
| **새 리뷰를 쓸 때** | 이전 회차의 미해결을 **먼저 읽어 이번 리포트에 이어 적는다** |
| **`gatekeeper`** | **전 회차의 미해결 critical 합계** |
| **`/flow:commit`** | 같음 — 미해결 critical 이 있으면 알린다 |

`상태` 는 셋뿐이다 — `미해결` · `수정됨(NN회차)` · `보류(사유)`. 해결됐으면 그 회차 문서의 칸을 갱신하고 **지우지 않는다.**

## 자율로 고쳐도 되는 범위

되돌아가 고치는 국면에서만 해당한다. 되돌아가기 상한과 멈추는 조건은 `traceability` 의 되돌아갈 범위 조각이 정본이다.

| critical | 자율 수정 |
|:--|:--|
| 컴파일 오류 | ✅ 구현 루프가 이미 한다 |
| SQL 주입·XSS 등 | ✅ 고친다. `claude-security` 는 **패치까지 제안**한다 |
| 데이터 손실 마이그레이션 | ✅ 설계 결함이라 되돌아가 고친다 |
| **요구를 고쳐야 하는 것** (예: 기능 자체가 법 위반) | ❌ **정지** — 요구는 바닥선이다 |
