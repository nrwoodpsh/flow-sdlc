# 운영·설명 문서

개발 파이프라인이 만들지 않는 문서를 쓴다. **사람이 읽는 문서**라 골격이 흔들리면 못 쓴다 — 템플릿을 강제한다.

**운영 장애와 적어둔 절차 실행에는 안전 규칙이 걸린다.** 앞선 판은 이 규칙을 라우팅 커맨드 본문에 뒀는데, 그 커맨드가 접히면서 규칙이 사라질 자리였다. **정본을 여기 둔다.**

## 어느 조각을 읽나

| 이 상황이면 | 반드시 읽는다 |
|:--|:--|
| **지금 서비스가 안 된다** · 적어둔 절차를 실행해 달라고 한다 | `references/safety.md` — **무엇을 하기 전에 먼저** |
| 장애 **회고를 쓴다** | `references/postmortem.md` |
| **운영 절차·설명 노트를 쓴다** | `references/authoring.md` |

## 시작할 때 선언한다

```
[ops-doc] 유형: {장애 회고 | 운영 절차 | 설명 노트}
          템플릿: 00.ref/03.templates/{유형}/
          착지: {경로}
```

근거가 없는 칸은 비우지 말고 **`(근거 자료에 없음)`**, 애매하면 **`[NEEDS CLARIFICATION]`** 으로 적는다. 끝나면 **무엇을 못 채웠고 누구에게 물어야 하는지** 함께 낸다.

## 경계

- **근거에 없는 걸 지어내지 않는다.** 특히 장애 시각·담당자·권한은 모르면 물어보거나 `(근거 자료에 없음)` 이다.
- **코드를 고치지 않는다.** 문서만 쓴다.
- **결정하지 않는다** — 설명 노트가 새 규칙을 만들면 그건 ADR 로 가야 한다.
- **파이프라인 문서를 이걸로 쓰지 않는다.** 요구·설계·task 는 각 커맨드가 쓴다.
- 커밋하지 않는다 — `/flow:commit` 은 사람이 요청할 때만 돈다.
