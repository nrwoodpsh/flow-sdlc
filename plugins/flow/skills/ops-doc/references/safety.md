# 운영 안전 규칙 (정본)

라우팅 커맨드에 두기 쉬운 규칙이지만 **없어지면 안전 회귀**라 정본을 여기 둔다.

## 운영 장애 — 순서가 다르다

기능 버그와 성격이 다르다. **지금 서비스가 안 되는 상태**라 순서를 바꾼다.

| | 기능 버그 | **운영 장애** |
|:--|:--|:--|
| 먼저 할 것 | 근본 원인 확정 | **완화** — 되돌리기·재시작·우회로 서비스를 살린다 |
| 그다음 | 설계 → 구현 | 근본 원인 → 수정 |
| 뒤에 오는 것 | 없음 | **회고가 반드시 따라온다** |

```
① 지금 서비스가 되고 있습니까?
     안 된다 → 완화가 먼저입니다. 되돌릴 배포가 있습니까?
     된다(느리거나 일부만) → ②로

② 근본 원인을 찾아 고칩니다
     성능·원가 문제면 종류·측정 방법을 함께 정합니다

③ 고친 뒤 회고를 씁니다
     재발 방지 조치마다 "어디로"를 적어야 파이프라인에 들어갑니다
```

- **완화를 우리가 실행하지 않는다.** 되돌리기·재시작은 **배포 시스템과 사람**의 일이다. 무엇을 해야 하는지 제시하고 멈춘다.
- **회고를 빠뜨리지 않는다.** 고치고 끝내면 회고가 안 남고 같은 장애가 다시 온다. **고친 뒤 회고를 쓸지 반드시 묻는다.**
- 장애 시각·영향 범위는 **추정하지 않는다** — 로그·알람에서 확인하거나 사용자에게 묻는다.

## 적어둔 절차를 실행해 달라고 할 때 — 단계마다 갈린다

`04.ops/` 의 운영 절차는 **사람이 따라 하는 문서**다. 통째로 실행하지 않는다.

| 단계 | 누가 |
|:--|:--|
| **`사람만` 으로 표시된 단계** | **실행하지 않는다.** 무엇을 해야 하는지 제시하고 멈춘다 |
| 표시 없는 단계 (개발·로컬) | 실행한다 |
| **표시 자체가 없는 문서** | **묻는다** — 구버전 템플릿이다. 어느 단계가 사람 몫인지 확인받고 진행한다 |

- **`사람만` 표시는 절차 문서의 `담당` 표에 있다** — 운영 반영·권한 부여·과금·데이터 삭제가 그것이다.
- **절차 문서가 없으면 실행하지 않는다.** 기억으로 배포 순서를 재구성하지 않는다 — 먼저 절차를 적는다.
- **끝났는지 확인까지 하고, 사람 몫으로 남긴 단계를 목록으로 낸다.**
