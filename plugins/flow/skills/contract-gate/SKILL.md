# 계약 검증 게이트

계약 파일은 워크플로우의 정본이다. 자연어가 아니라 **기계 검증 가능한 형식**으로 쓰는 이유는 컴파일러·타입체커가 환각·오타를 자동으로 잡기 때문이다.

## 통과 기준

`contract.gate` 명령의 **Exit code 0** 이고 에러·경고가 없는 것. 그것뿐이다.

**차단하는 것은 커맨드다.** 훅은 없다 — 설계 국면은 통과 전까지 완료로 보고하지 않고, 구현 국면은 사전 게이트에서 멈춘다.

## 어느 조각을 읽나

| 이 상황이면 | 반드시 읽는다 |
|:--|:--|
| 게이트를 **처음 설정한다** · 스택이 바뀌었다 · 계약 파일이 안 잡힌다 | `references/config.md` |
| 게이트가 **실패했다** | `references/failure.md` |

`testing` 의 실행 조각이 실패 원인 이분법을 여기로 가리킨다 — **거기가 정본이라 옮겨 적지 않는다.**

## 경계

- **게이트를 우회·완화하지 않는다.** `--noEmit` 을 빼거나 `any` 로 덮어 통과시키는 것은 금지다 — 계약이 거짓말을 시작한다.
- **컴파일 통과가 계약이 맞다는 뜻은 아니다.** 파일별로 컴파일하니 **유닛끼리 같은 이름 타입이 다르게 정의돼도 둘 다 통과한다** — 그건 리뷰가 본다.
- **뜻을 정해야 하는 실패는 자율 교정 금지.** 멈추고 설계로 돌린다.
- **`contract.gate` 를 커맨드가 임의로 바꾸지 않는다** — 프로젝트 설정이다.
