# 문서 채점 (템플릿 대조)

문서가 **제 템플릿대로 됐는지** 본다. `tdd-verify`는 코드를, `drift-check`는 코드↔문서 간격을 본다. 이 스킬은 **문서 안**을 본다.

**고치지 않는다.** 리포트가 산출물이고 수정은 작성자 몫이다.

## 시작 전 확인

| 확인 | 없으면 |
|:--|:--|
| **대상 문서의 템플릿** (`00.ref/03.templates/`) | **채점 대상이 아니다** — N/A로 넘긴다. 체크리스트를 지어내지 않는다 |
| `03.templates/VERSION`의 `flow:` 값 | 구버전 `/flow:setup`으로 만든 프로젝트다 — 리포트 맨 위에 적는다 |
| 요구 표의 `상태` 칸 | **비어 있으면 `확정`**이다 — 신규 기준을 적용한다 |
| 대상 범위 | 유닛 하나면 그대로. **유닛을 넘으면 `explorer`에 위임**한다 — 결과는 FAIL 목록이라 결론만 받으면 된다 |

**템플릿 버전이 플러그인과 다르면 리포트 맨 위에 한 줄 적는다.**

```
ℹ️ 템플릿이 flow 0.8.0 기준입니다 (현재 플러그인 0.9.0).
   새 절이 채점에서 빠질 수 있습니다 — /flow:setup 으로 동기화를 검토하세요.
```

- **차단하지 않는다.** 낡은 템플릿으로도 채점은 된다 — 다만 **새 규칙이 반만 작동한다**는 사실을 알린다.
- **버전이 같으면 아무 말도 하지 않는다.**

## 기준 = 그 문서의 템플릿

**별도 체크리스트를 만들지 않는다.** 경로가 유형을 정하고, 유형이 템플릿을 정한다.

| 문서 | 템플릿 |
|:--|:--|
| `0.requirement.md` | `00.ref/03.templates/00.requirement/` |
| `1.design.md` | `01.design/` |
| `2.task/NN.md` | `02.task-doc/` |
| `3.contract/*.ts` | `03.api-contract/` — **채점하지 않는다**(`contract-gate`가 컴파일로 판정) |
| `4.build/NN.md` | `04.build/` |
| `5.verify/NN.md` | `05.verify/` |
| `6.review/NN.md` | `06.review/` |
| `7.summary/NN.md` | `07.summary/` |
| `02.decisions/NN.md` | `08.adr/` |
| `00.ref/01.domain/*.md` | `09.domain/` |
| `00.ref/00.architecture/*.md` | `13.architecture/` |

- 템플릿이 없는 문서는 **채점 대상이 아니다**(N/A로 넘긴다).
- **`README.md`는 전부 N/A** — 유닛 인덱스·영역 인덱스는 `/flow:sync`가 git과 태그에서 계산하는 색인이다. 사람이 채우는 문서가 아니다.
- 프로젝트가 템플릿을 고쳤으면 **고친 쪽이 기준**이다 — 플러그인 원본과 비교하지 않는다.

**단 "고친 것"과 "낡은 것"을 구분해 알린다.** 둘은 겉보기가 같다 — 템플릿에 그 절이 없다.

| | 왜 절이 없나 |
|:--|:--|
| 프로젝트가 일부러 뺐다 | 커스터마이즈 — **정상** |
| **업데이트를 못 받았다** | **플러그인이 올라갔는데 템플릿이 낡았다** |

## 절의 등급 — 세 가지

템플릿의 절마다 등급이 붙어 있다. **등급이 판정 강도를 정한다.**

| 등급 | 표기 | 뜻 | 안 채우면 |
|:--|:--|:--|:--|
| **진행 필수** | `**[진행 필수]**` | **다음 커맨드가 이 내용을 소비**한다. 없으면 진행 불가·추적 끊김 | **FAIL** — `gatekeeper`도 **차단**한다 |
| **문서 필수** | `**[문서 필수]**` | **업계 표준이 요구**한다. 기계는 안 읽지만 **사람이 읽는다** | **FAIL** — 다만 `gatekeeper`는 **차단하지 않는다** |
| 선택 | `*(선택)*`·`*(해당 시)*`·표기 없음 | 있으면 좋다 | 표시만 |

**진행 필수**

| 절 | 소비하는 곳 |
|:--|:--|
| `00.requirement`·`13.architecture` **요구**(ID·완료 기준·측정 방법) | `/flow:design` 태그 · `/flow:verify project` 커버리지 · `gatekeeper` |
| `13.architecture` **요구** *(횡단 제약이 있을 때만)* | 같음 — **`SYS-*`가 0개면 비는 게 정상**이다. 작은 도구엔 횡단 제약이 없다 |
| `01.design`·`13.architecture` **설계 요소**(`D-N`+충족 요구) | `/flow:spec`이 task로 쪼갬 |
| `02.task-doc` **frontmatter 태그** | `traceability` grep · `auto` 모드 되돌아갈 범위 |
| `02.task-doc` **Logic** · **File Map** · **Verification** | `builder` 구현 · `impact-analysis` · `/flow:verify` |
| `05.verify`·`14.integration` **판정**(첫 절) | **`gatekeeper` `verify → review`가 PASS/FAIL을 여기서 읽는다** · `/flow:run`이 다음 국면 여부를 정한다 |
| `05.verify` **완료 기준 매핑** · `14.integration` **결과 상세** | `/flow:verify project` 커버리지 |
| `05.verify` **미검증** | **`/flow:verify branch`·`project`가 여기를 모아 가서 닫는다** — 비면 `DR번호`가 검증 없이 사라진다. 없을 때도 `없다`로 적는다 |
| `14.integration` **모아 온 미검증** | 같음 — **`branch`가 못 닫은 규칙을 `project`가 여기서 받는다.** 비면 그 규칙이 조용히 사라진다 |
| `06.review` **판정**(첫 절) | **`gatekeeper` `review → sync`가 미해결 critical을 여기서 읽는다**(전 회차 누적) · `/flow:commit` |
| `06.review` **발견**(severity) | `gatekeeper` critical 확인 · `/flow:commit` |
| `02.task-doc` **사용 계약** *(계약을 쓰는 task만)* | **계약은 task와 M:N** — 여기가 유일한 추적 자리다. 비면 `impact-analysis`가 계약 변경의 영향 task를 못 찾는다 |
| `13.architecture` **외부 의존의 `우리 요구와 맞나`** *(행이 있을 때만)* | `gatekeeper` `prd → design` — **`충돌`이면 설계 착수 금지** |
| `09.domain` **유닛 계획** *(요구가 `확정`일 때만)* | `/flow:run` 3층이 이 목록을 돈다 · `/flow:prd func`의 진입 대상 |
| `00.requirement` **유스케이스 상세의 업무 규칙** *(규칙이 있을 때만)* | `test-spec`이 **경계값 테스트를 도출**한다 — 없으면 규칙이 검증되지 않는다 |
| `09.domain` **업무 규칙**(`DR번호`) *(규칙이 있을 때만)* | 같음 — 도메인의 여러 유스케이스가 공유하는 규칙 |

**문서 필수** (표준 근거)

| 절 | 표준 |
|:--|:--|
| `09.domain` **경계** *(도메인이 둘 이상일 때만)* · **용어** | DDD — Bounded Context · Ubiquitous Language |
| `13.architecture` **크로스커팅 규칙** · **목표** · **외부 의존** | arc42 8 · 1 · 3+11 |
| `01.design`·`13.architecture` **결정 · 기각 대안** | ISO/IEC/IEEE 42010 rationale · MADR |
| `00.requirement` **액터** | UML 유스케이스 |
| `05.verify`·`14.integration` **결함** | ISO/IEC/IEEE 29119-3 Incident Report |

> **왜 표준을 따르나** — 6개월 뒤 다른 사람이 읽는다. `결정·기각`이 없으면 **같은 논쟁을 다시** 하고, `용어`가 없으면 **같은 말을 다르게** 쓴다. 기계는 안 읽지만 사람이 읽는다.

## 절차

### 1단계 — 항목별로 본다

| 항목 | 기준 |
|:--|:--|
| **절 존재** | 등급대로 — `진행 필수`·`문서 필수`는 없으면 FAIL, 선택은 표시만 |
| **빈 껍데기** | 제목만 있고 내용이 없거나, `{{ }}` 자리표시자가 그대로 남아 있나 |
| **표 채움** | 표가 머리글만 있고 행이 없나 |
| **표 깨짐** | 셀 안에 **이스케이프 안 된 `\|`** 가 있어 행의 칸 수가 머리글과 다르나 · 표 사이에 문단이 끼어 뒤 행이 **표 밖으로 나가나**. 렌더된 뒤에야 보이고, 그때는 아무도 안 본다 |
| **그림 렌더** | PlantUML 코드블록 첫 줄에 **`!pragma layout smetana`** 가 있나 (`doc-template`). 없으면 Graphviz 없는 환경에서 **그림이 안 그려진다** — 텍스트로만 보인다 |
| **링크·앵커** | 마크다운 링크의 **파일과 앵커(헤딩)가 실제로 있나.** 절 이름을 고치면 조용히 끊긴다 |
| **측정 가능** | 완료 기준이 "빠르게"·"사용자 친화적"처럼 잴 수 없는 말인가 |
| **측정 방법** | `종류`가 있는 요구(성능·원가·법·정책)에 **어떻게 잴지**가 적혀 있나 (비면 영구 gap) · **적힌 도구가 카탈로그에 있나**. `00.requirement`·`13.architecture` **둘 다 열이 있다** — 기능 제약은 `—`가 정상 |
| **측정 수단** | 성능·원가 요구에 **그 데이터를 남기는 설계 요소(`D-N`)** 가 있나 — **레벨 무관**. 없으면 방법만 적힌 것이고 **잴 수 없다** |
| **쿼터 대조** | 외부 의존에 행이 있으면 `우리 요구와 맞나`가 `OK`/`충돌`/`확인 필요`/`현행` 중 하나로 적혀 있나. **`충돌`·미기재는 FAIL** |
| **UC 입도** | 같은 명사에 동사만 다른 유스케이스가 여럿인가 (`등록`·`수정`·`삭제`·`조회`) · 실패·예외를 별도 UC로 뺐나 → **입도 위반**(`usecase`) |
| **UC 상세 조건** | 업무 규칙이 있거나 예외 흐름이 둘 이상인 UC에 **상세 절이 있나** (`usecase`). 조건에 안 걸리면 없는 게 정상 |
| **규칙 레벨** | 같은 규칙이 유스케이스 여럿에 **복사돼 있나** → `09.domain`의 `DR번호`로 올려야 한다 · `참조:`가 **없는 번호**를 가리키나 |
| **화면 ID** *(FE가 있을 때)* | `SCR-N`이 **여러 유닛에서 중복**되나 → `13.architecture`의 `화면 지도`에서 발급받아야 한다 · 지도의 화면 목록과 각 유닛 설계도가 맞나 |
| **범위 밖 대조** | `범위 밖`에 적힌 것이 **요구 목록에도 있나** → 있으면 FAIL. 만드는 것인지 안 만드는 것인지 갈린다 |
| **태그 연결** | 요구 ID·`D-N`이 실제로 이어지나 (`traceability`) |
| **모름 표기** | 추측으로 채운 흔적이 있나. 모르는 건 `확인 필요`에 있나 |

### 2단계 — 표↔그림 대조 (`00.requirement`)

**정본이 나뉘어 있다** — 표는 UC 목록·액터, 그림은 관계. 각자 자기 것만 갖되 **이름은 일치해야** 한다.

**먼저 그림 대상을 가른다.** 표의 모든 행이 그림에 올라가는 것이 아니다 — **판정표는 `usecase`에 있다.** 여기 옮겨 적지 않는다. `종류`·`상태`가 무엇을 뜻하는지가 거기 정의돼 있어, 두 곳에 두면 한쪽만 고쳐진다.

그다음 이름 집합을 비교한다.

```
그림 대상 행의 UC 이름  ↔  그림의 usecase "…"
그림 대상 행의 액터     ↔  그림의 actor "…"
```

| 발견 | 뜻 |
|:--|:--|
| 그림에만 있는 UC·액터 | **표 반영 누락** — 요구로 등록되지 않았다 |
| 그림 대상인데 그림에 없음 | **그림 미갱신** |
| 없는 이름을 가리키는 관계 | 오타 |

- **어느 쪽이 맞는지 정하지 않는다.** 지적만 하고 사람이 판단한다.
- 무엇을 대조하고 무엇을 안 하는지는 `usecase`가 정한다 — 여기 옮겨 적지 않는다.

### 3단계 — 문서끼리 값이 어긋날 때

**같은 값이 두 문서에 있고 다르면, 그 중복 자체가 결함이다.**

```
0.requirement:  완료 기준 "성공 시 JWT 발급(30분)"
3.contract:     export const TOKEN_TTL = 180        ← 3분
```

**어느 쪽이 맞나를 먼저 묻지 않는다. 왜 두 곳에 있나를 본다.**

| 값 | 정본 | 다른 곳에는 |
|:--|:--|:--|
| 요구·완료 기준 | `0.requirement`(레벨별) | **적지 않는다** — ID로 가리킨다 |
| 타입·엔드포인트·에러코드 | **`3.contract`** | 적지 않는다 |
| 용어 | **`00.common.md`**(도메인 전용은 그 도메인 파일) | 적지 않는다 — **`10.explainer`는 이름만 나열**하고 정의는 가리킨다 |
| 구조·결정·기각 | `1.design`·`13.architecture` | — |
| **이탈(Deviation)** | **task `History`** | `4.build`엔 **한 줄만** · `7.summary`는 **요약만** |
| 업무 규칙 | 레벨별 — `R`/`DR`/`SYS` (`usecase`) | `참조:`로 번호만 |
| 화면 목록 | `13.architecture` 화면 지도 | `01.design`은 발급받아 쓴다 |
| 관계(`«include»`·`«extend»`) | 유스케이스 **그림** | 표에 칸을 두지 않는다 |
| DDL | `00.ref/02.db-schema/` | `1.design`엔 구조·이유만 |
| 테마 토큰 | `00.ref/04.theme/` | 재정의 금지 |

| 상황 | 판정 |
|:--|:--|
| 정본이 아닌 쪽에 값이 **복사돼 있다** | **중복이 결함이다** — 정본 아닌 쪽을 **참조로 바꾼다** |
| **정본 쪽도 틀렸을 수 있다** | 어느 값이 옳은지는 **도메인 문제**다 — **사람이 정한다** |
| 정본이 어디인지 위 표에 없다 | **지어내지 않는다** — `확인 필요`로 적는다 |

- **리포트에는 셋을 적는다**: 어느 두 문서가 · 어느 값이 · **정본이 어디인가**.
- **코드↔문서 불일치는 여기가 아니다** — `drift-check`(존재)와 `/flow:review` ①(계약 정합성)이 본다.

### 4단계 — 회고 조치가 등록됐나 (`04.ops/` 회고)

**회고는 조치를 "어디로 보낸다"고만 적는다** — 등록은 그 커맨드가 한다(`ops-doc`). **아무도 안 돌리면 조치가 표 한 줄로 남고 같은 장애가 다시 온다.**

`어디로` 칸에 ID가 적혀 있으니 대조할 수 있다.

| `어디로` 형태 | 어디를 보나 | 없으면 |
|:--|:--|:--|
| `SYS-N` | `00.ref/00.architecture/00.requirement.md` | **미등록** |
| `DR번호` | `00.ref/01.domain/{도메인}.md`의 업무 규칙 | **미등록** |
| `{도메인}-{유닛}-N` | 그 유닛의 `0.requirement.md` | **미등록** |
| 크로스커팅 규칙 | `13.architecture`의 그 절에 해당 내용이 있나 | **미등록** |
| `04.ops/` SOP 신설 | 그 파일이 있나 | **미등록** |
| **커맨드만 적혀 있다** (`/flow:run fix`) | 대조할 ID가 없다 | **`사람 확인`** — 미등록으로 세지 않는다 |

- **`P1` 미등록은 따로 세서 맨 앞에 낸다** — 기한만 적고 넘어간 것이 가장 자주 재발한다.
- **`어디로`가 비어 있으면 그 자체가 FAIL이다** (템플릿이 비우지 말라고 한다).
- **등록해 주지 않는다.** 지적만 하고 그 커맨드로 보낸다 — 요구를 이 스킬이 쓰면 소관이 뒤섞인다.

### 5단계 — 역추출 요구는 기준이 다르다

**`상태: 확인 필요`는 코드에서 뽑은 것**이라 신규용 기준을 그대로 대면 전부 FAIL이 된다. 판정 근거는 요구 표의 **`상태` 칸**이다 — **비어 있으면 `확정`**이고 신규 기준을 적용한다(`traceability`).

| 항목 | 역추출에서 |
|:--|:--|
| 측정 가능 (완료 기준) | **N/A** — 판정하지 않는다 |
| 측정 방법·측정 수단 | **N/A** |
| 쿼터 대조 | `현행 — {실제 동작}`이면 PASS |
| `09.domain` **유닛 계획** | **N/A** — 역추출은 *무엇이 있나*고, 유닛 계획은 *무엇을 만들 것인가*다 |
| **모름 표기** | 그대로 본다 — `의도 불명`을 요구로 승격했으면 FAIL |

- **사람이 `확정`으로 바꾸면 신규와 같은 기준으로 채점한다.**
- **면제를 리포트에 밝힌다** — `역추출 N건 — 신규 기준 미적용`. 안 밝히면 "다 통과했다"로 읽힌다.

### 6단계 — FAIL마다 돌아갈 곳을 적는다

**"수정은 작성자 몫"인데 작성자가 누구인지 리포트에 없으면 사용자가 헤맨다.** 문서·절마다 소관 커맨드가 다르다.

| 발견 | 돌아갈 곳 |
|:--|:--|
| 완료 기준이 측정 불가 · 측정 방법 없음 | **`/flow:prd`** (그 레벨) |
| 쿼터 `충돌`·미기재 | **`/flow:prd sys`** |
| UC 입도 위반 · UC 상세 누락 · 표↔그림 불일치(표 쪽) | **`/flow:prd func`** |
| 업무 규칙이 여러 UC에 복사됨 | **`/flow:prd domain`** — `DR번호`로 올린다 |
| 설계 요소(`D-N`)가 요구를 안 덮음 · 없는 요구를 태그 | **`/flow:design`** |
| 측정 수단 `D-N` 없음 · 결정·기각 없음 | **`/flow:design`** |
| **`09.domain`의 경계·용어·업무 흐름·유닛 계획** | **`/flow:design domain`** — 요구 절만 `prd`다 |
| **`13.architecture`의 구조·화면 지도·크로스커팅** | **`/flow:design sys`** — 요구·외부 의존만 `prd sys`다 |
| `SCR-N` 중복 | **`/flow:design sys`** (화면 지도에서 재발급) |
| task 태그·Logic·File Map·Verification | **`/flow:spec`** |
| task가 설계 요소를 안 덮음 | **`/flow:spec`** |
| `05.verify`의 결과·결함·기대값 출처 | **`/flow:verify`** |
| `06.review`의 발견·판정 | **`/flow:review`** |
| **회고 조치 미등록** | **`어디로`에 적힌 커맨드** — `/flow:prd sys`·`/flow:prd domain`·`/flow:run fix`·`ops-doc` |
| 빈 껍데기·자리표시자 잔존 | **그 문서를 만든 커맨드** (위 표로 찾는다) |

**한 문서를 두 커맨드가 나눠 쓴다** — `09.domain`·`13.architecture`가 그렇다. **절이 어느 커맨드 소관인지 보고 보낸다.**

- **여러 FAIL이 같은 커맨드로 가면 묶어 적는다** — 한 번에 고칠 수 있다.
- **돌아갈 곳을 모르면 그렇게 적는다.** 지어내지 않는다.

## 출력 형식

**등급별로 나눠 낸다** — 무엇이 진행을 막고 무엇이 문서 품질인지 구분돼야 한다.

```
[doc-verify] 대상: doc/01.work/user/00.login/
ℹ️ 템플릿 flow 0.8.0 / 플러그인 0.9.0 — 동기화 검토 필요   (버전이 같으면 이 줄 없음)

진행 필수  (없으면 gatekeeper가 차단)
  ✅ 요구 목록 · 설계 요소 · task 태그 · Logic · File Map · Verification
  ❌ 0.requirement — 완료 기준 "빠르게 응답" 측정 불가      → /flow:prd func
  ⚠️ 1.design — D-2가 어떤 요구도 안 덮음                  → /flow:design

문서 필수  (표준 요구 · 차단은 안 함)
  ✅ 액터 · 결정·기각 대안
  ❌ 1.design 결정·기각 — 절 자체가 없음  (ISO 42010 rationale)  → /flow:design

선택
  — 배포·롤백 · 엣지 케이스  (없음)

역추출 2건 — 신규 기준 미적용   (없으면 이 줄 없음)

합계: 진행 필수 FAIL 1 · 문서 필수 FAIL 1 · 확인 1
고치지 않았습니다. 수정 후 다시 부르세요.
```

- 항목마다 **PASS / FAIL / N/A** + **어느 템플릿의 무엇** 인지 근거를 단다.
- **문서 필수 FAIL엔 표준 이름을 붙인다** — 왜 채워야 하는지 알 수 있게.
- **선택은 "없음"으로만 적는다.** FAIL이 아니다.
- **애매하면 FAIL**로 본다. 근거 없이 PASS 하지 않는다.

**문서 불일치는 정본까지 적는다.**

```
⚠ 문서 불일치: 완료 기준 값
  0.requirement.md   "JWT 30분"
  3.contract/user.ts  TOKEN_TTL = 180 (3분)
  정본: 0.requirement (완료 기준) · 계약엔 값을 복사하지 않는다
  → 어느 값이 옳은지는 사람이 정합니다. 정하면 계약은 참조로 바꾸세요.
```

**회고 조치 미등록은 `P1`을 맨 앞에.**

```
⚠ 회고 조치 미등록 2건 — doc/04.ops/00.결재지연.20260715.md
  P1  커넥션 풀 상한 조정 + 알람    → SYS-9    ← 요구 등록소에 없음
  P2  목록 조회 인덱스 검토 필수화  → 크로스커팅  ← 13.architecture에 해당 내용 없음
  → P1은 회고를 닫기 전에 착수해야 합니다. /flow:prd sys 로 등록하세요.
```

## 경계

- **문서를 고치지 않는다.** 위치와 사유만 짚는다.
- **차단하지 않는다** — 리포트가 결론이고 판단은 사람이다. (`/flow:run`의 게이트만 예외이고, **거기서도 `진행 필수`만** 차단한다)
- **`문서 필수`로 진행을 막지 않는다.** 표준이 요구하는 것이지 다음 단계가 못 도는 게 아니다.
- **등급을 임의로 올리거나 내리지 않는다** — 템플릿에 적힌 표기를 따른다.
- **내용이 맞는지는 보지 않는다.** 요율·정책이 옳은지는 도메인 문제다. **형식과 빈칸**만 본다. **어느 값이 옳은지 정하지 않는다** — 정본이 어디인지만 적는다.
- **체크리스트를 새로 만들지 않는다.** 기준은 항상 템플릿이다. 템플릿이 없으면 지어내지 말고 N/A로 넘긴다.
- **조건절이 붙은 절(`*(있을 때만)*`)을 조건 확인 없이 FAIL로 적지 않는다.** `SYS-*`가 0개인 것은 정상이다 — 작은 도구엔 횡단 제약이 없다.
- **`README.md`를 채점하지 않는다** — 계산된 색인이다.
- **역추출 면제를 밝히지 않으면 "다 통과했다"로 읽힌다.**
