# 문서 채점

문서가 **제 템플릿대로 됐는지** 본다. `testing` 은 코드를, `drift-check` 는 코드↔문서 간격을 본다. 이 스킬은 **문서 안**을 본다.

**고치지 않는다.** 리포트가 산출물이고 수정은 작성자 몫이다.

## 어느 조각을 읽나

| 이 상황이면 | 반드시 읽는다 |
|:--|:--|
| 문서를 **채점한다** — 항목별로 PASS/FAIL 을 매긴다 | `references/scoring.md` |
| 산출물의 값이 규약에서 온 것인가 | `references/vocabulary.md` |
| **차단할지만 판정한다** — `gatekeeper` 가 국면 전환을 막나 | `references/grade.md` |
| **같은 값이 두 문서에 있다** — 어느 쪽이 정본인가 | `references/canon-map.md` |

`gatekeeper` 는 등급 조각까지다 — 채점은 하지 않는다. `/flow:sync` 는 값의 정본 조각만 쓴다.

## 남의 정본을 옮겨 적지 않는다

| 무엇 | 정본 |
|:--|:--|
| 유스케이스 입도 · 그림 대상 판정 · 표↔그림 분담 | `usecase` |
| 요구 `상태` 값 · 요구 ID 연결 · gap 분류 | `traceability` |
| 절 등급의 표기 자체 (`**[진행 필수]**` 같은 표기) | 프로젝트 템플릿 |

*"판정표는 `usecase` 에 있다"* 고 적고 그 표를 옮겨 적으면 선언이 거짓이 된다. 여기 옮겨 적지 않는다.

## 경계

- **문서를 고치지 않는다.** 위치와 사유만 짚는다.
- **차단하지 않는다** — 리포트가 결론이고 판단은 사람이다. 국면 게이트만 예외이고, **거기서도 `진행 필수` 만** 차단한다.
- **`문서 필수` 로 진행을 막지 않는다.** 표준이 요구하는 것이지 다음 단계가 못 도는 게 아니다.
- **등급을 임의로 올리거나 내리지 않는다** — 템플릿에 적힌 표기를 따른다.
- **내용이 맞는지는 보지 않는다.** 요율·정책이 옳은지는 도메인 문제다 — **형식과 빈칸**만 본다.
- **체크리스트를 새로 만들지 않는다.** 기준은 항상 템플릿이다. 템플릿이 없으면 지어내지 말고 N/A 로 넘긴다.
- **`README.md` 를 채점하지 않는다** — 계산된 색인이다.
