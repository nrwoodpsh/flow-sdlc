# 채점 절차

## 시작 전 확인

| 확인 | 없으면 |
|:--|:--|
| **대상 문서의 템플릿** (`00.ref/03.templates/`) | **채점 대상이 아니다** — N/A 로 넘긴다. 체크리스트를 지어내지 않는다 |
| 템플릿 버전 | 구버전 세팅으로 만든 프로젝트다 — 리포트 맨 위에 한 줄 적는다 |
| 요구 표의 `상태` 칸 | **비어 있으면 확정**이다 — 신규 기준을 적용한다 |
| 대상 범위 | 유닛 하나면 그대로. **유닛을 넘으면 `explorer` 에 위임**한다 — 결과가 FAIL 목록이라 결론만 받으면 된다 |

**템플릿 버전이 플러그인과 다르면 알린다.** 차단하지 않는다 — 낡은 템플릿으로도 채점은 되지만 **새 규칙이 반만 작동한다**는 사실을 알린다. 버전이 같으면 아무 말도 하지 않는다.

**"프로젝트가 일부러 뺐다"와 "업데이트를 못 받았다"는 겉보기가 같다** — 템플릿에 그 절이 없다. 둘을 구분해 알린다.

## 기준은 그 문서의 템플릿이다

**별도 체크리스트를 만들지 않는다.** 경로가 유형을 정하고, 유형이 템플릿을 정한다.

- 템플릿이 없는 문서는 **채점 대상이 아니다.**
- **계약 파일은 채점하지 않는다** — `contract-gate` 가 컴파일로 판정한다.
- **`README.md` 는 전부 N/A** — `/flow:sync` 가 git 과 태그에서 계산하는 색인이다.
- 프로젝트가 템플릿을 고쳤으면 **고친 쪽이 기준이다** — 플러그인 원본과 비교하지 않는다.

## 항목별로 본다

| 항목 | 기준 |
|:--|:--|
| **절 존재** | 등급대로 — `진행 필수`·`문서 필수` 는 없으면 FAIL, 선택은 표시만 |
| **빈 껍데기** | 제목만 있고 내용이 없거나 `{{ }}` 자리표시자가 그대로 남아 있나 |
| **표 채움** | 표가 머리글만 있고 행이 없나 |
| **표 깨짐** | 셀 안에 **이스케이프 안 된 `\|`** 가 있어 칸 수가 머리글과 다르나 · 표 사이에 문단이 끼어 뒤 행이 **표 밖으로 나가나**. 렌더된 뒤에야 보이고 그때는 아무도 안 본다 |
| **그림 렌더** | PlantUML 첫 줄에 레이아웃 지시가 있나 (`doc-template` 의 다이어그램 조각). 없으면 Graphviz 없는 환경에서 **그림이 안 그려진다** |
| **링크·앵커** | 링크의 파일과 앵커가 실제로 있나. 절 이름을 고치면 조용히 끊긴다 |
| **측정 가능** | 완료 기준이 "빠르게"·"사용자 친화적"처럼 잴 수 없는 말인가 |
| **측정 방법** | `종류` 가 있는 요구에 **어떻게 잴지**가 적혀 있나 (비면 영구 gap) · 적힌 도구가 카탈로그에 있나. 기능 제약은 `—` 가 정상이다 |
| **측정 수단** | 성능·원가 요구에 **그 데이터를 남기는 설계 요소**가 있나 — 레벨 무관. 없으면 방법만 적힌 것이고 **잴 수 없다** |
| **쿼터 대조** | 외부 의존에 행이 있으면 `우리 요구와 맞나` 가 `OK`·`충돌`·`확인 필요`·`현행` 중 하나로 적혀 있나. **`충돌`·미기재는 FAIL** |
| **UC 입도** · **UC 상세 조건** | `usecase` 의 입도 조각이 기준이다 |
| **규칙 레벨** | 같은 규칙이 유스케이스 여럿에 **복사돼 있나** · `참조:` 가 **없는 번호**를 가리키나 |
| **표↔그림 대조** | `usecase` 의 그림 대상 판정표로 **먼저 대상 행을 가른 뒤** 이름 집합을 비교한다 |
| **화면 ID** *(FE 가 있을 때)* | 같은 번호가 **여러 유닛에서 중복**되나 · 화면 지도와 각 유닛 설계도가 맞나 |
| **범위 밖 대조** | `범위 밖` 에 적힌 것이 요구 목록에도 있나 → 있으면 FAIL. 만드는 것인지 안 만드는 것인지 갈린다 |
| **태그 연결** | 요구 ID·설계 요소가 실제로 이어지나 (`traceability`) |
| **모름 표기** | 추측으로 채운 흔적이 있나. 모르는 건 `확인 필요` 에 있나 |
| **값 중복** | 같은 값이 두 문서에 다르게 있나 → `canon-map.md` |

## 회고 조치가 등록됐나

**회고는 조치를 "어디로 보낸다"고만 적는다** — 등록은 그 커맨드가 한다. **아무도 안 돌리면 조치가 표 한 줄로 남고 같은 장애가 다시 온다.**

`어디로` 칸에 ID 가 적혀 있으니 대조할 수 있다.

| `어디로` 형태 | 어디를 보나 | 없으면 |
|:--|:--|:--|
| `SYS-N` | 아키텍처 요구 등록소 | **미등록** |
| `DR번호` | 그 도메인 문서의 업무 규칙 | **미등록** |
| `{도메인}-{유닛}-N` | 그 유닛의 요구 문서 | **미등록** |
| 크로스커팅 규칙 | 아키텍처 문서의 그 절에 해당 내용이 있나 | **미등록** |
| SOP 신설 | 그 파일이 있나 | **미등록** |
| **커맨드만 적혀 있다** | 대조할 ID 가 없다 | **`사람 확인`** — 미등록으로 세지 않는다 |

- **`P1` 미등록은 따로 세서 맨 앞에 낸다** — 기한만 적고 넘어간 것이 가장 자주 재발한다.
- **`어디로` 가 비어 있으면 그 자체가 FAIL 이다.**
- **등록해 주지 않는다.** 지적만 하고 그 커맨드로 보낸다.

## 역추출 요구는 기준이 다르다

**`상태: 확인 필요` 는 코드에서 뽑은 것**이라 신규용 기준을 그대로 대면 전부 FAIL 이 된다.

| 항목 | 역추출에서 |
|:--|:--|
| 측정 가능 (완료 기준) | **N/A** — 판정하지 않는다 |
| 측정 방법·측정 수단 | **N/A** |
| 쿼터 대조 | `현행 — {실제 동작}` 이면 PASS |
| 유닛 계획 | **N/A** — 역추출은 *무엇이 있나* 고, 유닛 계획은 *무엇을 만들 것인가* 다 |
| **모름 표기** | 그대로 본다 — `의도 불명` 을 요구로 승격했으면 FAIL |

- **사람이 확정으로 바꾸면 신규와 같은 기준으로 채점한다.**
- **면제를 리포트에 밝힌다** — `역추출 N건 — 신규 기준 미적용`. 안 밝히면 "다 통과했다"로 읽힌다.

## FAIL 마다 돌아갈 곳을 적는다

**수정은 작성자 몫인데 작성자가 누구인지 리포트에 없으면 사용자가 헤맨다.**

| 발견 | 돌아갈 곳 |
|:--|:--|
| 완료 기준이 측정 불가 · 측정 방법 없음 · 쿼터 `충돌` | **`/flow:prd`** (그 레벨) |
| UC 입도 위반 · UC 상세 누락 · 표↔그림 불일치(표 쪽) | **`/flow:prd`** (기능 레벨) |
| 업무 규칙이 여러 UC 에 복사됨 | **`/flow:prd`** (도메인 레벨) — 도메인 규칙으로 올린다 |
| 설계 요소가 요구를 안 덮음 · 없는 요구를 태그 · 측정 수단 없음 · 결정·기각 없음 | **`/flow:design`** |
| 도메인 문서의 경계·용어·업무 흐름·유닛 계획 | **`/flow:design`** (도메인) — 요구 절만 `prd` 다 |
| 아키텍처 문서의 구조·화면 지도·크로스커팅 · 화면 번호 중복 | **`/flow:design`** (시스템) — 요구·외부 의존만 `prd` 다 |
| task 태그·`Logic`·`File Map`·`Verification` · task 가 설계 요소를 안 덮음 | **`/flow:design`** (기능) |
| 검증 결과의 결과·결함·기대값 출처 | **`/flow:verify`** |
| 리뷰의 발견·판정 | **`/flow:review`** |
| 회고 조치 미등록 | **`어디로` 에 적힌 커맨드** |
| 빈 껍데기·자리표시자 잔존 | **그 문서를 만든 커맨드** |

**한 문서를 두 커맨드가 나눠 쓴다** — 도메인·아키텍처 문서가 그렇다. **절이 어느 커맨드 소관인지 보고 보낸다.**

- **여러 FAIL 이 같은 커맨드로 가면 묶어 적는다** — 한 번에 고칠 수 있다.
- **돌아갈 곳을 모르면 그렇게 적는다.** 지어내지 않는다.

## 출력 형식

**등급별로 나눠 낸다** — 무엇이 진행을 막고 무엇이 문서 품질인지 구분돼야 한다.

```
[doc-verify] 대상: doc/01.work/user/00.login/
ℹ️ 템플릿이 플러그인보다 낮다 — 동기화 검토 필요   (버전이 같으면 이 줄 없음)

진행 필수  (없으면 gatekeeper가 차단)
  ✅ 요구 목록 · 설계 요소 · task 태그 · Logic · File Map · Verification
  ❌ 0.requirement — 완료 기준 "빠르게 응답" 측정 불가      → /flow:prd
  ⚠️ 1.design — D-2가 어떤 요구도 안 덮음                  → /flow:design

문서 필수  (표준 요구 · 차단은 안 함)
  ✅ 액터 · 결정·기각 대안
  ❌ 1.design 결정·기각 — 절 자체가 없음  (ISO 42010 rationale)  → /flow:design

선택
  — 배포·롤백 · 엣지 케이스  (없음)

역추출 2건 — 신규 기준 미적용   (없으면 이 줄 없음)

합계: 진행 필수 FAIL 1 · 문서 필수 FAIL 1 · 확인 1
고치지 않았습니다. 수정 후 다시 부르세요.
```

- 항목마다 **PASS / FAIL / N/A** 와 **어느 템플릿의 무엇** 인지 근거를 단다.
- **문서 필수 FAIL 엔 표준 이름을 붙인다** — 왜 채워야 하는지 알 수 있게.
- **선택은 "없음"으로만 적는다.** FAIL 이 아니다.
- **애매하면 FAIL 로 본다.** 근거 없이 PASS 하지 않는다.
- 회고 조치 미등록은 `P1` 을 맨 앞에 낸다.
