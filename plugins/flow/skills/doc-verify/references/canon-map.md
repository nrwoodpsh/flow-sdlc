# 값의 정본 지도

**같은 값이 두 문서에 있고 다르면, 그 중복 자체가 결함이다.**

```
0.requirement:  완료 기준 "성공 시 JWT 발급(30분)"
3.contract:     export const TOKEN_TTL = 180        ← 3분
```

**어느 쪽이 맞나를 먼저 묻지 않는다. 왜 두 곳에 있나를 본다.**

| 값 | 정본 | 다른 곳에는 |
|:--|:--|:--|
| 요구·완료 기준 | 그 레벨의 요구 문서 | **적지 않는다** — ID 로 가리킨다 |
| 타입·엔드포인트·에러코드 | **`3.contract/`** | 적지 않는다 |
| 용어 | **`01.domain/00.common.md`** (도메인 전용은 그 도메인 파일) | 적지 않는다 — 설명 노트는 **이름만 나열**하고 정의는 가리킨다 |
| 구조·결정·기각 | 설계 문서 · 아키텍처 문서 | — |
| **이탈(Deviation)** | **task 의 `History`** | 구현 기록엔 **한 줄만** · 요약은 **요약만** |
| 업무 규칙 | 레벨별 — `R`·`DR`·`SYS` (`usecase`) | `참조:` 로 번호만 |
| 화면 목록 | 아키텍처 문서의 화면 지도 | 유닛 설계도는 발급받아 쓴다 |
| 관계(`«include»`·`«extend»`) | 유스케이스 **그림** | 표에 칸을 두지 않는다 |
| DDL | `00.ref/02.db-schema/` | 설계 문서엔 구조·이유만 |
| 테마 토큰 | `00.ref/04.theme/` | 재정의 금지 (`theme-apply`) |

## 어떻게 판정하나

| 상황 | 판정 |
|:--|:--|
| 정본이 아닌 쪽에 값이 **복사돼 있다** | **중복이 결함이다** — 정본 아닌 쪽을 **참조로 바꾼다** |
| **정본 쪽도 틀렸을 수 있다** | 어느 값이 옳은지는 **도메인 문제**다 — **사람이 정한다** |
| 정본이 어디인지 위 표에 없다 | **지어내지 않는다** — `확인 필요` 로 적는다 |

- **리포트에는 셋을 적는다** — 어느 두 문서가 · 어느 값이 · **정본이 어디인가**.
- **코드↔문서 불일치는 여기가 아니다** — 존재는 `drift-check`, 계약 정합성은 리뷰의 `계약` 층이 본다.

```
⚠ 문서 불일치: 완료 기준 값
  0.requirement.md   "JWT 30분"
  3.contract/user.ts  TOKEN_TTL = 180 (3분)
  정본: 0.requirement (완료 기준) · 계약엔 값을 복사하지 않는다
  → 어느 값이 옳은지는 사람이 정합니다. 정하면 계약은 참조로 바꾸세요.
```
