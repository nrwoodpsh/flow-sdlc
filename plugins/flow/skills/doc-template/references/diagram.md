# 다이어그램 표기 (정본)

**모든 그림은 PlantUML 로 그린다.** 여기가 정본이고 커맨드·템플릿이 이 규약을 따른다.

이 정본을 그림을 **안 그리는** 커맨드에 두면 그리라고 하는 쪽이 규약을 못 읽는다. 그래서 이 조각은 **그림을 그리는 커맨드가 싣는다.**

````
```plantuml
@startuml
!pragma layout smetana
…
@enduml
```
````

- **`!pragma layout smetana` 를 첫 줄에 넣는다.** Graphviz 없이 렌더된다 — 설치 부담을 없앤다. 시퀀스·활동에는 불필요하지만 넣어도 무해하니 **전부 넣어 규칙을 하나로** 둔다.
- **mermaid 를 쓰지 않는다.** UML 유스케이스 다이어그램 타입이 없어 플로차트로 흉내야 하고, 그러면 액터와 유스케이스가 시각적으로 구분되지 않는다.

## 무엇을 무엇으로 그리나

| 대상 | 표기 | 어디 |
|:--|:--|:--|
| 유스케이스 | `usecase` + `actor` + `rectangle` | 요구 문서 |
| 데이터 구조 (관계형) | `entity` + `hide circle` + 까마귀발(`\|\|--o{`) | 설계 문서 |
| 데이터 구조 (그래프) | `object` | 설계 문서 |
| 처리 흐름 (시간 축) | 시퀀스 — `actor`·`participant`·`database` | 설계 문서 |
| 업무 흐름 (분기) | 활동 — `start`·`if…then…else`·`stop` | 도메인 문서 · 아키텍처 문서 |
| 구성 요소·배포 단위 | `component` + `database` | 아키텍처 문서 |

- **업무 흐름이 여러 도메인을 지나면 `partition` 으로 감싼다** — 어느 단계가 누구 책임인지 그림에서 읽힌다.

## 표와 그림의 정본이 나뉘는 곳

유스케이스가 그렇다. **무엇이 표고 무엇이 그림인지는 `usecase` 의 그림 대상 조각이 정한다** — 여기 옮겨 적지 않는다.

- **각자 자기 것만 가지면 중복이 없고, 중복이 없으면 드리프트도 없다.**
- 그 밖의 그림(ERD·시퀀스·활동·컴포넌트)은 **표·본문의 산출물**이다. 새 정보를 넣지 않는다 — 어긋나면 **글이 맞다.**
- **렌더는 선택이다.** 텍스트만으로도 읽히고 표↔그림 대조도 텍스트로 한다.

## 밖으로 내보낼 때는 이미지가 필요하다

| 어디 | PlantUML |
|:--|:--|
| 편집기 (확장 설치 후) | ✅ |
| **Notion** · **docx·pdf** · GitHub 웹 | ❌ **코드 텍스트로 보인다** |

- **`/flow:publish` 가 이미지로 렌더해 올린다** — 못 하면 그 사실을 알린다.
- **`doc/` 의 정본은 텍스트다.** 이미지는 발행물에만 넣고 원본 코드블록을 지우지 않는다.
