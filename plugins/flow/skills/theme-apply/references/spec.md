# 스펙 구하기 · 형식

받은 스펙은 **`doc/00.ref/04.theme/`** 에 둔다 — 그게 프로젝트의 테마 정본이다. 파일 첨부·경로 지정·다운로드 무엇으로 받든 여기 놓고 시작한다.

## 구하는 순서 — 위에서부터 시도한다

남이 만든 것이 AI 추측보다 낫다.

| 순위 | 어디서 | 출처 표기 | 형식 |
|:--|:--|:--|:--|
| 1 | 사내 디자인시스템 · 디자이너가 준 것 | 그 이름 | 대개 토큰. 그대로 쓴다 |
| 2 | 피그마 (Figma MCP) | `피그마` | 변수로 나온다. 그대로 쓴다 |
| 3 | 브랜드 테마 카탈로그 | 그 이름 | **산문이다 — 정규화 필수** |
| 4 | **없으면 만든다** | **`AI 초안`** · 상태 `승인 대기` | 만들 때부터 토큰으로 |

- **3순위는 값이 문장 안에 있다.** *"둥근 모서리를 넉넉히 쓴다"* 는 토큰이 아니다 — **읽어서 토큰으로 옮기고, 옮긴 값이 스펙의 어느 문장에서 왔는지 적는다.** 못 옮긴 문장은 `원칙` 으로 남긴다.
- **4번은 아예 없을 때만이다.** 스펙이 있는데 빠진 토큰을 채우는 것은 금지다 — 사람 결정과 추측이 섞이면 나중에 구분이 안 된다.
- 사내 디자인시스템도 같은 형식으로 여기 두면 **팀 표준 테마**가 된다.
- `theme.source` 는 **비어 있는 게 기본**이다 — 그러면 `04.theme/` 를 쓴다. 다른 경로일 때만 채운다.

## 스펙 형식 — 4범주

frontmatter 에 토큰과 컴포넌트, 본문에 대상·매핑 기록·원칙·빠진 값이 온다.

```yaml
colors:     { primary: "#0066cc", ink: "#1d1d1f", canvas: "#ffffff", ... }
typography: { hero-display: {fontFamily, fontSize, fontWeight, lineHeight, letterSpacing}, body: {...} }
rounded:    { sm: 8px, lg: 18px, pill: 9999px }
spacing:    { xs: 8px, lg: 24px, section: 80px }
components: { button-primary: { backgroundColor: "{colors.primary}", rounded: "{rounded.pill}", ... } }
```

- 본문에는 개요·Do/Don't·반응형 같은 **원칙**이 온다.
- `{colors.primary}` 같은 **토큰 참조**를 해석해 실제 값으로 잇는다.
- 형식이 다른 스펙이면 위 4범주(색·타이포·radii·spacing)로 **정규화한 뒤** 진행한다.

## 정규화 근거를 남긴다

산문에서 옮긴 값은 **근거 문장을 함께 적는다.** 표기 없는 추정을 넣지 않는다.

| 토큰 | 스펙의 어느 문장에서 |
|:--|:--|
| rounded.pill = 9999px | "버튼은 완전히 둥글게" |
| spacing.section = 80px | "섹션 사이는 넉넉히" — **추정. 승인 필요** |
