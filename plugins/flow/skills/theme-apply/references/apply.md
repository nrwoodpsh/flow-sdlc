# 적용 범위와 절차

v1 은 이 절차를 커맨드 하나로 갖고 있었는데 그 커맨드는 위임만 했다. **여기가 정본이다** — 사용자가 이 스킬을 직접 부르면 이 절차를 돈다.

## 시작 전 확인

| 확인 | 없으면 |
|:--|:--|
| **스펙이 `doc/00.ref/04.theme/` 에 있나** | `spec.md` 로 구한다. **없는 채로 시작하지 않는다** |
| 스택 (`theme.stack`·`theme.targetPath`) | 코드에서 감지한다 — Next.js·React·Vue + Tailwind·MUI·CSS 변수 |
| 브라우저 (`test.browser`) | 화면 확인을 못 한다. 스크린샷만 남기고 **사람이 본다** |
| 이전 매핑 기록 | 첫 적용이다. 있으면 **그 매핑을 이어 쓴다** |

**표준 디자인 요구를 먼저 묻는다** — 정부 서비스 등은 표준 디자인 시스템이 요구될 수 있다. 토큰을 덮은 뒤 알면 되돌려야 한다.

## 적용 범위 — 세 단계

| Tier | 무엇 | 하는가 |
|:--|:--|:--|
| **토큰** | 색·타이포·radii·spacing | ✅ **전면 자동** |
| **컴포넌트** | button·card·input·nav 의 룩 | 🟡 **핵심만 반자동** — 프로젝트에 있는 것만 매핑 |
| **구조** | 레이아웃·화면 배치·정보 구조 | ❌ **안 함** — 원칙만 참고로 기록 |

> **스킨만 갈고 화면 구조는 그대로.** 로그인 폼의 배치는 유지하고 버튼·색·폰트·간격만 스펙대로 바뀐다.

## 토큰을 전면 적용한다

| 스택 | 산출 |
|:--|:--|
| CSS 변수 | `theme.css` (`--color-primary` 등) |
| Tailwind | `tailwind.config` 의 `theme.extend` |
| MUI | `createTheme({palette, typography, shape, spacing})` |

진입점에 연결한다. 프로젝트가 토큰을 쓰고 있으면 **전체 룩이 즉시 전환된다.**

**폰트** — 독점 폰트는 embed 하지 않는다. 스펙의 **대체 폰트**에 letter-spacing 을 미세조정한다.

## 컴포넌트는 핵심만 매핑한다

- 스펙 컴포넌트를 **프로젝트의 실제 컴포넌트에 매핑**해 토큰으로 스타일한다.
- 프로젝트에 없는 컴포넌트는 **만들지 않고 건너뛴다.**
- 매핑 결과를 기록한다 — 다음 적용 때 이어 쓴다.
- **기존 커스텀 스타일을 조용히 덮지 않는다** — 무엇이 바뀌는지 보여주고 진행한다.

## 검증

**빌드 통과만으로는 화면이 깨졌는지 알 수 없다.** `verifier` 에 넘겨 브라우저를 띄워 주요 화면을 본다.

- 스크린샷을 남기고 경로를 보고에 적는다. 스토리북이 있으면 함께 본다.
- 실패하면 리포트하고 멈춘다.

## 원칙은 보존만 한다

스펙의 Do/Don't·레이아웃 철학은 **참고 메모로만** 남긴다. 자동 적용하지 않는다.

## 출력 형식

`doc/00.ref/04.theme/` 의 스펙 문서에 적용 기록을 이어 쓴다. **스펙 파일이 정본이고 기록도 거기 붙는다.**

```markdown
## 대상

스택 Next.js + Tailwind · 경로 src/styles/ · 출처 카탈로그(정규화함) · 검증 chrome

## 매핑 기록

| 스펙 컴포넌트 | 실제 파일 | 상태 |
|:--|:--|:--|
| button-primary | src/components/Button.tsx | 적용 |
| card | src/components/Card.tsx | 적용 |
| nav | — | **프로젝트에 없음 — 건너뜀** |

## 빠진 값

| 토큰 | 무엇을 썼나 |
|:--|:--|
| spacing.section | **스펙에 없음** — 기존 80px 유지 |
| colors.danger | **스펙에 없음** — 기존 값 유지. 지어내지 않았다 |

## 원칙 (참고만 — 자동 적용하지 않음)

- 한 화면에 강조색을 두 번 이상 쓰지 않는다
- 모바일에서 hero는 한 컬럼

## History

- {YYYYMMDD} 빌드 통과 · 화면 4개 확인 · 스크린샷 doc/00.ref/04.theme/shots/
```

`빠진 값` 이 없으면 그 절을 `없다` 로 적는다. **지우지 않는다** — 다음에 스펙이 갱신됐는지 대조하는 자리다.
