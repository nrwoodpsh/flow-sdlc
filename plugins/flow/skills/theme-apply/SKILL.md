# 테마 적용 (스펙 → 코드)

받은 테마 스펙을 프론트 코드에 일관되게 반영한다.

스펙 형식·적용 범위·매핑 규칙을 여기 한 곳에 둔다. 적용하는 쪽(`/flow:theme`)과 참조하는 쪽(`/flow:design` 화면 구조)이 같은 규약을 본다.

## 시작 전 확인

| 확인 | 없으면 |
|:--|:--|
| **스펙이 `doc/00.ref/04.theme/`에 있나** | 아래 `스펙 착지처`로 구한다. **없는 채로 시작하지 않는다** |
| 스펙이 4범주로 정규화됐나 | 정규화부터. 산문 스펙은 값이 문장 안에 있다 |
| 스택 (`theme.stack`·`theme.targetPath`) | 코드에서 감지 — Next.js·React·Vue + Tailwind/MUI/CSS변수 |
| 브라우저 (`test.browser`) | `chrome` 권장. `playwright`뿐이면 스크린샷 → **사람이 본다** |
| 이전 매핑 기록 | 첫 적용이다. 있으면 **그 매핑을 이어 쓴다** |

**표준 디자인 요구를 먼저 묻는다** — eGov 등 정부 서비스는 KRDS 표준이 요구될 수 있다. 토큰을 덮은 뒤 알면 되돌려야 한다.

## 스펙 착지처

받은 스펙은 **`doc/00.ref/04.theme/`** 에 둔다 — 이게 프로젝트의 테마 정본이다.

**스펙을 구하는 순서** — 위에서부터 시도한다. 남이 만든 것이 AI 추측보다 낫다.

| 순위 | 어디서 | 출처 표기 | 형식 |
|:--|:--|:--|:--|
| 1 | 사내 디자인시스템 · 디자이너가 준 것 | 그 이름 | 대개 토큰. 그대로 |
| 2 | 피그마 (Figma MCP) | `피그마` | 변수로 나온다. 그대로 |
| 3 | 브랜드 테마 카탈로그(`getdesign.md` 등) | 그 이름 | **산문이다 — 정규화 필수** |
| 4 | **없으면 만든다** — `frontend-design` 플러그인 또는 직접 | **`AI 초안`** · 상태 `승인 대기` | 만들 때부터 토큰으로 |

- **3순위는 값이 문장 안에 있다.** *"둥근 모서리를 넉넉히 쓴다"* 는 `rounded`가 아니다 — **읽어서 토큰으로 옮기고, 옮긴 값이 스펙의 어느 문장에서 왔는지 적는다.** 못 옮긴 문장은 `원칙`으로 남긴다.
- **4번은 아예 없을 때만.** 스펙이 있는데 빠진 토큰을 채우는 건 금지다 — 사람 결정과 추측이 섞이면 나중에 구분이 안 된다.
- 파일 첨부·`@경로`·다운로드 무엇으로 받든 여기에 놓고 시작한다.
- 사내 디자인시스템도 같은 형식으로 여기 두면 **팀 표준 테마**가 된다.
- `workflow.config.json`의 `theme.source`는 **비어 있는 게 기본** — 그러면 `04.theme/`를 쓴다. 다른 경로를 쓸 때만 채운다.

## 스펙 형식

**템플릿 `15.theme`** 를 쓴다 — frontmatter에 토큰과 컴포넌트, 본문에 대상·매핑 기록·원칙·빠진 값.

```yaml
colors:     { primary: "#0066cc", ink: "#1d1d1f", canvas: "#ffffff", ... }
typography: { hero-display: {fontFamily, fontSize, fontWeight, lineHeight, letterSpacing}, body: {...} }
rounded:    { sm: 8px, lg: 18px, pill: 9999px }
spacing:    { xs: 8px, lg: 24px, section: 80px }
components: { button-primary: { backgroundColor: "{colors.primary}", rounded: "{rounded.pill}", ... } }
```

- 본문에는 Overview·Do/Don't·Responsive 등 **원칙**이 온다.
- `{colors.primary}` 같은 **토큰 참조**를 해석해 실제 값으로 잇는다.
- 형식이 다른 스펙이면 위 4범주(색·타이포·radii·spacing)로 **정규화**한 뒤 진행한다.

## 적용 범위 — 3 Tier

| Tier | 무엇 | 하는가 |
|:---|:---|:---|
| **1. 토큰** | 색·타이포·radii·spacing | ✅ **전면 자동** |
| **2. 컴포넌트** | button·card·input·nav 룩 | 🟡 **핵심만 반자동** — 프로젝트에 있는 것만 매핑 |
| **3. 구조** | 레이아웃·화면 배치·IA | ❌ **안 함** — 원칙만 참고 기록 |

> **스킨만 갈고 화면 구조는 그대로.** 로그인 폼의 배치는 유지하고 버튼·색·폰트·간격만 스펙대로 바뀐다.

## 절차

### 1단계 — Tier1 토큰 (전면)

| 스택 | 산출 |
|:--|:--|
| CSS 변수 | `theme.css` (`--color-primary` …) |
| Tailwind | `tailwind.config` 의 `theme.extend` |
| MUI | `createTheme({palette, typography, shape, spacing})` |

진입점에 연결(import)한다. 프로젝트가 토큰을 쓰고 있으면 **전체 룩이 즉시 전환**된다.

**폰트** — 독점 폰트(SF Pro 등)는 embed하지 않는다. 스펙의 **대체 폰트**(예: Inter)에 letter-spacing을 미세조정한다.

### 2단계 — Tier2 컴포넌트 매핑 (핵심만)

- 스펙 컴포넌트(`button-primary`·`card`·`input`·`nav`)를 **프로젝트의 실제 컴포넌트에 매핑**해 토큰으로 스타일한다.
- 프로젝트에 없는 컴포넌트는 **만들지 않고 건너뛴다**.
- 매핑 결과를 기록한다 — 다음 적용 때 이어 쓴다.

### 3단계 — 검증

**빌드 통과만으로는 화면이 깨졌는지 알 수 없다.** `verifier`에 넘겨 브라우저를 띄워 주요 화면을 본다.

- 스크린샷을 남기고 경로를 보고에 적는다. 스토리북이 있으면 함께.
- 실패하면 리포트하고 멈춘다.

### 4단계 — 원칙 보존

스펙의 Do/Don't·레이아웃 철학은 **참고 메모로만** 남긴다. 자동 적용하지 않는다.

## 출력 형식

`doc/00.ref/04.theme/`의 스펙 문서에 적용 기록을 이어 쓴다. **스펙 파일이 정본이고 기록도 거기 붙는다.**

```markdown
## 대상

스택 Next.js + Tailwind · 경로 src/styles/ · 출처 getdesign.md (정규화함) · 검증 chrome

## 매핑 기록

| 스펙 컴포넌트 | 실제 파일 | 상태 |
|:--|:--|:--|
| button-primary | src/components/Button.tsx | 적용 |
| card | src/components/Card.tsx | 적용 |
| nav | — | **프로젝트에 없음 — 건너뜀** |

## 빠진 값

| 토큰 | 무엇을 썼나 |
|:--|:--|
| spacing.section | **스펙에 없음** — 기존 80px 유지 |
| colors.danger | **스펙에 없음** — 기존 값 유지. 지어내지 않았다 |

### 정규화 근거   (산문 스펙일 때만)

| 토큰 | 스펙의 어느 문장에서 |
|:--|:--|
| rounded.pill = 9999px | "버튼은 완전히 둥글게" |
| spacing.section = 80px | "섹션 사이는 넉넉히" — **추정. 승인 필요** |

## 원칙 (참고만 — 자동 적용하지 않음)

- 한 화면에 강조색을 두 번 이상 쓰지 않는다
- 모바일에서 hero는 한 컬럼

## History

- {YYYYMMDD} 빌드 통과 · 화면 4개 확인 · 스크린샷 doc/00.ref/04.theme/shots/
```

`빠진 값`이 없으면 그 절을 `없다`로 적는다. **지우지 않는다** — 다음에 스펙이 갱신됐는지 대조하는 자리다.

## 경계

- **Tier3(레이아웃·IA 재설계) 금지.** 화면 배치·섹션 순서·컬럼 수를 바꾸지 않는다 — 원칙은 기록만.
- **코드 로직을 건드리지 않는다** — 스타일·테마만.
- **스타일 코드는 `builder`가 쓴다** — 커맨드가 직접 파일을 고치지 않는다.
- **스펙에 없는 값을 지어내지 않는다.** 빠진 토큰은 기본값으로 두고 `빠진 값` 절에 표기한다. 생성은 **스펙이 아예 없을 때만**(`스펙 착지처` 4순위) — 그때도 `AI 초안`으로 표시하고 승인을 받는다.
- **산문에서 옮긴 값은 근거 문장을 함께 적는다.** 표기 없는 `추정`을 넣지 않는다.
- **기존 커스텀 스타일을 조용히 덮지 않는다** — 무엇이 바뀌는지 보여주고 진행한다.
- **빌드 통과를 화면 확인으로 대신하지 않는다** — 토큰이 안 걸린 컴포넌트는 빌드가 통과한다.
- **`04.theme/`의 토큰을 화면 설계에서 재정의하지 않는다** — 여기가 정본이다.
- **폰트 라이선스** — 독점 폰트 embed 금지, 대체 폰트·시스템 스택으로.
- **표준 디자인 충돌** — KRDS 등 표준이 요구되면 적용 전 경고·확인.
