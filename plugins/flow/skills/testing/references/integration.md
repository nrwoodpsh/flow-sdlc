# 통합 범위 — 브랜치 · 프로젝트

조합 매트릭스 · 시나리오 · 결과 · 결함 · (프로젝트면) 요구 커버리지가 **한 파일**에 온다.

- **조합 매트릭스 안에서만** 케이스를 만든다 — 매트릭스에 없는 조합을 지어내면 케이스가 무한히 늘어난다.
- 매트릭스는 **축과 값**으로 적는다 — `사용자 등급 = 일반·관리자` / `상태 = 정상·잠금·휴면`.
- 결과 위치는 브랜치 통합이 `03.integration/00.branch/{브랜치}/`, 프로젝트 E2E 가 `03.integration/01.project/` 다.

## 매트릭스가 없으면 만들되 승인 없이 쓰지 않는다

혼자 하는 프로젝트엔 책임자가 없다. 그렇다고 통합테스트를 못 도는 것은 아니다.

| 상황 | 어떻게 |
|:--|:--|
| **책임자가 줬다** | 그 안에서만. 축·값을 늘리지 않는다 |
| **없다** | **요구의 업무 규칙·계약의 열거 타입에서 축과 값을 뽑아 제안**하고 승인받는다 |
| 승인 못 받았다 | **돌리지 않는다** — 매트릭스가 케이스 수를 정한다 |

- **뽑는 것과 지어내는 것은 다르다** — 축은 요구·계약에 이미 있는 것만 쓴다. 없는 축(예: `브라우저 종류`)을 추가하지 않는다. 축 하나로 케이스가 배로 는다.
- **제안한 매트릭스를 출처와 함께 적는다** — `제안(승인 20260730)`.

## 앞 범위에서 모아 온 것을 닫는다

앞 범위가 `미검증` 으로 남긴 규칙을 **먼저 모아 돌린다.** 새로 지어내지 않는다.

| 규칙 | 어디서 왔나 | 결과 |
|:--|:--|:--|
| DR-2 | leave/01.request 의 `5.verify` | 닫음 — 이 회차 |
| SYS-3 | leave/01.request 의 `5.verify` | **못 닫음 — 프로젝트 범위로 넘김** |

- **브랜치 범위를 건너뛰는 프로젝트는 프로젝트 범위가 `DR번호` 도 함께 닫는다.** 혼자 하면 두 시점이 같다 — 안 그러면 도메인 규칙이 **영원히 `미검증` 으로 남는다.** 닫은 범위를 결과에 적는다(`DR-2 — project 에서 검증`).
- 이 절을 비우지 않는다. 없으면 `없다` 로 적는다 — **비면 그 규칙이 조용히 사라진다.**
