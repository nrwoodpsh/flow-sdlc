# 케이스와 기대값

## 기대값의 출처를 찾는다

**구현을 돌려보고 나온 값을 기대값으로 적지 않는다.** 그러면 테스트가 코드의 복사본이 되어 아무것도 검증하지 않는다.

요구: *"로그인 성공 시 JWT 30분 만료"*

| | 어떻게 | 코드가 틀렸을 때 |
|:--|:--|:--|
| **정상** | 요구를 보고 → `expect(exp).toBe(30*60)` | **FAIL — 잡는다** |
| **역산** | 코드를 돌려봄 → `180` → `expect(exp).toBe(180)` | **PASS — 못 잡는다** |

**AI 가 특히 이렇게 하기 쉽다** — 방금 자기가 쓴 구현이라 그 값을 이미 알고 있다.

**출처는 넷뿐이다.**

| 출처 | 무엇 |
|:--|:--|
| 요구의 **완료 기준** | 완료 판정 |
| 요구의 **사후조건** | 끝난 뒤 남는 상태 |
| 요구의 **업무 규칙** | 경계값·예외 대상 |
| **계약** (`3.contract/`) | 타입·에러코드·응답 형식 |

- **출처를 `5.verify/` 의 완료 기준 매핑 표에 적는다** — 요구 ID 또는 규칙 번호. 못 적으면 역산했다는 뜻이다.
- **출처를 못 찾으면 멈춘다.** 요구를 보완하거나 `확인 필요` 로 남긴다 — **코드를 보고 채우지 않는다.**
- **"테스트 약화"와 다르다.** 약화는 통과시키려 기준을 낮추는 것이고, 역산은 **처음부터 기준이 코드**인 것이다. 역산은 흔적이 남지 않아 더 위험하다.
- **기대값 출처 칸이 비면 역산이다.**

## 업무 규칙에서 경계값을 뽑는다

요구의 업무 규칙에서 케이스를 만든다. **지어내지 않는다** — 규칙에 적힌 숫자·기간·예외 대상이 곧 경계다.

```
R1. 3회 실패 시 잠금 (관리자는 예외)
```

| 케이스 | 입력 | 기대 | 왜 |
|:--|:--|:--|:--|
| 경계 아래 | 2회 실패 | **통과** — 안 잠김 | 한도 직전은 정상이어야 한다 |
| **경계** | **3회 실패** | **잠김** | 규칙이 정한 지점 |
| 경계 위 | 4회 실패 | 잠김 (이미 잠김) | 넘어도 같은 상태 |
| **예외 대상** | 관리자 3회 실패 | **안 잠김** | 예외를 안 테스트하면 규칙 절반만 검증된다 |

- **규칙 하나에 최소 3케이스** — 경계 아래·경계·예외. 예외 대상이 없으면 둘이다.
- **규칙 번호를 케이스에 적는다** — 어느 규칙을 검증하는지 추적된다.
- **기간·금액도 같다** — `링크 10분 만료` 는 9분 통과 / 10분 만료 / 11분 만료다.
- **규칙이 없으면 건너뛴다.** 요구에 없는 것을 검증하면 그건 추측이다.

**기술적 경계와 다르다.**

| | 무엇 | 어디서 나오나 |
|:--|:--|:--|
| 기술적 경계 | 빈 입력 · 초과 길이 · 타임아웃 | 계약(타입·제약) |
| **업무 규칙 경계** | **3회 / 10분 / 관리자 예외** | **요구의 업무 규칙** |

## 규칙 번호가 검증 범위를 정한다

규칙이 어느 레벨에 있나는 `usecase` 의 규칙 레벨 조각이 정본이다. 여기는 **그 레벨을 어느 범위에서 돌리나** 다.

| 규칙 | 어느 범위에서 |
|:--|:--|
| **`R번호`** | **`unit`** — 유닛 안에서 끝난다 |
| **`DR번호`** | **`branch`** — 그 도메인 유닛들이 모여야 검증된다 |
| **`SYS-*`** | **`project`** — 여러 도메인이 얽힌다 |

```
LEAVE-REQUEST-1 휴가 신청·제출
  R1  반차는 반일 단위로만          → unit 에서 검증
  DR-2 3일 이상 2단 결재 (참조)     → branch — approval 유닛이 있어야 한다
  SYS-3 타인 내역 조회 금지 (참조)   → project
```

**`unit` 에서 못 돌리는 규칙을 조용히 빼지 않는다.**

| 상황 | 어떻게 |
|:--|:--|
| `R번호` 인데 다른 유닛이 필요하다 | **규칙 레벨이 틀렸다** — `DR번호` 로 올려야 한다. 그 사실을 리포트한다 |
| `DR번호`·`SYS-*` 참조 | `5.verify/` 에 **`미검증(범위: branch)`** 으로 남긴다 |
| 그 범위를 아직 안 돌렸다 | 남아 있는 것이 정상이다 — 통합 범위가 닫는다 |

- **`미검증` 을 안 적으면 사라진다** — 유닛 테스트가 다 통과했으니 규칙도 검증된 줄 안다.
- **`미검증` 이 없으면 그 절을 `없다` 로 적는다. 지우지 않는다** — 다음 범위가 모아 갈 자리다.
