# LLM 기능과 돈 드는 테스트

LLM 을 부르는 기능은 결과가 매번 다르다. **그래도 대부분은 결정론적으로 테스트된다.**

| 층 | 무엇을 | 판정 | 결정론? |
|:--|:--|:--|:--:|
| 형식 | JSON 파싱되나 · 필수 필드 있나 · 타입 맞나 | Exit code | ✅ |
| 범위 | 값이 정해진 범위 안인가 (예: 대본 60초 ±5초) | Exit code | ✅ |
| 경계 | 빈 입력 · 초과 길이 · 타임아웃 · 부적절 입력 거부 | Exit code | ✅ |
| 품질 | 재미있나 · 자연스럽나 | **사람** | ❌ |

- **앞 세 층이 대부분이다.** 품질만 사람이 본다 — 요구의 `종류` 를 `UX·체감` 으로 적고 커버리지 감사가 `사람 확인 필요` 로 분류한다.
- **Exit code 로 판정한다는 원칙은 여기서도 같다.**

## 흔들리는 것은 횟수와 임계로 고정한다

```
10회 돌려 8회 이상 60초 ±5초 → 통과
```

- **횟수와 임계를 요구 완료 기준에 적는다.** 정하면 결정론이 된다 — `8/10` 은 Exit code 로 판정된다.
- **1회만 돌려 판정하지 않는다.** 우연히 통과하거나 우연히 실패한다.
- 실패한 회차의 **입력·출력을 결함에 남긴다** — 어떤 입력에서 흔들리는지가 단서다.

## 상한 안에서만 돌린다

| 무엇 | 규칙 |
|:--|:--|
| **호출 횟수 상한** | task 의 `Verification` 에 적는다 (예: `LLM 10회 · 1회당 약 2원`) |
| **CI 에서는 줄인다** | 매 push 마다 전액을 쓰지 않는다 — 형식·경계는 mock, 범위는 소수 회차 |
| **원가 요구 검증** | 프로젝트 범위에서만 실제로 돌린다. **몇 편을 만들어 평균을 낼지**는 요구의 측정 방법에 있다 |
| **초과하면 멈춘다** | 상한을 넘으면 중단하고 리포트한다. 계속 돌리지 않는다 |

- **mock 으로는 원가를 못 잰다.** 원가 검증은 실제 호출이 필요하다.
- **비용이 드는 테스트를 사람 승인 없이 반복하지 않는다.**
- 결과의 특이사항 절에 쓴 만큼을 적는다 — `LLM 호출 24회 / 상한 30회 · 약 48원`.
