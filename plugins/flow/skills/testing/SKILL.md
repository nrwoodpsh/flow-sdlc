# 테스트 명세와 실행

v1 은 이 규약을 `tdd-verify`·`test-spec` 둘로 나눠 뒀는데 `build`·`verify` 가 **항상 둘을 같이** 실었다. 하나로 둔다.

**실행하지 않은 것은 검증이 아니다.** "통과할 것입니다"라는 추론은 판정이 아니고, 실행은 `verifier` 에이전트가 격리해서 한다.

## 시작 전 확인

**케이스를 만들기 전에 근거가 있는지 본다.** 없으면 지어내게 된다.

| 확인 | 없으면 |
|:--|:--|
| **요구의 완료 기준·사후조건** | **멈춘다** — 기대값의 출처가 없다. `확인 필요` 로 남긴다 |
| 요구의 업무 규칙 번호 | 경계값 테스트를 건너뛴다. **규칙을 만들어 늘리지 않는다** |
| 계약 (`3.contract/`) | 타입·에러코드 케이스를 못 만든다 |
| `test.command`·`test.browser` (`workflow.config.json`) | 무엇으로 돌릴지 모른다 — 물어본다. **도구·모드를 이 스킬이 정하지 않는다** |
| 앞 범위의 `미검증` 목록 | 첫 실행이다. 있으면 **그것부터 모은다** |

**구현을 아직 보지 않았다면 그대로 시작한다.** 본 뒤에 기대값을 적으면 역산이 섞인다.

## 어느 조각을 읽나

| 이 상황이면 | 반드시 읽는다 |
|:--|:--|
| 테스트를 **돌려 판정한다** · 실패했다 | `references/run.md` |
| 케이스와 **기대값을 새로 적는다** | `references/case-source.md` |
| 범위가 브랜치·프로젝트 통합이다 | `references/integration.md` |
| 대상이 **LLM 을 부르는 기능**이다 | `references/llm-cost.md` |

## 경계

- **테스트를 약화·mock 처리해 통과시키는 것 절대 금지.**
- **단위 결과는 task 번호 1:1이다** — `5.verify/NN` 을 task 번호와 다르게 붙이면 스파인이 깨진다.
- 통합·E2E 는 task 의 `Verification` 에 적힌 것만 실행한다. 임의로 무거운 테스트를 더 돌리지 않는다.
- **화면 테스트에서 모달·확인창을 띄우는 조작을 피한다** — 대화가 멈춘다. 불가피하면 먼저 알린다.
