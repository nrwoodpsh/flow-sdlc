# 추적 축

요구 ID 로 요구·설계·구현·검증을 잇는다. **레벨이 정해지면 저장 위치·파이프라인 깊이·ID 형식이 동시에 결정된다.**

규약 내용은 조각에 있다. 이 파일은 레벨 판별과 **어느 상황에 어느 조각을 읽나** 를 정한다.

## 레벨 판별 — 판정 질문은 하나다

> **"도메인을 하나 더 추가하면 이 요구가 거기에도 걸리나?"**
> **걸린다 → 시스템.** 안 걸린다 → 그 도메인. work-unit 하나에서 끝나면 → 기능.

| 레벨 | 무엇 | 예 |
|:--|:--|:--|
| 시스템 (`sys`) | 기술 구조 · **횡단 제약** | "모든 API는 JWT" · "모든 작업은 p95 200ms" · "MSA 구성" |
| 도메인 (`domain`) | 비즈니스 구조 — 경계·엔티티·용어 | "회원은 가입·로그인·탈퇴한다" |
| 기능 (`func`) | work-unit | "이메일 로그인" |

**"여러 도메인에 걸치나"로 묻지 않는다.** 도메인이 하나뿐인 프로젝트에서 답할 수 없고, 도메인이 늘 때마다 판정이 뒤집혀 **ID를 다시 매겨야 한다**(`불변·append-only` 위반).

| 요구 | 새 도메인이 생기면 | 레벨 |
|:--|:--|:--|
| "모든 출력은 UTF-8" | **걸린다** | **`SYS-*`** |
| "마크다운 표를 PDF 표로 변환한다" | 안 걸린다 | `CONVERT-*` |
| "변환은 10초 내" | 안 걸린다 (그 도메인 것) | `CONVERT-*` |
| "**모든** 작업은 10초 내" | 걸린다 | **`SYS-*`** |

- **마지막 두 줄이 요점이다** — 같은 성능 요구가 **범위를 어떻게 쓰느냐**로 갈린다.
- **`SYS-*`가 0개여도 정상이다.** 작은 도구에 횡단 제약이 없으면 시스템 요구가 없다 — 억지로 만들지 않는다.
- 레벨이 애매하면 추측하지 말고 사용자에게 묻는다.

## 어느 조각을 읽나

| 이 상황이면 | 반드시 읽는다 |
|:--|:--|
| 레벨을 정했고 어디에 쓸지 모른다 | `references/level.md` |
| 요구 번호·화면 번호를 **새로 발급**한다 | `references/id-system.md` |
| 브랜치가 갈린 상태에서 발급한다 · 머지 전 번호 중복을 본다 | `references/conflict.md` |
| 설계 요소·task 문서에 **태그를 적는다** | `references/tagging.md` |
| 요구가 검증됐나 · gap 인가를 판정한다 | `references/coverage.md` |
| 지금 어디까지 됐나 · 어디서 이어가나 | `references/unit-state.md` |
| 실패해서 앞 국면으로 되돌아간다 | `references/revert-scope.md` |

## 경계

- **ID를 재편·재사용하지 않는다.** 한 번 발급한 번호는 뜻이 고정된다.
- **task 이하에 새 ID 체계를 만들지 않는다** — 경로가 식별자다.
- **매핑 테이블을 별도 파일로 유지하지 않는다** — 태그에서 계산한다.
- **gap을 요구 삭제·축소로 닫지 않는다** — 리포트가 결론이다.
