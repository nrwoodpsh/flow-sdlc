# 코드에서 요구를 뽑기

기획서가 없고 **코드가 유일한 진실**일 때. 착지처는 `level.md`, ID 형식과 발급 순서는 `id-system.md` 가 정본이다. 여기는 **무엇을 읽어 무엇을 요구로 올리나** 다.

**뽑은 것은 정본이 아니다.** 전부 `상태: 확인 필요` 로 적는다 — 그 값의 뜻과 게이트 면제는 `coverage.md` 가 정본이다.

## 바깥에서 안으로 읽는다

요구는 밖에서 관측되는 동작이다. 안쪽(유틸·헬퍼)부터 읽으면 구현 세부가 요구로 올라온다.

| 회차 | 무엇을 읽나 | 여기서 나오는 것 |
|:--|:--|:--|
| 진입점 | 라우트·핸들러·CLI·스케줄러·큐 구독 | 무엇을 시킬 수 있나 — 액터와 기능 목록 |
| 안쪽 | 진입점이 부르는 서비스·도메인 코드 | 판정 기준·한도·거부 조건 |
| 데이터 | 스키마·마이그레이션·제약 | 무엇을 보관하나 · 필수·유일 조건 |
| 설정 | 환경변수·기능 플래그·배포 매니페스트 | 환경마다 갈리는 동작 · 외부 의존 |

**레벨이 회차의 범위를 정한다.** 같은 진입점을 봐도 무엇을 집는지가 달라진다.

| 레벨 | 무엇을 집나 |
|:--|:--|
| `sys` | 횡단 구현 — 인증·에러 처리·로깅·설정 |
| `domain` | 엔티티·서비스 경계·용어 |
| `func` | 그 모듈의 동작 |

- **진입점 목록을 먼저 뽑아 센다.** 세지 않고 들어가면 어디까지 왔는지 계산할 자리가 없다.
- **한 번에 다 읽지 않는다.** 진입점을 모듈 단위로 끊고, 회차마다 요구 표에 append 한다. 끊겨도 표가 진척을 말한다.
- 코드베이스 원문을 메인 컨텍스트로 끌어오지 않는다 — 위임 판정은 `default-reference` 의 `delegation` 조각이 정본이다.
- **안 읽은 곳에 이름을 붙여 남긴다** — 벤더·생성 코드·미독 진입점. 빈칸이면 전부 봤다고 읽힌다.

## 무엇이 요구인가 — 동작이 다 요구는 아니다

판정 질문은 하나다. **"이 동작이 없어지면 밖에서 무엇이 달라지나?"** 답이 없으면 요구가 아니다.

| 코드에 있는 것 | 요구인가 |
|:--|:--|
| 밖에서 관측되는 것 — 응답·저장된 값·보낸 알림·거부 | **요구다** |
| **하드코딩된 숫자** — 타임아웃·페이지 크기·재시도·한도 | **요구다. 값째로 적는다** — 업무 규칙의 실체가 여기 있다 |
| 설정으로 켜고 끄는 것 | 요구다. **기본값과 함께** 적는다 |
| 레이어·패턴·헬퍼·DI 배선 | 아니다 — 설계다 |
| 도달 불가 코드 · 꺼진 플래그 뒤 | 아니다. `현행 아님` 으로 따로 적는다 |
| 우회·임시 처리 · 버그로 보이는 것 | **아니다.** `의도 불명` 으로 따로 나열한다 |

**버그도 동작이다.** 코드가 하는 일과 이름·주석·테스트가 말하는 일이 어긋나면 **둘 다 적고 요구로 확정하지 않는다.** 어느 쪽이 의도인지는 코드에 없다.

## 확인과 추정을 가른다

**근거 등급은 `상태` 와 다른 축이다.** `확인 필요` 는 *사람이 아직 확정 안 했다* 이고 근거 등급은 *우리가 얼마나 봤나* 다. 둘을 하나로 합치면 무엇을 더 읽어야 하는지가 사라진다.

| 표기 | 언제 | 무엇을 적나 |
|:--|:--|:--|
| **`확인`** | 실행 경로를 끝까지 읽어 동작을 확정했다 | `확인 {파일}:{심볼}` — 위치를 반드시 |
| **`추정`** | 이름·설정 키·부분만 보고 미뤄 짐작했다 | `추정 {무엇을 보고}` |
| `의도 불명` | 동작은 확인했는데 왜 그런지 모른다 | 요구 표에 올리지 않는다 |

- **근거는 요구 칸 끝에 붙인다.** `측정 방법` 칸에 넣지 않는다 — 그 칸은 `종류` 가 있는 요구의 것이고 역추출은 면제 대상이라 자리가 어긋난다.
- **주석·문서·변수 이름은 근거가 아니다.** 낡은 주석이 코드보다 흔하다. 그것뿐이면 `추정` 이다.
- **`git log`·이슈·PR 은 왜의 근거다.** 동작의 근거로 쓰지 않는다 — 그때 그랬다는 뜻이지 지금 그렇다는 뜻이 아니다.
- **`추정` 이 절반을 넘으면 멈춘다.** 범위가 넓거나 읽는 순서가 틀렸다 — 회차를 좁혀 다시 든다.
  *(절반은 **돌려 보고 고칠 값**이다. 근거가 있어서 정한 문턱이 아니다.)*

## 표에 올릴 때

- **표를 새로 만들지 않는다** — 그 레벨 템플릿의 요구 표에 행을 더한다.
- **`func` 는 유닛을 새로 만들지 않는다.** 유닛이 있으면 그 요구 문서에 append 하고, 없으면 거부하고 도메인 레벨로 보낸다. 지어낸 번호는 나중에 실제 작업 단위와 어긋난다.
- **외부 쿼터 대조 칸에는 `현행 — {실제 동작}` 을 적는다.** 계산상 넘는 것처럼 보여도 돌고 있다면 어떻게 넘기는지(재시도·큐·캐시)를 함께 적는다. 무엇이 면제인지는 `coverage.md` 가 정본이다.
- **회차를 시작할 때 이미 적힌 근거 위치를 먼저 훑는다.** 같은 동작을 두 회차에서 뽑으면 한 동작에 ID 가 둘 생긴다 — 근거 위치가 그 대조 키다.

```markdown
| ID | 종류 | 요구 | 완료 기준 | 측정 방법 | 상태 |
|:--|:--|:--|:--|:--|:--|
| SYS-9 |  | 현행: 모든 API 요청이 세션 검사를 지난다 — 확인 `AuthFilter.java:doFilter` |  | — | 확인 필요 |
| SYS-10 |  | 현행: 로그인 실패 5회면 10분 잠근다 — 확인 `LoginService.java:lock` |  | — | 확인 필요 |
```

뽑은 뒤 근거가 실제로 그 자리에 있나를 보는 것은 `reverse-check.md` 다.
