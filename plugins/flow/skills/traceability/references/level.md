# 레벨 → 위치 · 깊이 · ID

레벨 판별 질문은 `SKILL.md` 에 있다. 여기는 판별한 뒤 **어디에 쓰고 어디까지 가나** 다.

| 레벨 | 요구 (`/flow:prd`) | 설계 (`/flow:design`) | 이후 | ID |
|:--|:--|:--|:--|:--|
| 시스템 | `00.ref/00.architecture/00.requirement.md` | `00.ref/00.architecture/01.design.md` | **정지** | `SYS-N` |
| 도메인 | `00.ref/01.domain/{도메인}.md` 의 요구 절 | 같은 파일의 경계·용어 절 | **정지** | `{도메인}-N` |
| 기능 | `01.work/{도메인}/{NN.유닛}/0.requirement.md` | `…/1.design.md` | `/flow:build` → `/flow:verify` → … | `{도메인}-{유닛}-N` |

- 시스템·도메인은 **구현 없이 ref 정본으로 착지**한다. `/flow:spike` 가 지식만 남기는 것과 같은 형태다.
- 도메인이 커지면 폴더로 올린다 — `01.domain/user/00.requirement.md`·`01.design.md`.
- **착지처가 곧 판별이다** — 아키텍처 문서에 들어갈 내용이면 시스템, 도메인 경계·용어면 도메인.

## 절차를 건너뛰는 경로

작은 일에 무거운 절차를 강요하면 사람이 flow 를 우회한다. 그렇다고 추적을 끊지는 않는다.

| 상황 | 처리 |
|:--|:--|
| 버그·작은 변경 | `/flow:prd` 없이 `/flow:design` 부터. **`/flow:design` 이 요구를 자동 발급**해 `0.requirement.md` 에 이어 적는다 |
| 상위 요구가 없는 기능 (고아) | 허용. `/flow:verify` 의 커버리지 감사가 "상위 미연결"로 리포트한다 — 그 뒤 처리는 `coverage.md` |
| 문구·오타 (동작이 안 바뀐다) | flow 밖 — **진짜 면제** |

- **버그는 크기가 아니라 원인 하나가 단위다.** 한 줄 수정이어도 task 문서를 만든다.

## 코드부터 들어올 때 — 첫 커맨드

문서가 먼저 있는 전제로만 적으면 **주 사용 상황인 레거시에 갈 곳이 없다.** 라우팅의 정본이 여기다.

| 무엇을 들고 왔나 | 첫 커맨드 | 왜 |
|:--|:--|:--|
| 돌고 있는 코드뿐 — 문서가 없거나 낡았다 (`레거시`) | `/flow:prd {레벨} legacy` | 현행을 요구로 올리는 것이 먼저다. 뽑는 절차는 `reverse-extract.md` |
| 될지 안 될지를 모른다 (`불확실`) | `/flow:spike` | 버릴 코드로 먼저 확인한다 — 설계를 미검증 위에 쌓지 않는다 |

- **역추출이어도 착지처는 위 표 그대로다.** 레벨이 정해지면 어디에 쓰는지가 같이 정해진다.
- 뽑은 요구의 상태·게이트 면제는 `coverage.md` 가 정본이다. 여기서 판정하지 않는다.
