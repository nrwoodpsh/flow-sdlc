# 실패해서 되돌아갈 때 — 무엇을 다시 도나

**태그로 계산한다.** 범위를 손으로 정하면 넓어지고, 넓어지면 끝이 없다.

```
D-2를 고쳤다
  → grep "design:.*D-2"  →  2.task/01.length-check.md 만 걸림
  → 그 task만 설계 → 구현 → 검증 재실행
  → D-1 쪽 task는 건드리지 않는다
```

- **태그에 걸리지 않는 것을 임의로 다시 돌리지 않는다.**
- 고친 내용은 그 문서 `History` 에 **왜 고쳤는지** 남긴다 — 자율로 바꾼 것이 조용히 묻히면 안 된다.
- **되돌아가기는 유닛당 2회까지.** 두 번 고쳐도 안 되면 설계가 아니라 요구 문제일 확률이 높다 → 정지.

## 멈추는 조건

| 조건 | 왜 |
|:--|:--|
| 요구를 고쳐야 한다 | **사람 결정이다** |
| 같은 실패가 3회 반복 | 자기 수정이 안 통한다 |
| 한 바퀴 돌았는데 진전이 없다 | 무한 루프 방지 |
| 되돌아가기 2회 초과 | 위와 같다 |
| critical 을 두 번 고쳐도 안 없어진다 | 자기 수정 범위를 넘었다 |

**요구가 바닥선이다.** 사용자가 원한 것을 AI 가 고쳐서 "완성"하면 그건 다른 물건이다.

- 자율로 고친 것은 그 발견 행의 `상태` 에 `수정됨(NN회차)` 으로 적는다.
- **고친 뒤 같은 판정을 다시 돌려 통과를 확인한다.** 안 하면 "고쳤다"는 말만 남는다.
