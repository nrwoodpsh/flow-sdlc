# 매트릭스 · gap 판정

태그를 grep 해 역인덱스를 만든다. **별도 매핑 파일을 두지 않는다** — 그게 드리프트 원인이다.

```
USER-LOGIN-1 → D-1 → 2.task/00.login-api → 4.build ✓ → 5.verify ✓   = 검증됨
USER-LOGIN-2 → D-2 → (task 없음)                                     = gap
SYS-2        → (설계 요소 없음)                                       = gap
```

`/flow:verify` 의 커버리지 감사가 실행 결과에 이 인덱스를 겹쳐 분류한다 — **검증됨 / gap / 사람 확인 필요 / 현행(미검증)**.

## 무엇이 분류를 가르나

**요구의 `종류`** — 시스템 요구엔 종류가 적혀 있다.

- `성능`·`원가` — 측정 안 했으면 **gap**이다. 자동 검증이 가능한데 안 한 것이다.
- `법·정책` — **항상 사람 확인 필요.** 테스트가 없는 게 정상이라 **gap 으로 세지 않는다**.

**요구의 `상태`** — 역추출(`확인 필요`)은 `현행(미검증)` 이고 **gap 이 아니다.** 코드엔 있고 우리 테스트만 없다. 레거시에서 이걸 안 가르면 **요구 전부가 gap 으로 나와** 리포트가 쓸모없어진다. 합계도 분리해 센다.

| 상태 | 뜻 | 게이트 |
|:--|:--|:--|
| **비움** = `확정` | 사람이 "이걸로 간다"고 정한 요구 | **신규 기준 전부 적용** — 완료 기준 측정 가능·측정 방법·측정 수단·쿼터 대조 |
| **`확인 필요`** | **역추출**, 또는 아직 확정 안 된 것 | **면제** — 코드가 하는 일을 옮긴 것이다 |
| `~~취소~~` | 폐기 — 지우지 않고 표기만 | 판정 대상 아님 |

- **신규 요구는 칸을 비운다.** 매번 `확정` 을 적는 부담을 만들지 않는다 — **비움이 곧 확정**이다.
- **역추출로 뽑은 것은 전부 `확인 필요`** 로 적는다.
- **사람이 검수해 칸을 비우면 그때부터 신규와 같은 게이트가 걸린다.** 그게 "확정했다"는 뜻이다.
- **`확인 필요` 를 게이트 우회용으로 쓰지 않는다** — 신규 요구에 붙이면 `gatekeeper` 가 판정에 적는다.

## 상위 미연결(고아)을 발견한 뒤

**"허용"이 방치를 뜻하지 않는다.** 리포트만 하고 두면 매 커버리지 감사가 같은 것을 다시 적어 **리포트가 노이즈가 된다.**

| 선택 | 언제 | 어떻게 |
|:--|:--|:--|
| **요구를 소급 발급** | **필요한 기능이었다** — 쓰이고 있고 없으면 곤란하다 | `/flow:design` 이 버그처럼 요구를 발급한다. 완료 기준은 **현재 동작**을 적고 `상태` 를 비운다(=확정) |
| **코드를 지운다** | 아무도 안 쓴다 · 실험이 남았다 | `impact-analysis` 로 호출부를 먼저 본다. 지우는 것도 변경이라 task 를 만든다 |
| **고아로 유지** | **과도기다** — 곧 요구가 붙을 예정 | **기한을 적는다** — 아키텍처 문서의 `확인 필요` 절에 `{언제까지}` 와 함께 |

- **판단 기준은 하나다** — *"이 기능이 없어지면 누가 곤란한가?"* 답이 있으면 소급 발급, 없으면 삭제.
- **`고아로 유지` 를 기한 없이 쓰지 않는다.** 기한이 없으면 영구 노이즈가 된다.
- **소급 발급한 요구는 역추출과 다르다** — 역추출은 `상태: 확인 필요` 지만 이건 **쓰기로 정한 것**이라 확정이다. 완료 기준·측정 방법을 채운다.
- **커버리지 감사가 리포트할 때 이 셋을 함께 제시한다.**
