# 소유를 가른다 — 누가 무엇을 쓰나

일을 여러 워커에게 나눌 때, **두 워커가 같은 파일을 고치면 서로 덮는다.** 그것을 미리 가르는 계산이다.

**영향 범위(`impact-analysis`)와 묻는 것이 반대다.** 그쪽은 *이걸 고치면 어디가 깨지나* 로 의존을 따라
**넓히고**, 이쪽은 *누가 무엇을 쓰나* 로 소유를 **가른다** — 교집합이 비어야 한다.

**그래서 순서가 있다. 영향 범위를 먼저 뽑는다.** 안 뽑으면 `[Mod]` 가 빠지고, 빠진 경로는 소유 집합에
없어서 두 워커가 같은 파일을 건드린다.

## 단위는 task 다

| | 왜 |
|:--|:--|
| **task** | 소유의 정본이 `File Map` 이고 그것이 task 문서의 절이다. 쓰기 게이트가 이미 그 절을 읽는다 |
| 유닛 | 굵어서 병렬이 거의 안 된다 — 한 유닛의 task 들이 대개 같은 파일을 나눠 쓴다 |
| 파일 | 잘긴 하지만 **소유를 적어 둔 정본이 없다.** 지어낸 배정은 게이트가 모른다 |

## 집합을 만들고 겹침을 본다

1. 후보 task 를 모은다 — `2.task/NN` 이 있고 `4.build/NN` 이 없는 것(`unit-state`).
2. task 마다 `File Map` 의 경로를 집합으로 뽑는다. `[New]`·`[Mod]` 를 함께 넣는다.
3. **두 집합의 교집합이 비어 있나**를 쌍마다 본다.

| 판정 | 무엇을 하나 |
|:--|:--|
| 교집합이 비었다 | 병렬로 돌릴 수 있다 |
| **겹친다** | **계획을 고치지 않고 직렬로 돌린다** |

- **겹침을 없애려고 `File Map` 을 손대지 않는다.** 그것은 쓰기 게이트의 판정 근거를 바꾸는 것이다 —
  **병렬은 편의이고 게이트는 근거다.** 편의를 위해 근거를 고치지 않는다.
- **디렉터리로 겹침을 판정하지 않는다.** 같은 폴더의 다른 파일은 겹치는 것이 아니다.
- 경로 표기가 달라도 같은 파일일 수 있다(`./src/a.ts`·`src/a.ts`). **정규화해서 비교한다.**

## 배정 순서는 이미 있다

**새 그래프를 만들지 않는다.** 번호가 곧 순서다.

| 무엇 | 어디서 오나 |
|:--|:--|
| 유닛 사이 | 유닛 번호가 의존 순서다 |
| 유닛 안 task 사이 | task 번호가 스파인이다(`unit-state`) |

- 앞 번호가 안 끝났는데 뒤 번호를 병렬로 돌리지 않는다 — 계약·스키마가 앞에서 정해진다.
- **의존이 없다고 확신할 수 없으면 직렬이다.** 병렬은 확신이 있을 때의 최적화다.

## 겹침 없음은 사전에 기계가 못 막는다

워커를 띄우는 것은 도구 호출이 아니라 **훅이 볼 시점이 없다.** 그래서 이 계산은 **약속**이다.

**다만 사후는 기계다** — 워커가 남의 소유 파일을 쓰면 그 경로가 자기 task 의 `File Map` 에 없으므로
쓰기 게이트가 막는다. **겹치게 배정하면 두 번째 워커가 그 자리에서 막힌다.**

- **그래서 겹침의 대가는 덮어쓰기가 아니라 차단이다.** 데이터가 조용히 망가지지는 않는다.
- **막는 것을 배정 검증으로 쓰지 않는다** — 막힌 뒤 고치는 것은 워커 하나를 버리는 것이다.

## 못 하는 것

| 무엇 | 왜 |
|:--|:--|
| `File Map` 밖에서 생기는 파일 | 생성물·잠금 파일은 누구 소유도 아니다. 겹치면 알 수 없다 |
| **테스트 러너의 수집 범위** | 실측에서 나온 경우다 — `vitest run` 에 설정이 없으면 리포 전체의 `*.test.ts` 를 모은다. 두 워커가 동시에 돌리면 **서로의 작성 중 테스트가 상대 판정에 섞인다.** `File Map` 밖에서 생기는 겹침이라 이 계산이 못 잡는다 — **테스트 명령이 유닛·경로로 좁혀져 있나를 따로 본다** |
| **레거시 도입 첫날** | 유닛이 없어 게이트가 `no-units` 로 통과한다 — **그 구간에는 병렬을 권하지 않는다** |
| 같은 파일을 두 task 가 함께 선언한 경우 | 둘 다 게이트를 통과한다. 이 계산이 잡아야 하고, 놓치면 아무도 안 잡는다 |
