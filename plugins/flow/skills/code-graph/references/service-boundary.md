# 서비스 경계는 못 넘는다 (정본)

**MSA 에서 서비스 간 호출은 코드가 아니라 네트워크다.** CPG 에 안 잡힌다 — 그래프 모드든 축소 모드든 같다.

```
order-svc   restTemplate.getForObject("/api/v1/user/{id}", …)
                                       ↑ 문자열 리터럴이다. 호출 엣지가 아니다
user-svc    @GetMapping("/api/v1/user/{id}")
                                       ↑ 다른 repo. 파싱 범위 밖
```

- **이건 상시다.** 단일 프로젝트에서 "못 찾을 수도 있다"와 달리, MSA 에서는 **서비스 간 호출이 항상 안 잡힌다.**
- **"영향 없음"으로 반환하면 거짓말이 된다.** 받는 쪽이 그걸로 "회귀 표면 없음"이라고 적으면 다른 서비스가 깨진다.

## 대신 계약을 축으로 본다

| 무엇을 | 어떻게 |
|:--|:--|
| 이 변경이 계약을 건드리나 | `3.contract/` 의 엔드포인트·타입이 바뀌었나 |
| 그 계약의 범위 | 계약 파일 머리의 `내부 전용` / `서비스 간` / **`외부 제공`** |
| 누가 쓰나 | **`서비스 간`·`외부 제공` 이면 코드로 못 찾는다** — 그 사실을 반환한다 |

## 무엇을 알리나

| 계약 머리의 범위 | 알림 |
|:--|:--|
| `내부 전용` | 없음 — 이 배포 단위 안에서 끝난다 |
| **`서비스 간`** | **호출하는 서비스를 함께 고쳐야 한다.** 구성 요소 표의 `repo` 열을 보여준다 |
| **`외부 제공`** | **상대 조직에 알려야 한다.** 깨는 변경이면 버전을 올렸는지·폐기를 예고했는지 묻는다 |

```
서비스 경계: 이 변경이 `서비스 간` 계약(user.ts)을 건드립니다.
             호출하는 서비스를 코드로 찾을 수 없습니다 — 구성 요소 표를 보고 사람이 확인해야 합니다.
```

- **차단하지 않는다.** 사람만 판단할 수 있다 — 상대 배포 일정을 우리가 모른다.
- **표기가 없으면 `내부 전용` 으로 보고 알리지 않는다.** 외부에 열었으면 표기가 있어야 한다.
- **`git diff` 도 한 repo 만 본다.** repo 가 갈리면 커밋 시점도 다르고 CI 도 따로 돈다 — 자동으로 잡을 방법이 없어서 **계약 표기가 유일한 방어**다.
