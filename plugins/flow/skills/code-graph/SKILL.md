# code-graph — 코드 그래프 질의

코드를 **노드와 엣지**로 본다. 파일·텍스트가 아니라 **관계를 질의**한다.

| 노드 | 엣지 |
|:--|:--|
| 함수 · 메서드 · 클래스 · 파라미터 · 변수 · 리터럴 | 호출(CALL) · 데이터 흐름(REACHES) · 제어 흐름(CFG) · 상속 · 소유 |

**왜 그래프인가** — 이 셋은 그래프 없이는 못 한다.

| 질의 | 그래프로 | 파일 읽기로 |
|:--|:--|:--|
| **외부 입력이 SQL·셸까지 닿나** | 엣지를 따라 도달성 계산 | **불가능** |
| **N홉 뒤에 무엇이 깨지나** | 전이적 도달성 한 번에 | 홉마다 후보가 곱해져 폭발 |
| **인증 없이 DB 쓰는 엔드포인트 전부** | 노드 속성 + 경로 조건 질의 | **불가능** |

**상시 인덱스를 두지 않는다.** 부를 때 스코프만 계산하고 버린다 — 낡은 그래프가 틀린 답을 준다.

## 두 모드

**Joern이 기본이다** — `[필수]` 도구다. 스킬 이름이 `code-graph`인 이유가 그래프 질의이고, 그게 없으면 목적이 사라진다.

**축소 모드는 예외 경로다.** 이때로 내려간다.

| 언제 | |
|:--|:--|
| Joern이 설치돼 있지 않다 | 설치를 안내하고 축소 모드로 진행 |
| **파싱이 실패한다** | 언어 프론트엔드가 그 코드를 못 다룬다 |
| **그래프가 빈약하다** | 노드·엣지가 거의 안 나온다 — 그 언어 지원이 얕다는 뜻 |

**둘은 할 수 있는 일이 다르다.**

| | **그래프 모드** (Joern) | **축소 모드** (LSP) |
|:--|:--|:--|
| 전이적 영향 | ✅ 홉 제한 없음 | 🟡 **1~2홉까지만** |
| 데이터 흐름(taint) | ✅ | ❌ **불가능** |
| 속성 질의 | ✅ | ❌ |
| 코드 안 문자열 (`@Qualifier("...")`) | ✅ 리터럴 노드 | 🟡 grep으로 |
| 정확도 표기 | `높음` | `보통` (LSP 없으면 `낮음`) |

**grep은 두 모드에서 다 돈다.** 겹치는 부분이 있지만, **CPG에 아예 안 들어가는 파일**이 있어서다.

| 어디 | CPG에 있나 |
|:--|:--|
| `application.yml` · `.properties` · `.env` | ❌ 프론트엔드가 없다 (코드가 아니다) |
| `.sql` 마이그레이션 | ❌ |
| HTML·템플릿 · i18n `.json` | ❌ |
| 스코프 밖 파일 | ❌ (스코프를 좁게 잡았으니) |
| 파싱 실패한 파일 | ❌ |

- `joern-parse`는 **언어 프론트엔드가 있는 소스 코드**만 그래프로 만든다. 설정·마이그레이션·템플릿은 대상이 아니다.
- 축소 모드에서 **"흐름 추적 안 함"·"2홉에서 끊음"을 결과에 반드시 적는다.** 안 본 것을 안 봤다고 해야 한다.

## 그래프 모드 — Joern

**1. 스코프 한정** — 변경 파일과 그 모듈만 파싱한다. 전체 코드베이스에 돌리지 않는다.

```
joern-parse {대상 경로} --output cpg.bin
```

**2. 질의** — 목적에 맞는 것만.

| 목적 | 무엇을 묻나 |
|:--|:--|
| **영향 범위** | 이 메서드에 **도달하는 모든 호출 경로** (역방향 전이) |
| **회귀 표면** | 이 시그니처·필드를 **쓰는 모든 곳** + 그 호출자 |
| **taint** | 외부 입력(파라미터·요청·파일)에서 **위험한 곳**(SQL·셸·경로·역직렬화)까지 경로가 있나 |
| **비밀값 누출** | 비밀 필드에서 **로그·응답·외부 호출**까지 경로가 있나 |
| **속성 검색** | 조건을 만족하는 노드 전부 — 예: 인증 검사 없이 DB 쓰기에 닿는 엔드포인트 |

- **질의문을 지어내지 않는다.** Joern 질의 문법(CPGQL)은 버전마다 다르다 — 설치된 버전의 문서·`--help`를 확인하고 쓴다. 확실치 않으면 **축소 모드로 내려가고 그렇게 적는다.**
- 결과가 100건을 넘으면 **스코프가 넓다는 뜻** — 좁혀 다시 묻는다.

**3. CPG 밖 보강** (grep) — 파싱 대상이 아닌 파일들.

```
{심볼명}   설정(yml·properties) · 라우팅 테이블 · i18n · 템플릿
{필드명}   .sql 마이그레이션 · 쿼리 문자열 파일
```

- **코드 안 문자열은 Joern이 이미 봤다**(리터럴 노드). 여기서는 **코드가 아닌 파일**만 훑는다.

**4. 정리·반환** — 그래프 원문·경로 전체가 아니라 **결론만.**

## 축소 모드 — LSP + grep

Joern이 없거나 언어가 지원되지 않을 때. **그래프 질의가 아니라 근사다.**

**1. 대상 심볼 확정** — 함수·클래스·필드 단위.

**2. 홉 전개** — 폭발을 막으려면 끊어야 한다.

| 홉 | 무엇 | 언제까지 |
|:--|:--|:--|
| 0 | 바뀐 심볼 | 항상 |
| 1 | 직접 부르는 곳 / 부르는 대상 (LSP `references`·`definition`·`implementation`) | 항상 |
| 2 | 1홉의 호출자 | **공개 API·계약·참조 10곳 초과**일 때만 |
| 3+ | — | **하지 않는다.** "여기서 끊음"에 적는다 |

**3. 문자열 보강** (grep) — 축소 모드에서는 **코드 안 문자열까지** 훑는다. LSP가 못 보기 때문이다.

```
{심볼명}   코드 안 문자열 · DI 이름 · 리플렉션 + 설정·라우팅·템플릿
```

**4. 못 하는 것을 명시** — 데이터 흐름·전이적 도달성·속성 질의. **"안 했다"고 적는다.**

## 반환 형식

부르는 쪽(`reviewer`·`impact-analysis`)이 그대로 쓸 수 있게.

```
대상: UserService.validateToken()
모드: 그래프 (Joern) · 스코프 src/user/**
정확도: 높음

영향 (전이적)
  1홉  AuthFilter.java:42 · LoginController.java:88
  2홉  ApiGateway.java:120  ← AuthFilter 경유
  구현체 MockUserService.java:15 (테스트)

흐름
  taint  없음 — 외부 입력이 SQL·셸에 닿는 경로 없음
  누출   ⚠ token 필드 → logger.debug (AuthFilter.java:51)

CPG 밖 (grep — 파싱 대상 아님)
  application.yml:12  "userService"
  V3__add_token.sql   token 컬럼 참조

테스트
  UserServiceTest.java (12건) · AuthFilterTest.java (3건)

확인 필요
  ReflectionUtils 동적 호출 — 문자열로도 안 잡힘

여기서 끊음
  없음 (전이 전체 계산)
```

축소 모드면 이렇게 바뀐다.

```
모드: 축소 (LSP + grep — Joern 없음)
정확도: 보통

여기서 끊음
  2홉 이상 · 데이터 흐름 추적 · 속성 질의  ← 전부 안 함
```

- **`여기서 끊음`·`확인 필요`를 비우지 않는다.**
- **그래프 원문·경로 전체를 반환하지 않는다** — 메인 컨텍스트를 지키려고 이 스킬을 쓰는 것이다.

## 서비스 경계는 못 넘는다

**MSA에서 서비스 간 호출은 코드가 아니라 네트워크다.** CPG에 안 잡힌다 — 그래프 모드든 축소 모드든 같다.

```
order-svc   restTemplate.getForObject("/api/v1/user/{id}", …)
                                       ↑ 문자열 리터럴이다. 호출 엣지가 아니다
user-svc    @GetMapping("/api/v1/user/{id}")
                                       ↑ 다른 repo. 파싱 범위 밖
```

- **이건 상시다.** 단일 프로젝트에서 "못 찾을 수도 있다"와 달리, MSA에서는 **서비스 간 호출이 항상 안 잡힌다.**
- **"영향 없음"으로 반환하면 거짓말이 된다.** `impact-analysis`가 그걸 받아 "회귀 표면 없음"이라고 적으면 다른 서비스가 깨진다.

**대신 계약을 축으로 본다.**

| 무엇을 | 어떻게 |
|:--|:--|
| 이 변경이 계약을 건드리나 | `3.contract/`의 엔드포인트·타입이 바뀌었나 |
| 그 계약의 범위 | 계약 파일 머리의 `내부 전용` / `서비스 간` / **`외부 제공`** (`/flow:spec`) |
| 누가 쓰나 | **`서비스 간`·`외부 제공`이면 코드로 못 찾는다** — 그 사실을 반환한다 |

반환에 **반드시 적는다**.

```
서비스 경계: 이 변경이 `서비스 간` 계약(user.ts)을 건드립니다.
             호출하는 서비스를 코드로 찾을 수 없습니다 — 구성 요소 표를 보고 사람이 확인해야 합니다.
             (13.architecture 구성 요소 · repo 열)
```

## 언어

Joern은 프론트엔드가 넓다 — **C/C++ · Java · JVM 바이트코드 · Python · JS/TS · Go · Kotlin · PHP · Ruby · Swift · C#**.

**다만 언어마다 정확도가 다르다. 미리 재단하지 말고 돌려보고 판단한다.**

| 신호 | 판단 |
|:--|:--|
| 파싱 성공 + 노드·엣지가 충분 | **그래프 모드로 진행** |
| 파싱 실패 | 축소 모드 · 사유를 적는다 |
| 그래프가 비어 있거나 호출 엣지가 거의 없다 | **그 언어 지원이 얕다** → 축소 모드 · 그렇게 적는다 |

- 판단 결과를 **기억하지 않는다** — 프로젝트마다 다르고 Joern 버전이 오르면 달라진다. 매번 돌려보고 판단한다.

## 경계

- **상시 인덱스를 만들지 않는다.** 부를 때 계산하고 버린다.
- **전체 코드베이스에 파싱을 돌리지 않는다.** 스코프는 변경 파일과 그 모듈.
- **질의문을 지어내지 않는다.** 버전 문서를 확인하고, 확실치 않으면 축소 모드로 내려가 그렇게 적는다.
- **서비스 경계를 넘는 호출을 "영향 없음"으로 적지 않는다** (`서비스 경계는 못 넘는다`) — MSA에서는 **항상** 안 잡힌다. 계약 범위(`내부 전용`/`서비스 간`/`외부 제공`)를 보고 그 사실을 반환한다.
- **모드와 정확도를 반드시 표기한다.** 축소 모드 결과를 그래프 분석처럼 보고하지 않는다.
- **못 본 것을 안 본 것으로 적는다.** `여기서 끊음`·`확인 필요`를 비우면 "다 봤다"로 읽힌다.
- **도구가 없다고 멈추지 않는다** — 축소 모드로 돌고 한계를 밝힌다.
- **결론만 반환한다** — 그래프·경로 원문을 메인으로 올리지 않는다.
