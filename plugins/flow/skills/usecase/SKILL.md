# 유스케이스 규약

유스케이스는 **기능 레벨 요구의 표현 형식**이다. 세 곳에서 쓰이는데 형식이 갈리면 추적이 끊긴다 — 규약을 여기 한 곳에 둔다.

**유스케이스만으로 시스템이 완성되지 않는다.** 비기능·횡단 제약은 `SYS-*`, 경계·용어는 도메인 요구가 맡는다. 여기는 **기능 레벨의 표현**만 정한다.

## 어느 조각을 읽나

| 이 상황이면 | 반드시 읽는다 |
|:--|:--|
| 유스케이스를 **새로 쓰거나 쪼갠다** · 표 칸을 채운다 · 상세 절이 필요한지 정한다 | `references/granularity.md` |
| **업무 규칙을 적는다** · 이 규칙이 다른 유스케이스에도 걸리나 판단한다 | `references/rule-level.md` |
| **표와 그림을 대조한다** · 무엇을 그림에 올리나 정한다 | `references/figure-scope.md` |

`doc-verify` 는 채점할 때 이 세 조각을 이름으로 가리킨다 — **판정표를 그쪽에 옮겨 적지 않는다.**

## 경계

- **유스케이스를 엔드포인트 단위로 쪼개지 않는다.** CRUD 는 하나다.
- **실패·예외를 별도 유스케이스로 빼지 않는다** — 예외 흐름이다.
- **업무 규칙을 완료 기준에 섞지 않는다.** 완료 기준은 완료 여부, 규칙은 판정 조건이다.
- **횡단 제약을 유스케이스에 넣지 않는다** — `SYS-*` 다.
- **그림에 표에 없는 유스케이스를 넣지 않는다.** 반대도 안 된다.
- **상세 절을 조건 없이 쓰지 않는다** — 자명한 것에 문서를 늘리면 다음 국면이 그걸 다 읽는다.
- **역추출은 전부 `상태: 확인 필요`** 다. 코드가 하는 일을 옮긴 것이라 완료 기준·측정이 비어도 된다.
