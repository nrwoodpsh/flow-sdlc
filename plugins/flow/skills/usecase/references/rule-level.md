# 업무 규칙과 규칙 레벨 (정본)

## 업무 규칙 — 경계값 테스트의 근거

```
- 업무 규칙:
    R1. 3회 실패 시 잠금 (관리자는 예외)
    R2. 휴면은 1년 미접속
```

- **규칙마다 `R번호` 를 단다.** 테스트가 어느 규칙을 검증하는지 가리킬 수 있어야 한다.
- **숫자·기간·예외를 명시한다.** "여러 번 실패하면"은 규칙이 아니다.
- `testing` 이 이걸 읽어 **경계값**을 만든다 — 2회 통과 / 3회 잠김 / 관리자 3회 안 잠김.
- **완료 기준과 다르다.** 완료 기준은 *"이 유스케이스가 끝났나"*, 업무 규칙은 *"어떤 조건에서 어떻게 되나"* 다.

## 규칙은 걸리는 범위의 레벨에 적는다

**여기(유스케이스)에 남의 규칙을 적지 않는다.** 여러 곳에 복사되면 한쪽만 고쳐져 어긋난다.

| 규칙이 걸리는 범위 | 어디 | ID |
|:--|:--|:--|
| **이 유스케이스 하나** | 여기 — 상세 절 | `R번호` |
| 이 도메인의 여러 유스케이스 | 도메인 문서의 **업무 규칙** 절 | **`DR번호`** |
| 여러 도메인 | 아키텍처 문서의 횡단 요구 | **`SYS-번호`** |

**판별 질문** — *"다른 유스케이스에도 이 규칙이 걸리나?"* 걸리면 올린다.

```
LEAVE-REQUEST-1 휴가 신청·제출
- 업무 규칙:
    R1. 반차 신청은 반일 단위로만 고를 수 있다     ← 이 UC만
    참조: DR-2(3일 이상 2단 결재)                ← approval 소관 · 복사 안 함
    참조: SYS-3(타인 내역 조회 금지)
```

- **올린 규칙은 `참조:` 로 적고 번호만 가리킨다.** 내용을 옮겨 적지 않는다.
- **다른 도메인의 규칙을 참조할 때도 같다** — 결재 단수는 `approval` 의 `DR-*` 이고 `leave` 는 참조만 한다.
- **`testing` 이 이 레벨을 보고 검증 범위를 정한다** — 어느 범위에서 돌리나는 그쪽 조각에 있다.
- **같은 규칙이 유스케이스 여럿에 복사돼 있으면 결함이다** — 도메인 규칙으로 올려야 한다. 채점이 이걸 본다.
