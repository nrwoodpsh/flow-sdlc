# 거둬들이고 이어간다

**거둬들이기는 수집이 아니라 계산이다.** 워커에게 결과를 물어 모으는 것이 아니라 **파일을 세서**
어디까지 됐는지 계산한다. 워커가 죽었든 살았든 답이 같다.

## 먼저 읽는다

- 무엇을 세고 무엇을 알리나 — `${CLAUDE_PLUGIN_ROOT}/skills/traceability/references/unit-state.md`

## 보고는 캐시, 파일이 정본

`unit-state` 가 이미 적어 둔 문장의 **대상을 넓힌 것**이다 — *"상태의 정본은 파일이고 README 는 캐시다."*
**워커 리포트를 README 와 같은 등급으로 내린다.**

| 무엇 | 등급 |
|:--|:--|
| `4.build/NN.md`·`5.verify/NN.md`·`6.review/` 등 유닛 스파인 파일 | **정본** |
| 워커의 완료 보고 · 태스크 기록 | **캐시** — 낡을 수 있다 |

- **보고가 완료라 해도 파일이 없으면 안 된 것이다.** 근거는 실측이다 — 이 플러그인을 만드는 과정에서
  태스크 기록이 사실과 어긋났다(완료를 기록하기 전에 런이 죽었다).
- **전환 게이트를 보고로 대신하지 않는다.** 결과가 파일로 없으면 없는 것으로 센다.
- **코디네이터가 직접 판정하지 않는다** — 진행하는 쪽이다. 판정은 `gatekeeper` 가 한다.

## 모으는 자리를 새로 만들지 않는다

| 무엇 | 어디로 |
|:--|:--|
| 국면 산출 | 유닛 스파인 그대로 — 워커가 자기 국면의 정본 자리에 쓴다 |
| 런 단위 종합 | **`/flow:sync`** — 색인·요약의 정본이 이미 거기다 |
| 왜 그렇게 했나 · 버린 시도 | task 문서의 `History` 절 |

오케스트레이션 전용 요약 파일을 두면 **정본이 둘이 된다.**

## 죽어도 이어간다 — 상태를 저장하지 않는다

**재개는 계획 복원이 아니라 같은 계산의 반복이다.** 그래서 원장이 필요 없다.

- 죽은 시점의 배정 계획을 되살리지 않는다. **파일을 다시 세면 남은 것이 나온다.**
- 재개용 커맨드도 파일도 없다 — `next` 가 파일에서 계산하는 것이 이미 그 일이다.
- 워커 산출은 **repo 안에** 쓴다. 세션 밖 임시 폴더는 비워진다(실측).

**못 잡는 것 — 고아 워커.** 코디네이터가 죽고 워커가 살아 있으면 flow 는 모른다. 프로세스를 안 보기 때문이다.
**재개 전에 사람이 남은 워커를 정리한다.** 약속이고, 기계로 적지 않는다.

## 보고 형식

```
[/flow:next] 거둬들임 — 파일에서 계산

  끝난 것   {task}  → {산출 파일}
  안 된 것   {task}  → 산출 파일 없음   (보고는 완료라 했다면 그 사실도 함께 적는다)
  판정 대기  {task}  → gatekeeper 미통과
  다음 차례  {task}

  → 이어서 돌릴까요?
```

- **보고와 파일이 어긋나면 그것을 적는다.** 조용히 파일 쪽만 쓰면 다음에 같은 일이 또 난다.
