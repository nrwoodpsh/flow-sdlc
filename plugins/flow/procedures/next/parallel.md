# 일을 갈라 워커에게 맡긴다

**flow 는 계획과 판정을 내고, 띄우는 것은 환경이 한다.** 프로세스를 알아야 하는 것은 밖이다 —
flow 가 아는 것은 파일뿐이다. 이 절차의 산출은 **배정 계획**이고 실행 명령이 아니다.

## 먼저 읽는다

- 소유 집합·겹침 판정·배정 순서 — `${CLAUDE_PLUGIN_ROOT}/skills/traceability/references/ownership.md`
- 회귀 표면을 먼저 뽑는다 — `${CLAUDE_PLUGIN_ROOT}/skills/impact-analysis/references/regression-surface.md`

**영향 범위가 선행 조건이다.** 안 뽑으면 `[Mod]` 가 빠지고, 빠진 경로는 소유 집합에 없다.

## 한도를 먼저 읽는다 — 넘는 계획을 내지 않는다

값은 `workflow.config.json` 의 `orchestration` 절에 **사람이** 적는다. 비어 있으면 **병렬을 제안하지 않는다** —
동시 수는 사용자의 구독·기기 제약이라 우리가 기본값을 정할 수 없다.

| 키 | 무엇 |
|:--|:--|
| `maxWorkers` | 동시에 띄울 수 있는 수 |
| `models` | 역할별 등급 — 진행자·판정자 |

- **한도 안으로 자른다.** 후보가 더 많으면 나머지는 다음 차례로 둔다.
- **판정자를 진행자보다 싼 등급으로 내리지 않는다.** 판정이 유일한 게이트라 거기가 약해지면
  나머지 층이 다 무의미해진다. `models` 가 그렇게 적혀 있으면 **알리고 멈춘다.**
- **등급은 약속이다** — 띄우는 것이 환경이라 flow 가 한도를 못 막는다.

## 배정 계획을 낸다

```
[/flow:next] 병렬 배정 — 후보 {N} · 한도 {maxWorkers} · 배정 {M}

  W1  {task 경로}   소유: {File Map 경로 목록}
  W2  {task 경로}   소유: {…}
  직렬로 미룸: {겹친 task} — {누구와 겹치나}
  다음 차례: {한도에 밀린 task}

  → 이대로 띄울까요?
```

- **소유 목록을 보여준다.** 무엇을 쓸 수 있는지가 지시서의 핵이고, 사람이 겹침을 눈으로 볼 수 있어야 한다.
- **겹치면 이유를 적는다.** *"직렬"* 만 적으면 계획을 고쳐야 하는지 알 수 없다.

## 워커 지시서 — task 문서가 겸한다

**새 파일을 만들지 않는다.** 워커가 받아야 하는 것은 이미 있다.

| 워커가 알아야 하는 것 | 어디 있나 |
|:--|:--|
| 무엇을 만드나 | `2.task/NN.md` — `File Map`·`Verification` |
| 무엇을 읽나 | 그 국면 커맨드의 `## 연결` 과 읽기 절 |
| 어디에 쓰나 | 유닛 스파인 — `4.build/NN.md`·`5.verify/NN.md` |
| 판정은 누가 | `gatekeeper`. 워커가 자기 산출을 판정하지 않는다 |

지시서에 덧붙일 것은 **경계 둘**뿐이다.

- **소유 밖 파일을 고치지 않는다.** 막히면 훅을 끄지 말고 멈추고 보고한다.
- **repo 안에 쓴다.** 세션 밖 임시 폴더에 쓰면 세션이 죽을 때 사라진다 — 실측된 사고다.

## 못 하는 것

- **겹침 없음을 사전에 기계가 막지 못한다** — 워커를 띄우는 것은 도구 호출이 아니라 훅이 볼 시점이 없다.
  사후는 기계다: 남의 소유 파일을 쓰면 쓰기 게이트가 막는다.
- **동시 수·프로세스 감시는 환경의 일이다.** flow 는 한도를 계획에 반영할 뿐 강제하지 못한다.
- **레거시 도입 첫날에는 병렬을 권하지 않는다** — 유닛이 없어 게이트가 `no-units` 로 통과한다.
