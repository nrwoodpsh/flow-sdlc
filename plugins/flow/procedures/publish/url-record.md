# /flow:publish — 신규·갱신 판정과 기록

**판정 근거는 기록된 URL 하나다.** 제목이나 감으로 판정하지 않는다 — 같은 유닛의 페이지를 두 번 만든다.

## 어느 회차든 URL 이 있으면 갱신이다

`7.summary/` 는 **회차로 쌓인다.** 최신 회차만 보면 URL 이 없어 **미발행으로 읽힌다.**

```
7.summary/00.구현.20260729.md   발행 URL 있음
        01.수정.20260805.md   URL 없음 (새 회차)   ← 최신만 보면 "미발행"
```

**전 회차를 뒤져 URL 을 찾는다.** 유닛당 페이지는 하나다.

| 상황 | 처리 |
|:--|:--|
| **어느 회차든 URL 이 있다** | 그 페이지를 **갱신한다.** 최신 회차에 없어도 마찬가지다 |
| **여러 회차에 URL 이 다르게 있다** | **묻는다** — 어느 페이지가 정본인가. 임의로 고르지 않는다 |
| URL 은 없는데 같은 제목의 페이지가 부모 아래 있다 | **묻는다** — 갱신할지 새로 만들지 |
| 둘 다 없다 | 부모 아래 **새 자식 페이지**를 만든다 |

## 어디에 적나 — 범위가 정한다

| 범위 | 어디에 | 무엇을 |
|:--|:--|:--|
| 유닛 | **이번에 발행한 내용의 `7.summary/` 회차 파일** | 그 유닛 페이지 URL |
| `project` 전체 | **`doc/README.md` 맨 위 한 줄** — `발행: {루트 URL} ({YYYYMMDD})` | **루트 페이지 URL.** 유닛별 자식 페이지 URL 은 각 유닛의 `7.summary/` 에 |

- **`project` 에는 회차 파일이 없다** — 여기 안 적으면 다음 발행이 **루트 페이지를 또 만든다.** 갱신 판정이 이 줄을 먼저 본다.
- **회차마다 같은 URL 이 반복되는 것이 맞다** — 어느 회차를 봐도 어디로 발행됐는지 알 수 있다.
- **이전 회차의 URL 을 지우지 않는다** — 이력이다. `doc/README.md` 의 줄은 **한 줄만 유지**하고 날짜를 갱신한다(색인이라 쌓지 않는다).
