# /flow:commit — 커밋 전 확인

넷을 본다. **드리프트만 훅이 막고, 나머지 셋은 확인이다** — 판단은 사용자가 한다. 확인을 차단으로 바꾸면 사람이 훅을 꺼 버린다.

## 드리프트

소스는 바뀌었는데 대응 문서가 아무것도 안 바뀌었나. **소스 판정 규칙은 `drift-check/rule` 이 정본이고, git 훅·CI 가 같은 규칙을 읽는다.**

- 걸리면 `/flow:sync` 를 먼저 돌릴지 묻는다. `2.task`·`3.contract`·`5.verify`·`7.summary` 중 어느 것이 바뀌었어도 인정한다.
- 오타·주석·설정 변경이면 그대로 진행한다.
- **여기서 답을 받았어도 훅을 끄지 않는다.** 훅이 막으면 그 사실을 알리고 멈춘다(`/flow:commit` 의 `게이트` 절).

## 스키마 문서

마이그레이션이 들어 있는데 `doc/00.ref/02.db-schema/` 가 안 바뀌었나. **훅·CI 가 못 잡는 자리다** — `doc/` 아래라 드리프트 판정에서 문서로 취급된다.

- 경로는 프로젝트마다 다르다 — **글롭으로 판정하지 않고 변경 내용을 보고 판단한다.**

  ```
  ⚠ 마이그레이션이 있는데 doc/00.ref/02.db-schema/ 가 안 바뀌었습니다.
    거기가 지금 상태의 정본이라, 안 맞추면 다음 세션이 없는 컬럼을 믿습니다.
    지금 갱신할까요? (그냥 커밋해도 됩니다)
  ```

- **확인이다.** 스키마와 무관한 SQL(조회·데이터 보정)이면 그대로 진행한다.

## 리뷰

- **이번 변경에 리뷰 기록이 없으면 알린다** — 대응 유닛의 `6.review/` 가 비었거나 이번 변경보다 오래됐을 때다. 코드에 박힌 값·취약점을 아직 아무도 안 봤다는 뜻이다.
- **미해결 critical 은 전 회차를 누적해 본다**(`code-review/severity`). 최신 회차가 깨끗해도 이전 회차에 미해결이 남아 있으면 알린다.

  ```
  ⚠ 미해결 critical N건 — 6.review/00(1건) · 6.review/01(1건)
    그냥 커밋할까요?
  ```

## 조합 검증

이 브랜치가 건드린 유닛이 둘 이상인데 조합 검증 결과가 없거나 마지막 커밋보다 오래됐나. **머지는 사람이 하니 여기가 마지막으로 알릴 자리다.**

```
⚠ 이 브랜치에 유닛 3개 — 조합 검증을 안 돌렸습니다.
  유닛별로는 통과했지만 합쳐서 돌아가는지는 아직 모릅니다.
  /flow:verify branch 를 먼저 돌릴까요? (그냥 커밋해도 됩니다)
```

- **유닛이 하나면 알리지 않는다** — 조합할 것이 없다.
- **필요 없다고 답하면 다시 묻지 않는다.** 혼자 하는 프로젝트는 브랜치 범위와 프로젝트 범위의 시점이 같다. 그 답을 `CLAUDE.md` 의 Git 규약에 한 줄로 남긴다.

## 계약이 변경에 들었으면 범위를 읽어 알린다

계약 범위가 `서비스 간`·`외부 제공` 이면 **이 repo 밖의 호출부를 우리가 확인할 수 없다**(`code-graph/service-boundary`).

- 영향 받을 구성 요소를 보여주고 **사람에게 넘긴다.** 차단하지 않는다.
- **확인할 수 없는 것을 확인했다고 적지 않는다.**
