# /flow:verify — 테스트 실행

`unit`·`branch`·`project` 범위가 읽는 조각이다. 케이스 규약은 `testing/case-source`, 조합 매트릭스와 `모아 온 미검증` 은 `testing/integration`, 실행 판정은 `testing/run` 이 정본이다. **여기 다시 적지 않는다.**

## 범위마다 어디에 남기나

| 범위 | 무엇을 돌리나 | 결과 위치 |
|:--|:--|:--|
| `unit` | task 1:1 단위 테스트 | `{유닛}/5.verify/NN.md` — task 번호와 1:1 |
| `branch {이름}` | 그 브랜치 유닛들의 조합 | `doc/03.integration/00.branch/{브랜치}/` |
| `project` | 전체 통합(E2E) | `doc/03.integration/01.project/` |

**브랜치 이름에 `/` 가 들어가면 `-` 로 바꾼다** — `feature/login` 은 `00.branch/feature-login/` 이다. 폴더가 한 단 더 깊어지지 않게 한다.

- 이름을 안 주면 `git branch --show-current` 를 쓴다. 커밋 규약과 무관하다 — 현재 브랜치가 답이다.
- **`main`·`master` 에서 `branch` 범위를 부르면 되묻는다** — 머지 전 조합을 보는 것이라 기본 브랜치에서는 뜻이 없다. `project` 를 뜻한 게 아닌지 확인한다.

## `project` 는 언제 도나

아무 때나 돌리면 리포트가 쓸모없다.

| 상황 | |
|:--|:--|
| **돌릴 때** | 계획한 유닛을 **전부 만든 뒤** · 릴리스 전 |
| **안 돌릴 때** | 일부만 만든 상태 — **대부분이 실패·누락으로 나와** 무엇이 진짜 문제인지 안 보인다 |
| 미완성이 있으면 | **그 목록을 먼저 보여주고 확인받는다.** 그래도 돌리겠다면 `미완성 N개 제외` 를 결과에 적는다 |

## 시나리오 확보

- `unit` — task 의 완료 기준을 매핑한다. 명세와 결과는 한 파일이다.
- `branch`·`project` — **조합 매트릭스 안에서만** 케이스를 만든다. 매트릭스가 없으면 요구·계약에서 축과 값을 뽑아 **제안하고 승인받는다** — 승인 전에는 돌리지 않는다(`testing/integration`).
- **앞 범위에서 `미검증` 으로 남은 업무 규칙을 먼저 모은다.** 새로 지어내기 전에 남은 것을 닫는 것이 먼저다. 닫았든 못 닫았든 `모아 온 미검증` 에 적는다 — 조용히 빼지 않는다.

## 실행과 기록

- 실행은 `verifier` 가 격리해서 한다. **추론으로 통과를 선언하지 않는다.**
- 화면이 있는 테스트는 브라우저를 실제로 띄운다. 모드는 `workflow.config.json` 의 `test.browser` 가 정하고, 설정된 도구가 없으면 **멈추고 설치를 안내한다** — 건너뛰고 통과로 처리하지 않는다.
- 실패는 *입력 → 기대 → 실제* 와 아티팩트 경로를 함께 남긴다. **`결함` 절에 재현·증거·처리 상태까지** 적는다 — 고치는 것은 `/flow:build` 다.
- 결과는 그 위치의 문서에 **날짜와 함께 in-place 로** 적는다. 회차를 덮지 않는다.
- **레거시면 커버리지 대상이 갈린다** — `확정` 요구만 센다. 역추출 요구는 따로 센다(`traceability/coverage`).
