# /flow:review — 코드 리뷰

층을 쌓아 잡는다. **무엇이 무엇을 잡고 없으면 어떻게 되나는 `code-review/layers` 가 정본이고, 등급은 `code-review/severity` 가 정본이다.** 여기 옮겨 적지 않는다.

## 층은 reviewer 가 돌린다

- **메인 세션이 코드를 훑어 등급을 매기지 않는다.** 정적분석·취약점 도구를 **Bash 로 실제로 돌리는** 쪽이 근거를 갖는다.
- `reviewer` 는 발견만 돌려준다 — 파일:라인 · 출처(어느 층·어느 룰) · 재현 조건. **고치지 않는다.**
- 교차 파일 영향은 `code-graph/query` 로 좁힌다. 그래프가 **서비스 간 호출을 못 잡는다** — 그때는 계약 범위로 대신 본다(`code-graph/service-boundary`).
- **과거 리뷰를 먼저 본다.** 이미 지적됐다가 정리된 것을 또 올리지 않는다. 최소한 그 유닛의 기존 `6.review/` 를 읽는다.
- 회귀 테스트를 다시 돌려야 하면 `testing/run` 을 따른다 — 여기서 통과를 추론하지 않는다.

## 점검 카테고리

층이 낸 것을 이 틀로 정리한다. **여러 층이 같은 것을 짚으면 한 줄로 합치고 출처를 둘 다 적는다** — 신뢰도가 높다는 뜻이다.

- **계약 정합성** — 계약의 엔드포인트·DTO·에러코드가 실제 코드와 맞나.
  - **타입·필드는 `contract-gate` 가 컴파일로 본다** — 여기서 눈으로 다시 대조하지 않는다.
  - **엔드포인트·에러코드는 눈으로 본다** — 계약에만 있는 것(구현 누락)·코드에만 있는 것(계약 없는 API).
- **설계 충실도** — 완료 기준이 구현됐나 · 이탈이 task `History` 에 적혔나.
- **보안** — 두 갈래로 가른다.
  - **적힌 위험**: 문서·코드에 드러난 것 — 입력 검증 · 주입 · 민감정보 로깅 · 권한 누락.
  - **안 적힌 위험**: 문서에 없지만 **아는 사람이 보면 보이는 것.** 예: 응답 차이로 계정 존재가 새어나감 · 재발송 횟수 제한이 없음. **근거를 함께 적는다** — 근거 없는 추측은 리포트로만.
- **아키텍처** — 계층 책임 · 트랜잭션 경계 · 의존 방향.
- **회귀 표면** — task `History` 의 회귀·미검증 목록이 처리·테스트됐나.
- **우리 규약** — `code-review/checklist`.

**설계 문서가 없으면** `계약 정합성`·`설계 충실도` 를 건너뛰고 나머지로 돈다. 건너뛴 것을 리포트에 적는다.

## 계약이 유닛마다 self-contained 라서 못 잡는 것

`contract-gate` 는 파일별로 컴파일한다. **같은 도메인의 계약 파일들을 나란히 놓고 봐야** 아래가 보인다.

| 무엇 | 예 | 어떻게 적나 |
|:--|:--|:--|
| **같은 이름 타입이 다르게 정의** | 한 유닛의 `User.id` 는 `number`, 다른 유닛은 `string` | critical 이 아니다 — 리포트 |
| **같은 엔드포인트를 두 유닛이 정의** | 둘 다 같은 경로를 잡는다 | **유닛 경계 문제다** — 유닛 분할을 다시 보라고 적는다 |
