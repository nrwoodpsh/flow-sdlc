# /flow:build — 단위 검증

`/flow:build` 의 구현↔검증 루프가 읽는 조각이다. v1 `verify unit` 이 하던 일이 여기로 왔다.
**실행하지 않은 것은 검증이 아니다** — 판정 규약은 `testing/run`, 케이스와 기대값의 출처는 `testing/case-source` 가 정본이다.

## 테스트 먼저

로직·계산·분기는 task `Verification` 기준을 **실패하는 테스트로 먼저** 만든다. 단순 배선·설정·화면 문구는 생략할 수 있다.

- **구현을 본 뒤에 기대값을 적지 않는다** — 역산이 섞인다(`testing/case-source`).
- 기대값의 출처가 없으면 케이스를 지어내지 않고 `확인 필요` 로 남긴다.

## 어디에 무엇을 두나

| 무엇 | 어디 |
|:--|:--|
| **실행되는 테스트 코드** | 소스 트리 (프로젝트가 정한 테스트 경로 — `doc/` 아님) |
| **명세와 결과** | `{유닛}/5.verify/NN.md` — **task 번호·이름과 1:1** |

- 번호가 어긋나면 스파인이 깨진다. `2.task/01` 의 검증은 `5.verify/01` 이다.
- 같은 task 를 다시 돌리면 **덮지 않고 in-place 로 결과에 날짜를 더한다.**
- **build 루프가 돌린 것도 반드시 `5.verify/` 에 남긴다.** 안 남기면 돌렸는데 기록이 없어 `/flow:verify` 의 커버리지 감사가 gap 으로 잡는다.

## 실행은 verifier 가 격리해서 한다

- 구현한 쪽이 자기 테스트의 통과를 선언하지 않는다. `verifier` 가 돌려 **Exit code** 로 판정한다.
- 실패하면 **원인이 코드인지 환경인지 먼저 가른다**(`testing/run`). 환경이면 3회 루프에 넣지 않는다.
- 실패 케이스는 *입력 → 기대 → 실제* 로 적고, 아티팩트(스크린샷·로그) 경로를 함께 남긴다.

**화면이 있는 테스트는 브라우저를 실제로 띄워 클릭한다.**

- 모드는 `workflow.config.json` 의 `test.browser` 가 정한다. **이 커맨드가 도구를 고르지 않는다.**
- 설정된 도구가 없으면 **멈추고 설치를 안내한다** — 화면 테스트를 건너뛰고 통과로 처리하지 않는다.
- 창을 띄운다(headed). 사람이 무슨 일이 일어나는지 볼 수 있어야 한다.
- 대화를 멈추는 조작(모달·확인창)을 어떻게 다루나는 `testing` 의 경계가 정본이다.

**LLM 을 부르는 기능이면 `testing/llm-cost` 를 읽는다**(그 기능일 때만 싣는 조건부 조각이다). 1회 돌려 판정하지 않고, 호출 상한을 넘으면 멈추고 리포트한다 — 승인 없이 반복 호출하지 않는다.

## 못 닫은 것을 남긴다

- 이 범위에서 못 닫은 업무 규칙은 **`미검증` 으로 범위를 적어 남긴다** — 조용히 빼지 않는다. 어느 범위가 받는지는 규칙 레벨이 정한다(`testing/case-source`).
- **`미검증` 을 지워 통과로 만들지 않는다.** 다음 범위가 이 목록을 모아 닫는다.
