# /flow:sync — 동기화

코드 ↔ 문서를 동기화하는 **유일한 퇴장구**다.
어느 진입점에서 왔든 커밋 전에 여기를 통과해 드리프트를 막는다. **커밋하지 않는다**(→ `/flow:commit`).

## 연결

- **에이전트**: `explorer` (diff가 크거나 유닛이 여럿일 때 — 원문을 메인으로 끌어오지 않는다)
- **스킬**: `plain-writing` · `contract-gate`(계약 갱신 시) · `traceability`(태그로 색인 계산) · `doc-verify`(갱신한 문서 점검) · `default-reference`
  > 드리프트 **판정**은 `/flow:commit`이 한다(`drift-check`). 여기는 **갱신하는 쪽**이다 — 짝을 이루지만 이 커맨드가 그 스킬을 쓰지는 않는다.
- **템플릿**: `07.summary` · `08.adr`(결정이 나왔을 때)
- **도구**: 없음 — 로컬 `git`으로 충분하다. PR 초안은 텍스트만 만들고 **올리지 않는다**

## 입력 (`$ARGUMENTS`)

| 인자 | 동작 |
|:--|:--|
| (비움) | `git diff` 변경을 도메인별 자동 분류 |
| `도메인` | 그 도메인 변경만 동기화 |

## 절차

**1. Diff 수집·분류** — BE/FE/DB/설정별 분류. 비었으면 "동기화 대상 없음" 후 종료.

- **유닛을 넘으면 `explorer`에 위임**한다(`default-reference` 위임 판정) — 무엇이 어느 유닛에 속하는지는 **결론만** 필요하다. 큰 diff를 메인에서 통째로 읽지 않는다.

**2. 설계 문서 갱신** (`doc/01.work/`) — 의도된 변경만 반영, 미설명 불일치는 정정 말고 리포트

- **`/flow:build`의 Deviation 로그를 먼저 읽는다** — task History의 이탈이 "무엇이·왜 벗어났나"의 1차 입력
- **의도된 변경**: 계약·`2.task`를 코드 기준으로 갱신 + History에 사유. 계약은 `contract-gate` 통과
- **설명 안 되는 코드↔계약 불일치**(버그 의심): 덮어쓰지 말고 **불일치 리포트만** (나쁜 구현을 SSOT로 세탁 금지)
- 프로젝트 수준 결정·정책 변경 → `doc/02.decisions/` ADR (템플릿 `08.adr` · README 색인)

**DB 변경이 분류에 있으면 `00.ref/02.db-schema/`를 맞춘다.** 거기가 **지금 상태의 정본**이다.

- **`/flow:build` 절차 3-1이 이미 갱신했으면 확인만** 한다. 안 됐으면 여기서 맞춘다 — 스키마와 문서가 어긋나면 다음 세션이 **없는 컬럼을 믿는다.**
- **드리프트 판정이 이걸 못 잡는다**(`drift-check`) — `doc/` 아래라 문서로 취급된다. 퇴장구인 여기와 `/flow:commit`이 마지막 확인이다.
- **실행문을 `1.design.md`에 옮기지 않는다** — 설계엔 구조와 이유만 있다.

**3. 요약 생성** — `{unit}/7.summary/NN.내용.날짜.md` (유닛 회차 · `NN.내용.YYYYMMDD.md`)

- 개요(유닛·날짜·브랜치) / 변경(BE·FE·DB) / API 변경 / 특이사항(설계 대비 변경·제약·후속)
- 언어는 `workflow.config`의 `language`(기본 한국어). 문장은 `plain-writing`

**4. README 색인 갱신** — 영역 인덱스(셋업 때 생성됨)를 git 분석으로 **채우고**, 유닛 README는 유닛 생기면 생성 (라벨 README 금지)

- **`01.work/README`(상단)** — **git 분석**으로 브랜치→유닛을 묶어 링크. 한 브랜치가 여러 도메인 유닛을 낳으면 그 아래 함께(교차 도메인도 드러남).
- **work-unit `README`** — 그 유닛 폴더 목차. 유닛이 생기면 만든다. (담당자 1명 소유 → 충돌 안전) 골격은 이 넷:

  ```markdown
  # {도메인}/{NN.유닛} — {한 줄}
  요구 USER-LOGIN-1,2 · 상태 {설계|명세|구현중|검증됨|정지(사유)} · 브랜치 {이름}

  | 단계 | 파일 |
  |:--|:--|
  | 0.requirement | [링크] |
  | 2.task | 전부 링크 (00.… 01.…) |
  | 5·6·7 | 회차 전부 링크 |
  ```

  **`2.task`~`7.summary`는 폴더 안 파일을 전부 링크**한다 — `5.verify`·`6.review`·`7.summary`는 회차가 쌓인다.
- **`02.decisions`·`03.integration`·`04.ops`의 `README`** — 목록 갱신. 없으면 만든다.
- **도메인 요구 파일**(`00.ref/01.domain/{도메인}.md`) — **`하위 기능` 절만** 갱신한다. 요구·경계·용어는 손대지 않는다(`/flow:prd`·`/flow:design`의 자리). 목록은 `traceability`의 태그를 grep해 계산한다.
- **안 만드는 곳**: 도메인 폴더(상단이 대신)·`00.ref` 하위·단계 폴더(`2.task`~`7.summary`). "이 폴더는 X" 라벨 README 금지 — `doc/README`가 대신.
- 규칙 정본: `doc/README.md`의 "README 체계" (프로젝트 로컬).

**5. 갱신한 문서 점검** — `doc-verify`로 이번에 손댄 문서만 템플릿과 대조한다.

- 퇴장구이므로 여기서 한 번 걸러야 한다. **빠진 절·빈 껍데기·남은 자리표시자**를 리포트에 함께 낸다.
- **고치지 않는다.** 지적만 하고 판단은 사람이 한다.

**색인이 머지 충돌하면 손으로 풀지 않는다.** 계산된 것이라 다시 돌리면 맞는다.

| 충돌하는 것 | 왜 | 어떻게 |
|:--|:--|:--|
| `01.work/README` (상단) | git 분석으로 채운다 — 둘 다 고친다 | **한쪽을 취하고 `/flow:sync`를 다시 돈다** |
| `02.decisions/README` | ADR 색인 | 같음 |
| 도메인 `하위 기능` | 태그 grep으로 계산 | 같음 |
| 유닛 `README` | **담당자 1명 소유라 안 부딪힌다** | — |

```
git checkout --ours doc/01.work/README.md   (또는 --theirs — 어느 쪽이든)
/flow:sync                                   → 다시 계산해 덮는다
```

- **내용을 섞어 풀지 않는다.** 손으로 합치면 계산 결과와 어긋나 다음 `sync`가 또 바꾼다.
- **사람이 쓴 문서는 다르다** — 요구·설계·task·ADR 본문은 **정상적으로 머지**한다. 색인만 재생성 대상이다.
- **어느 것이 색인인가**: 위 표의 넷 + 영역 인덱스(`03.integration`·`04.ops`). 그 밖은 사람 소유다.

**ID 중복도 여기서 본다** (`traceability`). 머지 전 마지막 관문이다.

- 요구 파일을 grep해 **같은 ID가 두 번 나오는지** 확인한다. `SYS-*`가 주로 부딪힌다 — 여럿이 동시에 발급하면 같은 번호가 나온다.
- 중복이면 **리포트하고 멈춘다.** 재발급은 요구 표와 **그 ID를 가리키는 태그를 전부 함께** 고쳐야 하므로 임의로 하지 않는다.

**6. PR 초안 제시** (선택 — 브랜치 작업일 때)

`7.summary/`에 이미 있는 내용을 모아 **텍스트만 만든다. 올리지 않는다.**

```
PR 초안 (복사해 쓰세요)
  제목: [USER-LOGIN] 이메일 로그인 구현
  본문: 요구 USER-LOGIN-1,2 / 변경 BE·FE / 테스트 12건 통과 / 리뷰 critical 0
  명령: gh pr create --title "…" --body-file -
```

- **새 내용을 지어내지 않는다** — 요약·검증·리뷰 결과에 있는 것만.
- **`gh` 명령을 실행하지 않는다.** 제시만 하고 사람이 친다.

**7. 리포트 후 종료** — **커밋하지 않는다**(→ `/flow:commit`).

## 가드레일

- **커밋·push 금지.** 문서 동기화까지만.
- 코드↔계약 불일치는 **리포트만**, 자동 정정 금지.
- 설계 문서 부재 시 경고 후 요약본만 생성하고 종료.
- **도메인 파일의 `하위 기능` 절 밖을 건드리지 않는다** — 요구는 `/flow:prd`, 경계·용어는 `/flow:design`의 자리다.
- **색인을 손으로 채우지 않는다** — git과 태그에서 계산한다.
- **색인 머지 충돌을 손으로 풀지 않는다** — 한쪽을 취하고 다시 돈다(절차 4).
- **유닛 상태값은 `traceability`만 쓴다.** 멈춘 유닛을 `구현중`으로 적지 않는다 — `정지(사유)`다.
- **PR을 만들지 않는다.** 초안 텍스트만 제시하고 `gh`·GitHub MCP로 올리는 것은 사람이 한다.

> **여기가 퇴장구다.** 이걸 건너뛰면 두 곳에서 걸린다 — `/flow:commit`이 묻고(`drift-check`), **git 훅이 커밋을 막는다**(`pre-commit`). 둘 다 같은 규칙을 본다.
