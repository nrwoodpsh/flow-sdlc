# /flow:next — 다음 차례 · 이어 돌리기

**어디까지 됐는지 파일에서 계산**해 다음 커맨드를 제시하고, 승인하면 **그 뒤를 이어서 돌린다.**
커맨드를 이미 알면 쓸 필요 없다 — 바로 그 커맨드를 부르면 된다.

> 이어 돌리기가 자동화하는 것은 **국면 사이의 호출**이지 게이트가 아니다.
> 손으로 하나씩 부르든 여기서 이어 돌리든 **같은 게이트를 지난다.**

## 연결

| 싣는 것 | 무엇 |
|:--|:--|
| 스킬 | `traceability`·`ops-doc`·`code-review` |
| 조각 | `traceability/level`·`traceability/unit-state`·`traceability/revert-scope`·`ops-doc/safety`·`code-review/severity` |

## 진입 조건

정본은 `${CLAUDE_PLUGIN_ROOT}/flow.topology.json` 의 `commands.next.entry` 다. **여기서는 선언만 한다.**

| 등급 | 조건 | 누가 판정 |
|:--|:--|:--|
| 기계 | `workflow.config.json` 이 있다 | 훅 — 파일 존재 |
| 약속 | 운영 장애·SOP 는 완화 우선이고 `사람만` 단계를 실행하지 않는다 | 아무도 — 규칙 정본은 `ops-doc` 이다 |

**내용 조건이 없다.** 대신 이어 돌릴 때는 **전환마다 다음 커맨드의 내용 조건을 `gatekeeper` 에게 넘긴다**(아래 `이어서 돌린다`).

## 입력 (`$ARGUMENTS`)

| 인자 | 동작 |
|:--|:--|
| (비움) | 진행 중인 유닛을 찾아 상태를 계산하고 다음 차례를 제시 |
| 자유 문장 | 하고 싶은 일 (예: `로그인이 자꾸 401 나는데 고쳐줘`) |
| `{도메인}/{NN.유닛}` | 그 유닛의 상태만 계산 |
| `이어서` | 제시한 다음 커맨드부터 정지 조건까지 이어 돌린다 |
| `REFERENCE @파일` | 기획서·로그·화면 |

## 절차

### 상태를 파일에서 계산한다

**README 의 `상태` 를 믿지 않는다.** 수렴을 안 돌리고 멈췄으면 낡았다 — **파일이 정본이다.**
유닛 상태값과 재개 지점 계산은 `traceability` 의 `unit-state` 조각이 정본이다.

```
[/flow:next] user/00.login — 파일에서 계산

  0.requirement ✅   1.design ✅   3.contract ✅
  2.task/   00.login-api  01.session  02.lockout
  4.build/  00.login-api  01.session              ← 02 미착수
  5.verify/ 00.login-api                          ← 01 미검증

  계산한 상태: 구현중        README 에 적힌 값: 명세  ← 낡았다
```

- **계산값이 README 와 다르면 알린다.** 수렴을 권하되 **여기서 고치지 않는다.**
- **앞선 단계를 먼저 닫는 쪽을 권한다** — 미검증을 두고 다음 task 를 구현하면 실패가 쌓인다.
- 오래된 맥락은 문서에 있다 — task 의 이력·미해결 리뷰·`확인 필요` 절을 함께 읽어 보여준다.

### 갈 곳을 정한다

- **위상 정본은 `${CLAUDE_PLUGIN_ROOT}/flow.topology.json` 이다.** 각 커맨드의 `after`·`next` 를 읽어 제시한다 — **체인표를 여기 옮겨 적지 않는다.** 옮겨 적으면 커맨드를 하나 더할 때 맞출 곳이 늘어난다.
- 레벨 판별은 `traceability` 다. 어느 레벨이냐에 따라 갈 곳과 착지가 함께 정해진다.
- 프로젝트가 세팅돼 있지 않으면(설정 파일이 없으면) 무엇을 물었든 **`/flow:setup` 부터** 안내한다.
- **두 곳 이상에 걸치면 후보를 나열하고 고르게 한다.** 임의로 정하지 않는다.
- 동작이 안 바뀌는 일(오타·문구)이면 **"flow 밖에서 그냥 고치세요"** 라고 답하고 끝낸다.
- **운영 장애·적어둔 절차 실행이면 `ops-doc` 의 `safety` 조각을 먼저 읽고 그 규칙을 따른다.** 완화 순서와 `사람만` 단계 규칙을 **여기 복제하지 않는다** — 정본이 둘이 되면 한쪽만 고쳐진다.

### 정리하고 승인받는다

```
[/flow:next] 작업: {한 줄 요약} · 유형: {신규|버그|불확실|레거시|점검|운영}
             갈 곳: {/flow:xxx 인자}
             근거: {왜 이 커맨드인지 한 줄}
             갈림길: {없음 | 물어서 받은 답}
             이어 돌리기: {안 함 | 어디까지 · 정지 조건}
             → 이대로 할까요?  [실행 / 고치기 / 취소]
```

- **갈림길이 남아 있으면 승인을 받지 않는다.** 답에 따라 갈 커맨드가 바뀌는 것만 여기서 묻는다.
- **준비물은 묻지 않는다** — 목적·완료 기준·스택 같은 것은 갈 커맨드가 묻는다. 여기서 물으면 같은 답을 두 번 하게 된다.

### 이어서 돌린다 *(`이어서` 일 때만)*

**전환마다 게이트를 지난다. 작업한 쪽이 자기 일을 판정하지 않는다.**

| 등급 | 전환에서 누가 보나 |
|:--|:--|
| 기계 | 훅이 이미 본다 — 여기서 다시 판정하지 않는다 |
| 내용 | **`gatekeeper` 에이전트에 넘긴다** — 다음 커맨드의 `entry.content` 항목을 그대로 준다 |
| 약속 | 아무도. 그래서 넘어갔다는 사실만 적는다 |

- **`gatekeeper` 를 부르지 않고 다음 국면으로 넘어가지 않는다.** 이름만 부르고 안 부르면 게이트가 없는 것이다.
- 게이트가 **실패하면 사유와 함께 직전 국면을 다시 실행**한다. 재실행할 때 **실패 사유를 함께 넘긴다** — 같은 실수를 반복하지 않게.
- **재시도 상한은 대상 하나당 3회다.** 전환마다 3회가 아니다 — 구현 커맨드가 이미 내부 루프를 갖고 있어 곱해지면 비용이 몇 배로 뛴다. 다음 대상으로 넘어가면 다시 3회다.
- 국면 내부 루프는 그 커맨드 정의를 따르며 이 상한과 별개로 세지 않는다.

**멈추는 자리**

| 조건 | 왜 |
|:--|:--|
| 재시도 소진 | 자기 수정이 안 통한다 |
| 국면 실패 | 실패 위에 다음 국면을 쌓지 않는다 |
| 대상 목록이 새로 정해질 때 | 도메인·유닛을 어떻게 나눌지는 판단이다 — 승인받는다 |
| 요구를 고쳐야 한다 | **요구가 바닥선이다.** 사람 결정이 입력이다 |
| **커밋 직전** | **반드시 멈춘다.** 커밋하지 않는다 |

### 멈춘 것을 재개할 때는 사유부터 본다

`정지` 상태에 그냥 다시 부르면 같은 지점에서 또 멈춘다.

| 사유 | 먼저 볼 것 | 그다음 |
|:--|:--|:--|
| `정지(빌드 3회)` | task 이력의 3회 시도 — 무엇을 시도했나 | 같은 방법을 또 쓰지 않는다. 설계를 의심할 근거면 설계로 돌아간다 |
| `정지(critical)` | 리뷰 산출의 **미해결 critical — 전 회차 누적**(`code-review` 의 `severity`) | 그것부터 고친다. 안 고치고 구현을 돌리면 리뷰에서 또 막힌다 |
| `정지(요구)` | 요구의 `확인 필요` 절 · 외부 쿼터 `충돌` 표기 | **사람이 결정한다.** 결정 없이 진행하지 않는다 |
| `정지(되돌아가기 2회)` | 무엇을 두 번 고쳤나 | 설계를 사람이 본다. 다시 자동으로 돌리지 않는다 |

- **재시도 횟수는 재개할 때 초기화된다** — 사람이 개입했으니 3회를 다시 준다. 다만 **같은 방법을 반복하면 그 사실을 적는다.**
- **critical 차단은 룰 기반 발견만이다.** 등급 규칙 정본은 `code-review` 의 `severity` 조각이다.

### 되돌아갈 때는 범위를 태그로 계산한다

무엇을 다시 도는지는 **`traceability` 의 `revert-scope` 조각이 정본이다.** 되돌아가기 전에 그것을 읽는다.

- **태그에 걸리지 않는 것을 임의로 다시 돌리지 않는다.** 범위를 넓히면 끝이 없다.
- 되돌아가 고친 것은 그 문서 이력에 **왜 고쳤는지** 남긴다 — 조용히 바뀌면 안 된다.

## 가드레일

- **승인 없이 이어 돌리지 않는다.** 정리 → 확인 → 실행 순서를 건너뛰지 않는다.
- **여기서 산출물을 만들지 않는다** — 요구·설계·코드는 넘겨받은 커맨드가 쓴다.
- **게이트를 건너뛰거나 기준을 낮추지 않는다.** 통과 못 하면 진행하지 않는다.
- **자동 커밋·push·merge 금지.** 커밋 직전에 멈추고 사람에게 넘긴다.
- **요구를 고쳐서 통과시키지 않는다.** 설계까지만 되돌아간다.
- **운영 장애의 완화를 우리가 실행하지 않는다.** 규칙은 `ops-doc` 의 `safety` 가 정본이다 — 읽고 따른다.
- **커맨드를 지어내지 않는다.** 위상 정본에 있는 것만 부른다.
- 되돌아온 것을 다시 보내는 것은 한 번까지다. 왕복하지 않는다.
