# /flow:setup — 프로젝트 초기 세팅

프로젝트 고유층(`CLAUDE.md`·`workflow.config.json`·`doc/`)을 만들고 **게이트를 심는다.**
골격은 복사, 추론값은 자동, **결정·정책은 질문.**

## 연결

| 싣는 것 | 무엇 |
|:--|:--|
| 스킬 | `contract-gate`·`plain-writing` |
| 조각 | `contract-gate/config` |

넓게 훑을 일이 생기면 `explorer` 에 위임한다 — 코드 원문을 메인 컨텍스트로 끌어오지 않는다.

## 진입 조건

정본은 `${CLAUDE_PLUGIN_ROOT}/flow.topology.json` 의 `commands.setup.entry` 다. **여기서는 선언만 한다.**

| 등급 | 조건 | 누가 판정 |
|:--|:--|:--|
| 약속 | 이미 깔린 프로젝트에 두 번 돌려도 덮어쓰지 않는다 | 아무도 — 본문이 적어 둔 것뿐이다 |

**내용 조건이 없어 `gatekeeper` 를 부르지 않는다.** 이 커맨드는 게이트를 통과하는 쪽이 아니라 **게이트를 심는 쪽**이다.

## 입력 (`$ARGUMENTS`)

| 인자 | 동작 |
|:--|:--|
| (비움) | 대화형. 빈·신규면 원형 메뉴, 진행중이면 업데이트 모드 |
| `list` | 원형 목록만 출력하고 멈춘다 |
| 원형키 | 그 원형으로 바로 복제 |
| git URL | 그 repo 를 커스텀 원형으로 복제 |

**넷 중 하나만 받는다.** 문장으로 설명하는 입력은 받지 않는다 — 필요한 값은 감지하거나 목록에서 고른다.

## 절차

### 대상 선언

파일을 만들기 전에 무엇을 만드는지 먼저 보여준다. 이 커맨드는 파일 생성·repo 복제·도구 설치를 한다 — 되돌리기 번거롭다.

```
[/flow:setup] 대상: {경로} · 상태: {빈 프로젝트 | 기존 코드 있음 | 업데이트 모드}
              원형: {키 또는 "없음"}   스택: {감지값 또는 "질문 필요"}
              만들 것: CLAUDE.md · .claude/ · workflow.config.json · doc/ 골격 · 훅
              건드리지 않을 것: 기존 코드 · 이미 있는 파일
              → 진행할까요?
```

### 골격 — 지어내지 않고 복사한다

원본은 `${CLAUDE_PLUGIN_ROOT}/project-template/` 다. 그대로 복사한 뒤 프로젝트 값(이름·스택)만 치환한다.
특히 **`doc/00.ref/03.templates/` 전체**를 빠짐없이 복사한다 — 이후 모든 산출물의 골격이자 `doc-verify` 의 채점 기준이다.

- **`.gitignore`·`.claude/settings.json` 은 덮지도 건너뛰지도 않는다 — 합친다.** 빠진 줄·키만 더한다.
  - `.gitignore` 에 `spike/*` 와 `.claude/` 예외(`!.claude/`·`.claude/*`·`!.claude/settings.json`·`!.claude/rules/`)를 확인한다. **전역 gitignore 가 `.claude/` 를 무시하는 기계가 많아** 예외가 없으면 설정과 규칙이 **에러 없이 조용히 미추적**된다. `git check-ignore -v .claude/settings.json` 으로 확인한다.
  - `.claude/settings.json` 은 `enabledPlugins` 에 flow 만 더한다. 다른 키는 손대지 않는다.
- 템플릿 버전은 **`workflow.config.json` 의 `templates` 절에 적는다**(`flowVersion`·`copiedAt`·`localEdits`). 별도 `VERSION` 파일을 만들지 않는다 — 자체 형식을 하나 더 두면 읽는 곳도 하나 더 늘어난다.
- 빈 폴더에는 원본의 `.gitkeep` 이 함께 온다. 내용이 생기면 지워도 된다.
- **업데이트 모드**: 빈 항목만 제안하고 덮지 않는다. 원형은 복제하지 않는다. `templates.flowVersion` 이 플러그인 버전과 다르면 동기화를 제안한다 — 절차는 `${CLAUDE_PLUGIN_ROOT}/presets/template-sync.md` 다(새 프로젝트에서는 읽지 않는다).

### repo 구성 확인 *(배포 단위가 여럿일 때만)*

코드는 repo 가 갈려도 **`doc/` 는 하나다.** 흩어지면 요구 ID 추적이 repo 경계를 못 넘는다.

```
배포 단위가 여럿으로 보입니다. repo 구성이 어느 쪽입니까?
  1. 모노repo — repo 하나에 서비스 여럿        → doc/ 는 이 repo 에
  2. 서비스마다 repo                          → doc/ 를 어디에 둘까요?
       a) 지금 이 repo (주 repo)   b) 별도 doc repo
```

- 2 면 위치를 확정하고 **repo 를 넘으면 못 하는 것을 알린다** — 드리프트가 repo 경계를 못 보고, 코드 그래프가 서비스 간 호출을 못 따라간다.

### 스택 스캔 · 원형

- 지표를 읽는다 — `package.json`·`build.gradle`·`pyproject.toml`·`go.mod` …. 지표가 없으면 스택을 묻는다.
- 원형 카탈로그 정본은 `${CLAUDE_PLUGIN_ROOT}/presets/architectures/README.md` 다. **표를 그대로 보여주고 키로 고른다** — 목록을 여기 복제하지 않는다.
- 원형 복제는 **빈 프로젝트만**. 기존 코드가 있으면 목록만 참고로 보여준다.
- 복제는 `--depth 1` → `.git` 제거 → 이름 치환.

### 실행 키는 돌려 보고 적는다

`workflow.config.json` 의 실행 키가 스택과 안 맞으면 게이트가 **조용히 안 돌거나** 매번 실패한다.

| 키 | 무엇 | 안 맞으면 |
|:--|:--|:--|
| `contract.pathGlob` | 계약 파일 판정 | 계약이 검증 없이 지나간다 |
| `contract.gate` | 계약 검증 명령 | 게이트가 매번 실패한다 |
| `build.command` | 전체 빌드 | 전체 컴파일 오류가 커밋까지 안 잡힌다 |
| `test.command` | 테스트 실행 | 검증이 추론으로 바뀐다 |
| `test.browser` | 화면 테스트 도구 | 화면이 있으면 검증할 길이 없다 |

- **계약 판정을 경로로 하나 파일명으로 하나**, 오프라인에서 무엇이 달라지나는 `contract-gate` 의 `config` 조각이 정본이다. 여기서 다시 적지 않는다.
- `contract.gate`·`build.command`·`test.command` 는 **한 번 돌려 Exit 0 을 확인**한다. 못 돌리면 그 사실을 요약에 적는다.

### 강제력 — 무엇이 기계이고 무엇이 옵트인인가

**설치된 프로젝트에서 어느 층이 실제로 막는지 표로 보여준다.** 안 켠 층을 켜졌다고 적지 않는다.

| 층 | 종류 |
|:--|:--|
| `Write`·`Edit` 진입 게이트 · 위험 명령 가드 | 기계 — `Write`·`Edit` 는 못 우회한다. `Bash` 는 가드가 닿는 범위까지, MCP 파일 도구는 밖이다 |
| 커밋 전 드리프트 훅 | 기계 — 단 `--no-verify` 로 우회 가능하다 |
| CI 워크플로 | **옵트인** — 켜는 것은 프로젝트의 선택이다 |
| 커맨드 본문의 지시 | 약속 |

- CI 파일은 복사만 한다. **켜라고 권하되 켜졌다고 적지 않는다** — 안 켰으면 그 층이 없다고 요약에 적는다.

### 훅 설치

드리프트 훅은 `${CLAUDE_PLUGIN_ROOT}/git-hooks/drift-hook.sh` 를 **`pre-commit`** 으로 건다.
**`.githooks/` 에 두고 `core.hooksPath` 를 가리키는 것이 기본이다** — 파일이 커밋되어 clone 마다 다시 깔 필요가 없다.

| 프로젝트 상태 | 어떻게 |
|:--|:--|
| 훅을 안 쓴다 (대부분) | `.githooks/pre-commit` 에 복사 + `git config core.hooksPath .githooks` |
| `core.hooksPath` 가 이미 있다 (husky·lefthook) | **그 폴더에** 넣는다. 설정을 덮지 않는다 |
| 같은 이름 훅이 이미 있다 | **덮지 않는다.** 기존 파일 끝에 호출 한 줄을 더할지 묻는다 |

- **`core.hooksPath` 를 먼저 확인한다** — 값이 있는데 `.git/hooks/` 에 넣으면 실행되지 않는다. 확인 없이 "설치 완료" 로 보고하면 거짓말이 된다.
- **`git config` 는 커밋되지 않는다** — clone 한 사람은 파일이 있어도 설정이 없어 훅이 안 돈다. 세션 시작 훅이 그것을 알린다.

### 도구 제안 · 설치

정본은 `${CLAUDE_PLUGIN_ROOT}/presets/tools/README.md` 다. 스택을 보고 **골라 제시하고, 고른 것만 설치한다.**
**종류와 마커를 이름과 함께 보여준다** — 무엇이 자동이고 무엇이 사람 몫인지 미리 알아야 한다.

| 마커 | 무엇을 하나 |
|:--|:--|
| `[자동]` | 권한 승인 후 설치하고 결과를 보고한다. 실패하면 명령과 오류를 그대로 보여준다 |
| `[인증필요]` | 등록까지 하고 **인증 절차를 안내**한다 |
| `[사용자 설치]` | **명령·경로를 그대로 제시**한다. 실행은 사용자가 한다 |
| `[필수·택1]` | 하나도 안 고르면 다시 묻고, 끝내 안 고르면 **어느 커맨드가 멈추는지** 알린다 |

- **크리덴셜·OAuth·비밀값 입력은 사람만 한다.**
- **설치 명령을 지어내지 않는다.** 카탈로그에 없으면 벤더 문서를 안내한다 — 틀린 명령은 사용자 시간을 버린다.
- 카탈로그가 스택별 플러그인 목록을 다 들고 있지 않다. **없으면 없다고 한다.**

### 못 채운 것만 되묻기 · 요약

step Q&A 를 하지 않는다. 빈 프로젝트에서는 도메인·커밋 규약을 아직 모른다 — 물어도 답이 안 나온다.

| 언제 | 묻는다 |
|:--|:--|
| 스택 지표가 없다 | 무슨 언어·프레임워크입니까? |
| 테스트 명령을 못 찾았다 | 테스트는 어떻게 돌립니까? |
| 기존 코드가 있다 | 감지한 도메인 후보가 맞습니까? |

```
채운 것    스택 {감지값} · 테스트 {명령} · 원형 {키}
설치됨     {도구 목록}
남은 것    {사용자가 직접 할 것} — 위 안내 참고
비워둔 것  도메인 → /flow:prd domain · 커밋 규약 → /flow:commit
켜지 않은 층 {CI 등} → {없으면 어떻게 되는지}
```

## 가드레일

- **추론은 자동, 결정·정책은 질문.** 가드레일·도구 정책·도메인 경계·커밋 규약은 코드에 없다 — 추측 금지.
- **템플릿을 지어내지 않는다.** `${CLAUDE_PLUGIN_ROOT}/project-template/` 에서 복사한다. `03.templates/` 를 빠뜨리면 이후 산출물에 기준이 없어진다.
- 기존 코드를 수정하지 않는다. 원형 복제는 빈 프로젝트만.
- **설치했다고 거짓 보고하지 않는다.** `[사용자 설치]`·`[인증필요]` 는 남은 일로 명시한다.
- **옵트인을 기계라고 적지 않는다.** 안 켠 층은 없는 층이다.
- 실제 값을 덮어쓰지 않는다 — 있으면 확인 후 갱신한다.
- `/init` 과 다르다 — 여기는 flow 층 전체 세팅이다.
