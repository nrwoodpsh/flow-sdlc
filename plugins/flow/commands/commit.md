# /flow:commit — 커밋 (요청 시에만)

역할은 **여기까지**: 변경 목록 → 커밋 전 확인 → 브랜치 확인 → 메시지 → 커밋.
**push·merge 는 절대 하지 않는다** — 되돌릴 수 없는 것은 사람이 외부 툴로 한다. 가드도 그 명령을 막는다.

## 연결

정본은 `flow.topology.json` 의 `commands.commit` 다. **조각은 여기 적힌 것만 읽는다.**

| 무엇 | 이름 |
|:--|:--|
| 스킬 | `drift-check` · `code-review` · `code-graph` |
| 조각 | `drift-check/rule` · `code-review/severity` · `code-graph/service-boundary` |
| 에이전트 | 없다 — **메인 세션이 직접 한다.** git 상태 판단이라 위임할 것이 없다 |
| 절차 조각 | `${CLAUDE_PLUGIN_ROOT}/procedures/commit/pre-commit-checks.md` |

## 게이트

게이트 조건의 정본은 `flow.topology.json` 의 `commands.commit` 의 `entry`·`exit` 다. **이 커맨드가 스스로 판정하지 않는다.**

- **기계** — `no-drift`. `pre-commit` 훅이 소스만 바뀌고 문서가 안 온 상태를 막는다. **사람이 손으로 커밋할 때도 같은 훅이 돈다.**
  **단 조건이 있다 — `/flow:setup` 이 `core.hooksPath` 를 건 프로젝트에서만 돈다.**
  안 건 프로젝트에는 이 층이 아예 없다. `SessionStart` 의 `check-drift-hook.sh` 가 그 상태를 알린다.
- **내용** — 없다. `entry.content`·`exit.content` 가 둘 다 비어 있으니 **여기서 `gatekeeper` 를 부르지 않는다.** 부를 자리를 만들려면 `flow.topology.json` 에 먼저 적는다 — 커맨드 본문이 게이트를 발명하지 않는다.
- **약속** — 없다.

**훅이 막으면 거기서 멈춘다.** 이 자리에서 `git commit --no-verify` 를 붙이면 **자기 방어층을 끄는 것**이다. 붙이지 않는다 — 가드가 `--no-verify` 와 `core.hooksPath` 를 차단하고, 그게 정상이다.

| 막혔을 때 | 어떻게 |
|:--|:--|
| 드리프트가 맞다 | **`/flow:sync` 를 돌린다.** 문서를 맞추고 다시 커밋한다 |
| 드리프트가 아니다(오타·설정) | **사실을 알리고 멈춘다.** 넘길지는 사람이 자기 손으로 판단한다 — AI 가 방어층을 끄지 않는다 |

## 입력 (`$ARGUMENTS`)

| 인자 | 동작 |
|:--|:--|
| (비움) | `git status` 변경을 분류해 커밋을 준비한다 |
| 메시지 힌트 | 메시지 작성에 반영한다 |

## 절차

### 먼저 규약을 읽는다 — 커밋 전 확인을 시작하기 전에

**`## 연결` 의 표는 배선 선언이고 지시가 아니다.** 실측에서 이 커맨드가 세 회차 모두 선언한 조각 셋 중
**`drift-check/rule` 하나만, 그것도 한 회차에서만** 읽었다. 나머지는 표에만 있었다.

읽는다 — `${CLAUDE_PLUGIN_ROOT}` 아래 경로다.

| 무엇을 위해 | 조각 |
|:--|:--|
| **드리프트 판정** | `skills/drift-check/references/rule.md` |
| 리뷰 미해결을 어느 등급까지 막나 | `skills/code-review/references/severity.md` |
| 계약·서비스 경계를 건드렸나 | `skills/code-graph/references/service-boundary.md` |
| 절차 | `procedures/commit/pre-commit-checks.md` |

- **판정 규칙을 안 읽고 "확인했다"고 적지 않는다.** 커밋 전 확인 넷이 전부 이 조각들에 근거한다.

**변경 목록** — `git status` + `git diff --stat` 으로 분류해 제시한다.

**커밋 전 확인** — 넷을 본다(드리프트 · 스키마 문서 · 리뷰 · 조합 검증). 판정 규칙과 문형은 `${CLAUDE_PLUGIN_ROOT}/procedures/commit/pre-commit-checks.md`.

**규약 확보** — `CLAUDE.md` 의 Git 규약에 **브랜치·커밋 메시지 형식이 없으면 이번에 한 번 물어 적는다.** 세팅이 빈 프로젝트에서 못 채우고 비워 둔 자리다 — 처음 커밋할 때가 정할 시점이다.

- 사용자가 "아무거나" 라고 하면 기본값을 쓰고, **무엇을 기본값으로 정했는지 `CLAUDE.md` 에 적는다.** 다음부터 묻지 않는다.

**브랜치 확인** — **main·master 에 직접 커밋하지 않는다.**

- 기본 브랜치면 위 규약대로 새 브랜치를 만든다. **이름은 사용자에게 확인받는다.**
- 아니면 그대로 커밋한다.
- **브랜치를 새로 만들면 색인이 그 순간 낡는다.** `/flow:sync` 가 `doc/01.work/README` 에
  **브랜치 → 유닛**을 적는데, 그때는 아직 기본 브랜치였다. **여기서 문서를 고치지 않는다** —
  낡았다는 사실을 커밋 뒤 요약에 적고 `/flow:sync` 를 다시 돌리라고 알린다.
  색인은 계산된 캐시라 다시 돌리면 맞는다(`traceability` 의 `unit-state`).

**메시지 작성** — 규약대로. 힌트가 있으면 반영한다. **추측·과장을 넣지 않는다** — 실제 변경만이다.

**민감정보 점검** — **파일 이름**을 본다. 환경 파일·키 파일·운영 설정이 대상에 들었나.

- 걸리면 **중단하고 경고한다.** 임의로 지우거나 마스킹하지 않는다.
- **비밀키는 한 번 올라가면 이력에 남는다** — 여기가 마지막 관문이다.
- **코드 안에 박힌 값**은 `/flow:review` 가 본다. 우리 흐름은 `review → sync → commit` 이라 그 앞을 지난다.

**커밋 실행** — 목록과 메시지를 제시하고 `git commit` 한다. 범위가 모호하면 먼저 확인한다.

- **코드와 대응 문서를 같은 커밋에 담는다** — 따로 커밋하면 이력에 드리프트가 남는다.
- 끝나면 알린다: *커밋 완료. push·merge 는 외부 툴로.*

## 가드레일

- **자동 커밋 금지.** 이 커맨드가 명시적으로 불렸을 때만 커밋한다. 다른 커맨드는 커밋하지 않는다.
- **`--no-verify` 를 붙이지 않는다.** 어떤 답을 받았어도 붙이지 않는다 — 커맨드가 자기 방어층을 끄는 경로를 없앤다.
- **push·merge·rebase 를 실행하지 않는다.** 되돌릴 수 없는 것은 사람에게 넘긴다.
- **파괴적 git 을 실행하지 않는다** — 되돌리기·정리 계열 명령은 가드가 막고, 우회하려 하지 않는다.
- **기본 브랜치에 직접 커밋하지 않는다.** 브랜치 이름을 확인 없이 만들지 않는다.
- 범위가 불분명하면 **전체 add 를 하지 않는다** — 확인받는다.
