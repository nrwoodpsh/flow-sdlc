# /flow:commit — 커밋 (요청 시에만)

역할은 **여기까지**: 변경 목록 → 드리프트 확인 → 브랜치 확인 → 메시지 작성 → 커밋.
**push·merge는 절대 하지 않는다** — 사용자가 외부 툴로 수행.

## 연결

- **에이전트**: 없음 — **메인 세션이 직접** 한다 (git 상태 판단이라 위임할 게 없다)
- **스킬**: `drift-check` · `default-reference`
- **도구**: 없음 — 파일 이름 검사는 `git`으로 충분하다. 코드 안 값은 `/flow:review`가 본다
- **템플릿**: 없음 (문서를 만들지 않는다)

## 입력 (`$ARGUMENTS`)

| 인자 | 동작 |
|:--|:--|
| (비움) | `git status` 변경을 분류해 커밋 준비 |
| 메시지 힌트 | 메시지 작성에 반영 |

## 절차

**1. 변경 목록** — `git status` + `git diff --stat`로 분류해 제시.

**2. 드리프트 확인** (`drift-check`)

- 소스는 바뀌었는데 대응 **`doc/01.work/` 아래가 아무것도** 안 바뀌었으면 경고 → `/flow:sync` 먼저 돌릴지 질문 (`2.task`·`3.contract`·`5.verify`·`7.summary` 어느 것이든 인정)
- **소스 판정은 `drift-check`의 규칙을 따른다** — `drift.ignore` → `drift.sourceGlobs` → 기본값 순. git 훅·CI와 같은 규칙이다
- 오타·주석·설정이면 그대로 진행

**사용자가 "그냥 커밋"을 고르면 `git commit --no-verify`로 실행한다.**

`pre-commit` 훅이 **같은 드리프트를 보고 막기 때문**이다. 여기서 이미 묻고 답을 받았는데 훅이 또 막으면 사용자가 빠져나갈 길이 없다.

| 사용자 답 | 어떻게 |
|:--|:--|
| `/flow:sync` 먼저 | **멈춘다.** 커밋하지 않는다 |
| **그냥 커밋** | **`--no-verify`로 커밋한다** — 판단은 이미 받았다 |
| 드리프트 아님(오타·설정) | 같음 — `--no-verify` |

- **드리프트가 없으면 `--no-verify`를 쓰지 않는다.** 훅이 통과시킬 것이라 붙일 이유가 없다.
- **훅이 보는 것은 드리프트 하나뿐이다** — 넘겨도 다른 검사를 건너뛰지 않는다.

**마이그레이션이 포함되면 `02.db-schema` 갱신을 확인한다.** 훅·CI가 **못 잡는 자리**다 — `doc/00.ref/02.db-schema/`는 `doc/` 아래라 드리프트 판정에서 문서로 취급된다.

- 판정: 커밋 대상에 **스키마를 바꾸는 파일**(마이그레이션·DDL)이 있는데 `doc/00.ref/02.db-schema/` 변경이 **없다.**
- 경로는 프로젝트마다 다르다(`db/migration`·`prisma/migrations`·`alembic/versions`) — **글롭으로 판정하지 않고 변경 내용을 보고 판단**한다.

  ```
  ⚠ 마이그레이션이 있는데 doc/00.ref/02.db-schema/ 가 안 바뀌었습니다.
    거기가 지금 상태의 정본이라, 안 맞추면 다음 세션이 없는 컬럼을 믿습니다.
    지금 갱신할까요? (그냥 커밋해도 됩니다)
  ```

- **차단이 아니라 확인이다.** 스키마와 무관한 SQL(뷰 조회·데이터 보정)이면 그대로 진행한다.

**계약이 변경에 포함되면 범위를 읽어 알린다** (`drift-check`). `서비스 간`·`외부 제공`이면 **이 repo 밖의 호출부를 자동으로 확인할 수 없다** — 구성 요소 표를 보여주고 사람에게 넘긴다. 차단하지 않는다.

**3. 규약 확보** — `CLAUDE.md`의 `Git 규약`에 **브랜치·커밋 메시지가 없으면 이번에 한 번 물어 저장한다.**

`/flow:setup`이 빈 프로젝트에선 못 채우고 비워둔 자리다. 처음 커밋할 때가 정할 시점이다.

| 물을 것 | 질문 예시 (플레이스홀더) |
|:--|:--|
| 브랜치 이름 | `브랜치 이름 규칙이 있습니까? (예: feature/{이슈}-{요약} · fix/{요약})` |
| 커밋 메시지 | `커밋 메시지 형식은? (예: [#이슈] 동사로 시작 — 한 줄 요약)` |

- 답을 **`CLAUDE.md`의 `Git 규약`에 적는다** — 다음부터 묻지 않는다.
- 사용자가 "아무거나"라고 하면 기본값을 쓰고, **무엇을 기본값으로 정했는지 `CLAUDE.md`에 적는다.** 기본값: 브랜치 `feature/{요약}`·`fix/{요약}` / 메시지 `[타입] 한 줄 요약` + 본문.

**4. 브랜치 확인** (main 직접 커밋 금지)

- **현재 main이면** 위 규약대로 새 브랜치를 만든다. **이름은 사용자에게 확인받는다.**
- **비-main이면** 그대로 커밋.

**5. 메시지 작성** — 위 규약대로. 힌트가 있으면 반영.

**6. 민감정보 점검** — **파일 이름**을 본다. `.env`·`*.key`·`*-prod.*` 등이 커밋 대상에 있나.

- 걸리면 **중단·경고.** 임의로 지우거나 마스킹하지 않는다.
- **비밀키는 push되면 이력에 남는다** — 여기가 마지막 관문이다.

**코드 안에 박힌 값**은 `/flow:review`가 본다(`claude-security`). 우리 흐름은 `review → sync → commit`이라 커밋 전에 지난다.

- **이번 변경에 리뷰 기록이 없으면 알린다** — 대응 유닛의 `6.review/`가 비었거나 이번 변경보다 오래됐으면:

  ```
  ⚠ 리뷰를 안 지났습니다. 코드에 박힌 비밀값·취약점을 아직 안 봤습니다.
    /flow:review 를 먼저 돌릴까요? (그냥 커밋해도 됩니다)
  ```

- **미해결 critical은 전 회차를 누적해 본다** (`code-review`). 최신 회차가 깨끗해도 이전 회차에 미해결이 남아 있으면 알린다.

  ```
  ⚠ 미해결 critical N건 — 6.review/00(1건) · 6.review/01(1건)
    그냥 커밋할까요?
  ```

- **차단이 아니라 확인이다** — `drift-check`와 같은 방식. 판단은 사용자가 한다.

**이 브랜치의 유닛이 둘 이상이면 조합 검증을 알린다.** 머지하면 되돌리기 어렵고, **머지는 사람이 하니 여기가 마지막으로 알릴 자리**다.

- 판정 기준: `git diff main...HEAD`로 이번 브랜치가 건드린 유닛이 둘 이상이고, `doc/03.integration/00.branch/{브랜치}/`가 **비어 있거나 마지막 커밋보다 오래됐다.**

  ```
  ⚠ 이 브랜치에 유닛 3개 — 조합 검증(verify branch)을 안 돌렸습니다.
    유닛별로는 통과했지만 합쳐서 돌아가는지는 아직 모릅니다.
    /flow:verify branch 를 먼저 돌릴까요? (그냥 커밋해도 됩니다)
  ```

- **유닛이 하나면 알리지 않는다** — 조합할 것이 없다.
- **필요 없다고 답하면 다시 묻지 않는다** — 혼자 하는 프로젝트는 `verify project`와 시점이 같다. 그 답을 `CLAUDE.md`의 `Git 규약`에 한 줄로 남긴다.

**7. 커밋 실행** — 목록·메시지 제시 후 `git commit`. 범위 모호하면 먼저 확인. **코드와 대응 문서를 같은 커밋에** (따로 커밋하면 이력에 드리프트).

**8. 종료 안내** — "커밋 완료. push·merge는 외부 툴로." **push 안 함.**

## 가드레일

- **자동 커밋 금지.** 이 커맨드가 명시 호출됐을 때만. 다른 커맨드는 커밋 안 함.
- **main 직접 커밋 금지.** main이면 새 브랜치부터.
- **push·merge 금지.** `git push`·`merge`·`rebase` 실행 안 함.
- **파괴적 git 금지.** `reset --hard`·`clean -fd`·`push --force` 실행 안 함.
- **`--no-verify`는 드리프트를 물어 답을 받았을 때만.** 습관적으로 붙이지 않는다 — 훅이 도는 이유가 없어진다.
- 범위 불분명하면 임의 `git add -A` 금지 — 확인. 메시지에 추측·과장 금지.
- **브랜치 이름을 확인 없이 만들지 않는다.** 규약이 없으면 물어서 `CLAUDE.md`에 남긴다.
