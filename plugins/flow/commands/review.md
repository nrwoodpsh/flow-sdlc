# /flow:review — 리뷰

**코드**는 OCR(오픈 코드 리뷰) severity + CPG(코드 속성 그래프) 영향도로 점검한다. **문서**는 제 템플릿과 대조한다. **리포트만** 낸다.
필요할 때 끼워 넣는 오버레이 — 설계 없는 레거시에도 돌 수 있다.

## 연결

- **에이전트**: `reviewer`(OCR+CPG 실행, 발견만 반환) · `verifier`(critical·high 재확인) · `explorer`(`doc` 모드에서 문서 다수 대조)
- **스킬**: `code-review`(severity 게이트) · `code-graph`(교차 영향) · `code-audit`(일반 품질) · **`doc-verify`**(문서 채점) · `plain-writing`(발견·안 본 주제 문장) · `default-reference`
- **템플릿**: `06.review`
- **도구**: **OCR**(CLI — 룰 기반 검출, `[필수]`) · **ponytail**(플러그인 — 과설계 삭제 목록) · `claude-security`(플러그인 — 취약점 + 자체 반박) · **`codex`**(플러그인 — `deep`에서만, 유료·외부) · GitHub(MCP — 과거 PR 리뷰) · LSP·Joern(교차 영향). **없으면 그 층을 빼고 리포트에 적는다**

## 입력 (`$ARGUMENTS`)

| 인자 | 동작 |
|:--|:--|
| (비움) | **코드** — `git diff` 변경 파일 대상 (일반 단계) |
| `파일/도메인 경로` | **코드** — 그 범위만 점검 |
| **`deep`** | **코드** — 일반 + **codex가 설계 선택을 의심**한다. 유료·외부 전송 (아래 `설계 의심`) |
| **`doc`** | **문서** — 최근 작업 유닛의 산출 문서를 템플릿과 대조 (아래 `문서 리뷰`) |
| `doc {경로}` | 그 범위 문서만 — 유닛 · `00.ref/` · `02.decisions/` · `04.ops/` |

## 문서 리뷰 (`doc`)

`doc-verify`에 위임한다. 기준은 **각 문서의 템플릿**이고, 별도 체크리스트를 만들지 않는다.

```
[/flow:review doc] 대상: {유닛 경로 | 00.ref/ | 02.decisions/ | 04.ops/}
                   기준: 00.ref/03.templates/ (프로젝트가 고친 쪽이 기준)
                   기록: {유닛이면 6.review/ · 아니면 리포트만}
```

- **유닛을 넘으면 `explorer`에 위임**한다(`default-reference` 위임 판정) — 채점 결과는 **FAIL 목록**이라 결론만 받으면 된다.
- 리포트만 낸다. **문서를 고치지 않는다.**
- 계약(`3.contract/*.ts`)은 제외 — `contract-gate`가 컴파일로 판정한다.

**기록 규칙**

| 대상 | 기록 |
|:--|:--|
| 유닛 (`01.work/…`) | **`{유닛}/6.review/`에 회차로 남긴다** — 다음에 무엇이 이미 지적됐는지 알아야 한다 |
| 그 밖 (`00.ref`·`02.decisions`·`04.ops`) | 파일로 남기지 않고 리포트만 |

> `/flow:run`의 `gatekeeper`도 `doc-verify`를 쓰지만, **그 단계 산출물 하나만** 본다. 전수 채점은 사람이 이 커맨드로 부를 때만 한다.

**설명 노트가 필요한 시점을 함께 본다** — 아무 커맨드도 이걸 만들지 않아 요청이 없으면 영원히 안 생긴다.

| 신호 | 왜 필요한가 |
|:--|:--|
| **`02.decisions/`에 ADR이 쌓였는데 `00.ref/05.explainer/`가 비어 있다** | *"왜 이렇게 돼 있나"* 를 알려면 ADR을 여러 개 읽어야 한다 — 묶은 문서가 없다 |
| 도메인 문서가 여럿인데 전체를 잇는 글이 없다 | 용어·경계만으로는 그림이 안 보인다 |
| 새 사람이 합류한다 | `doc/README`의 읽는 순서 5단계가 비어 있다 |

```
ℹ️ ADR이 쌓였는데 설명 노트가 없습니다 (00.ref/05.explainer/ 비어 있음).
   "왜 이렇게 돼 있나"를 묶은 문서를 만들까요? → ops-doc (10.explainer)
```

**`04.ops/`를 볼 때는 회고 조치가 등록됐는지도 본다** (`doc-verify`).

회고는 조치를 *어디로 보낸다*고만 적는다 — **아무도 그 커맨드를 안 돌리면 표 한 줄로 남고 같은 장애가 다시 온다.** `어디로`의 ID를 요구 등록소와 대조하고, **`P1` 미등록을 맨 앞에** 낸다.

- **제안만 한다.** 채점 항목이 아니고 차단하지 않는다 — 필요를 아는 것은 사람이다.
- **`ops-doc`에 넘긴다.** 이 커맨드가 문서를 쓰지 않는다.

## 코드 리뷰

**1. 대상 선언**

```
[/flow:review] 대상: {git diff 목록 또는 지정 경로}   단계: {일반 | deep}
          기준 설계: doc/01.work/{domain}/.../2.task·3.contract (있으면)
          층: {실제로 돌 도구 목록}   빠진 층: {미설치 도구와 그 영향}
```

- **빠진 층을 먼저 밝힌다.** 나중에 "다 봤다"로 읽히면 안 된다.
- **GitHub MCP가 있으면 과거 리뷰를 먼저 본다** — 이미 지적됐다가 "그건 이래서 괜찮다"로 정리된 것을 또 올리지 않는다. 없으면 유닛의 기존 `6.review/`만.

**2. 층 실행** (`reviewer` 위임) — 규약은 `code-review`.

| 층 | 무엇 |
|:--|:--|
| 1 | `contract-gate` — 타입·컴파일 |
| 2 | **OCR** — 알려진 패턴(NPE·XSS·SQLi·스레드 안전), 줄 단위 |
| 3 | `code-graph` — 교차 파일 영향 · **값이 위험한 곳까지 닿나**(Joern 있을 때) |
| 4 | `code-audit` — 우리 규약 · **ponytail** — 지울 것 목록(있으면) |
| 5 | `claude-security` — 취약점 + 자체 반박 |

**3. 설계 의심** (`deep`일 때만) — `codex`의 `adversarial-review`.

**다른 모델이 "이 방식이 맞나"를 묻는다.** 우리 층은 전부 Claude라 같은 곳을 놓친다.

- **코드를 OpenAI로 보낸다.** 실행 전에 알리고 확인받는다.
- **codex가 없으면 1~5만 돌고 "설계 의심 층 생략"을 리포트에 적는다.** 멈추지 않는다.
- `/codex:rescue`는 쓰지 않는다 — 코드를 고친다. 우리는 `builder`만 쓴다.

**4. 점검 카테고리** — 층이 낸 것을 이 틀로 정리한다.

- **계약 정합성** — 계약의 Endpoint/DTO/에러코드가 실제 코드와 일치
  - **DTO 필드·타입은 `contract-gate`가 컴파일로 본다** — 여기서 눈으로 다시 대조하지 않는다
  - **엔드포인트·에러코드는 눈으로 본다** — 계약에만 있는 것(구현 누락)·코드에만 있는 것(계약 없는 API)
  - **같은 도메인의 계약 파일들을 나란히 본다** — 계약은 **유닛마다 `self-contained`**라 `contract-gate`가 파일별로만 컴파일한다. 그래서 **못 잡는 것이 둘 있다**:

    | 무엇 | 예 |
    |:--|:--|
    | **같은 이름 타입이 다르게 정의** | `00.login`의 `User.id`가 `number`, `01.reset`은 `string` |
    | **같은 엔드포인트를 두 유닛이 정의** | 둘 다 `POST /api/user/login` — **유닛 경계 문제**다 |

  - 첫 줄은 **critical이 아니다**(리포트). 둘째 줄은 **유닛 분할을 다시 보라고 적는다.**
- **설계 충실도** — 완료 기준 구현·Logic 반영·이탈이 History에 기록됐나
- **보안** — 2·5층 결과 + 아래 두 갈래
  - **적힌 위험**: 문서·코드에 드러난 것 — 입력 검증·SQLi/XSS/CSRF·민감정보 로깅·권한 누락
  - **안 적힌 위험**: 문서에 없지만 **아는 사람이 보면 보이는 것.** 예: 응답 차이로 계정 존재가 새어나감 · 링크가 Referer로 유출 · 재발송 횟수 제한 없음. **근거를 함께 적는다** — 근거 없는 추측은 리포트로만
- **아키텍처** — 계층 책임·트랜잭션 경계·의존 방향
- **회귀 표면** — task History의 `impact-analysis` 회귀·미검증 목록이 처리·테스트됐나

> 설계 문서 없으면 `계약 정합성`·`설계 충실도`는 건너뛰고 `보안`·`아키텍처` + `code-audit`.
> **여러 층이 같은 것을 짚으면 한 줄로 합치고 출처를 둘 다 적는다** — 신뢰도가 높다는 뜻이다.

**5. critical·high 재확인** — `verifier`에 넘긴다.

리뷰한 쪽이 자기 발견을 검증하면 편향된다. `verifier`가 **독립적으로 반증을 시도**한다 — 진짜 문제인가, 재현되는가.

- 재확인에서 뒤집히면 등급을 내리고 **뒤집힌 사유를 함께 적는다.**
- `medium`·`low`는 재확인하지 않는다 (비용 대비 값이 낮다).

**6. 리포트** — `{unit}/6.review/NN.내용.날짜.md` (유닛 회차 · `NN.내용.YYYYMMDD.md`)

```
[Critical] 즉시 차단 (보안·데이터 손실·컴파일 오류) — 하드 차단
[High]     머지 전 필수 수정      [Medium] 개선 권장      [Low] 참고
```

- 각 항목에 **파일:라인 + 발견 + 출처(어느 층) + 권장 조치**. 문서에 없던 위험은 **근거**도.
- **안 본 주제**와 **빠진 층**을 함께 적는다 — 통과 목록만 보면 "다 봤다"로 읽힌다.

## 가드레일

- **코드를 직접 수정하지 않는다** — 수정은 `/flow:build`.
- **critical만 하드 차단**(룰 기반). **LLM 단독 추측은 리포트만**(오탐 완화). 임계는 `workflow.config.json`의 `review.severity`(기본 `critical`).
- 추측 금지 — 확인 안 된 것은 "확인 필요"로 명시.
- **문서에 없던 위험은 근거를 붙인다.** 근거 없이 등급을 매기지 않는다.
- **자기 발견을 자기가 확인하지 않는다** — critical·high는 `verifier`가 독립 재확인한다.
- **빠진 층을 숨기지 않는다.** 도구가 없으면 그렇게 적는다 — **"안 봤다"를 "문제없다"로 적지 않는다.**
- **`deep`에서 코드를 외부(OpenAI)로 보내기 전에 알린다.** 확인 없이 전송하지 않는다.
