# /flow:verify — 테스트 실행

테스트 시나리오를 실제로 돌려 통과/실패를 확인한다. 범위 3단.
실행은 `verifier` 에이전트가 격리 수행 — 추론이 아니라 Exit code로 판정.

## 연결

- **에이전트**: `verifier` (실행·통과/실패만 반환, 코드 수정 안 함)
- **스킬**: `tdd-verify`(판정) · `test-spec`(단위·통합 명세) · `traceability`(요구 커버리지·gap) · `code-graph`(관련 테스트 선별, 선택) · `plain-writing`(결함·특이사항 문장) · `default-reference`
- **템플릿**: `unit`→`05.verify` · `branch`·`project`→`14.integration`
- **도구**: 화면 테스트에 **Playwright(MCP) 또는 Claude in Chrome(확장) 중 하나 필수** (`presets/tools`) · Joern(CLI — `code-graph`로 관련 테스트 선별, 선택)

## 입력 (`$ARGUMENTS`)

범위는 **요구 레벨과 대응**한다 — 무엇을 커버했는지의 기준이 레벨마다 다르다.

| 범위 | 무엇을 | 커버리지 기준 | 위치 | 템플릿 |
|:--|:--|:--|:--|:--|
| `unit` | task 1:1 단위 테스트 (또는 `/flow:build` 루프가 자동) | 그 task의 완료 기준 | `{unit}/5.verify/` | `05.verify` |
| `branch {name}` | 그 브랜치 유닛들 조합 (머지 전) | 기능 요구(`{도메인}-{유닛}-*`) | `03.integration/00.branch/{branch}/` | `14.integration` |
| `project` | **전체 통합테스트**(E2E) — **유닛을 전부 만든 뒤.** 결과에 요구 커버리지도 포함 | 시스템·도메인 요구(`SYS-*`·`{도메인}-*`) | `03.integration/01.project/` | `14.integration` |

**`project`는 언제 도나** — 아무 때나 돌리면 리포트가 쓸모없다.

| 상황 | |
|:--|:--|
| **돌릴 때** | 계획한 유닛을 **전부 만든 뒤** · `/flow:run full project`의 4층 · 릴리스 전 |
| **안 돌릴 때** | 일부만 만든 상태 — **대부분이 gap으로 나와** 무엇이 진짜 누락인지 안 보인다 |
| 미완성이 있으면 | **그 목록을 먼저 보여주고 확인받는다.** 그래도 돌리겠다면 "미완성 N개 제외"를 리포트에 적는다 |
| **레거시면** | **`확정` 요구만 커버리지 대상**이다. 역추출 요구는 `현행(미검증)`으로 따로 센다 — 안 그러면 전부 gap이 된다 |

- 인자에 `playwright`·`chrome`을 함께 주면 그 모드로 실행한다(아래 절차 3).

**브랜치 폴더 이름** — 브랜치 이름에 `/`가 들어가면 폴더가 한 단 더 깊어진다.

| 브랜치 | 폴더 |
|:--|:--|
| `feature/login` | `00.branch/feature-login/` — **`/`를 `-`로 바꾼다** |
| `fix/token-expiry` | `00.branch/fix-token-expiry/` |

- 이름을 안 주면 **`git branch --show-current`** 를 쓴다. 커밋 규약과 무관하다 — 현재 브랜치가 답이다.
- **`main`·`master`에서 `branch` 범위를 부르면 되묻는다** — 머지 전 조합을 보는 것이라 기본 브랜치에선 뜻이 없다. `project`를 뜻한 게 아닌지 확인한다.

## 절차

**1. 대상 선언**

```
[/flow:verify] 범위: {unit|branch|project} · 대상: {유닛/브랜치}
          → 시나리오를 verifier로 실행합니다.
```

**규모 게이트** — `project`일 때만. 요구 전체를 대조하므로 모델을 확인한다.

```
⚠️ 전체 통합테스트 (요구 전수 대조 · 서브에이전트 병렬 · 긴 실행)
   현재 세션 모델: {감지값}
   Fable 5 권장 — 단 비용 2배 · 턴이 수 분 · 30일 데이터 보존 필요(ZDR 불가)
   바꾸려면 /model 로 전환 후 재실행. 그대로 진행할까요?
```

- 모델은 **권고만** 한다. 무시하고 진행해도 된다.

**2. 시나리오 확보**

- `unit` — `test-spec`(단위): task 완료 기준 매핑, 시나리오+결과 한 파일
- `branch`·`project` — `test-spec`(통합): **조합 매트릭스 안에서만** 케이스 생성. 매트릭스에 없는 조합을 지어내지 않는다 (케이스 무한 증식 방지). **매트릭스가 없으면** 요구·계약에서 축과 값을 뽑아 **제안하고 승인받는다** — 승인 전엔 돌리지 않는다
- 실행 코드는 `tests/scenarios/`(source)

**앞 범위에서 `미검증`으로 남은 업무 규칙을 먼저 모은다** (`test-spec`). 규칙 번호가 범위를 정한다 — `R번호`는 `unit`, **`DR번호`는 `branch`**, **`SYS-*`는 `project`**다.

```
verify branch feature-leave
  모을 것: 5.verify/ 들의 `미검증(범위: branch)` 항목
    DR-2  3일 이상 2단 결재   (leave/01.request · approval/00.line)
```

- **새로 지어내지 않는다.** 남은 것을 닫는 것이 먼저다.
- **닫았든 못 닫았든 `모아 온 미검증`에 적는다** — 못 닫은 것은 `project`가 여기서 받는다. 조용히 빼지 않는다.
- **`branch`를 건너뛰는 프로젝트면 `project`가 `DR번호`까지 모은다.** 혼자 하면 두 시점이 같다 — 안 모으면 도메인 규칙이 영원히 안 닫힌다. 닫은 범위를 결과에 적는다.

**3. verifier 실행** — **화면이 있는 테스트는 브라우저를 띄워 실제로 클릭한다.**

모드는 `workflow.config.json`의 `test.browser`로 정한다. 인자로 준 값이 있으면 그게 우선이다.

| 모드 | 무엇 | 언제 |
|:--|:--|:--|
| **`playwright`** (기본) | 스크립트가 브라우저를 조작한다. 같은 걸 반복·CI에서 재실행할 수 있다 | 회귀 테스트 · 케이스가 확정된 것 |
| **`chrome`** | Claude가 크롬을 직접 보고 클릭한다. 화면을 봐야 판단되는 것을 잡는다 | 시나리오를 처음 만들 때 · 레이아웃·표시가 기준일 때 |

- **둘 중 하나는 반드시 있어야 한다.** 없으면 **멈추고 설치를 안내한다** — 화면 테스트를 건너뛰고 통과로 처리하지 않는다.
- **창을 띄운다**(headed). 사람이 무슨 일이 일어나는지 볼 수 있어야 한다. `test.headless: true`로 바꿀 수 있다.
- 실패하면 **스크린샷·비디오**를 남기고 경로를 결과에 적는다.
- `chrome` 모드는 **모달·확인창을 띄우는 조작을 피한다** — 대화가 멈춘다. 불가피하면 먼저 알린다.
- 관련 테스트 선별이 필요하면 `code-graph`로 변경 커버 범위를 좁힌다.

**돈이 드는 테스트는 상한 안에서만 돈다** (`test-spec`).

| 범위 | 어떻게 |
|:--|:--|
| `unit`·`branch` | **호출을 최소로.** 형식·경계는 mock, 범위는 소수 회차. 상한은 task `Verification`에 |
| `project` | **원가 요구는 여기서만 실제로 돌린다** — 요구의 `측정 방법`에 몇 편을 만들어 평균 낼지 적혀 있다 |

- **LLM 기능은 1회 판정 금지** — 횟수·임계(예: 10회 중 8회)로 돌린다. 실패한 회차의 입력·출력을 `결함`에 남긴다.
- **상한을 넘으면 멈추고 리포트한다.** 승인 없이 반복 호출하지 않는다.

**4. 판정·기록**

- PASS/FAIL + 실패 케이스(입력→기대→실제) + 아티팩트 경로
- 실패는 **`결함` 절에 재현·증거·처리 상태와 함께** 남긴다. 고치는 건 `/flow:build`다.
- 결과를 해당 위치 문서에 날짜와 함께 in-place 기록

**5. 요구 커버리지** (`project` 전용) — `traceability`

통합테스트를 돌린 **뒤**, 그 결과를 요구에 대고 맞춰본다. 통과한 테스트만 보고 "다 됐다"고 하지 않는다 — 애초에 테스트가 없는 요구는 통과 목록에 나타나지도 않기 때문이다.

- 요구 등록소(`00.ref/00.architecture/00.requirement.md` · `00.ref/01.domain/*`)를 정본으로 삼는다.
- 태그를 grep해 역인덱스를 만든다: `요구 ID → 설계(D-N) → task → build → verify 결과`.
**대조는 도메인 단위로 묶어 병렬 위임한다** — 요구별로 나누면 요구 250개에 에이전트 250개가 된다.

| 묶는 단위 | 언제 |
|:--|:--|
| **도메인** (기본) | 도메인 8개면 에이전트 8개. 한 도메인의 요구·유닛·검증 결과가 한 에이전트에 모인다 |
| 유닛 | 한 도메인에 유닛이 너무 많아 한 에이전트가 다 못 읽을 때 |
| `SYS-*`는 따로 | 횡단이라 특정 도메인에 안 속한다 — 한 에이전트가 전부 |

- **각 에이전트는 결론만 돌려준다** — 요구 ID별 분류(✅/✗/⚠/▪)와 사유. 원문을 메인으로 끌어오지 않는다.
- **규모를 먼저 알린다.** 대조 전에 몇 개를 몇 갈래로 도는지 제시한다 — 비용이 여기서 정해진다.

```
[/flow:verify project] 요구 커버리지 — 도메인 8 + SYS 갈래 = 9 위임
   요구 250건 · 유닛 60개 · 문서 약 400개를 읽습니다
   → 진행할까요?
```

- **한 갈래가 너무 크면 그 갈래만 유닛으로 다시 쪼갠다.** 전체를 다시 나누지 않는다.

리포트는 분류해 낸다:

| 분류 | 뜻 |
|:--|:--|
| ✅ 검증됨 | 요구 → task → 통과한 테스트까지 연결 |
| ✗ **gap** | 태그 누락 · task 없음 · 테스트 없음 · 실패 — **사유를 명시** |
| ⚠ **사람 확인 필요** | 자동 검증 불가 |
| **▪ 현행(미검증)** | **역추출 요구**(`상태: 확인 필요`) — 코드엔 있고 우리 테스트는 없다 |

**역추출 요구를 gap으로 세면 리포트가 거짓말이 된다.** 레거시는 요구 대부분이 `확인 필요`라 **전부 gap으로 나온다** — 무엇이 진짜 누락인지 안 보인다.

| 요구 상태 | 분류 |
|:--|:--|
| `확정` + task·테스트 있음 | ✅ 검증됨 |
| **`확정`** + task·테스트 없음 | ✗ **gap** — 하기로 했는데 안 했다 |
| **`확인 필요`**(역추출) | **▪ 현행(미검증)** — **gap으로 세지 않는다** |

- **`현행(미검증)`은 합계에서 분리해 센다** — `gap 3건 · 현행(미검증) 41건`처럼. 섞으면 gap 숫자가 의미를 잃는다.
- **테스트를 쓰기로 정하면 요구를 `확정`으로 바꾼다** — 그때부터 gap 판정을 받는다.

**요구의 `종류`로 분류가 갈린다.** 시스템 요구는 종류가 적혀 있다(`13.architecture`).

**요구에 적힌 `측정 방법`을 그대로 실행한다.** 방법을 새로 지어내지 않는다.

| 종류 | 어떻게 |
|:--|:--|
| 기능 제약 · 보안 | 적힌 테스트를 돌려 ✅ 또는 ✗ |
| **성능** | **적힌 도구·부하 조건으로 측정**한다 (예: `k6로 100 VU 5분 → p95`). 측정했으면 ✅, 안 했으면 ✗ gap |
| **원가** | **적힌 대로 합산**한다 (예: LLM 토큰 로그 + S3 용량 + 전송량). 계산했으면 ✅, 안 했으면 ✗ gap |
| **법·정책** | **항상 ⚠ 사람 확인 필요** — 테스트가 없는 게 정상이다. **gap으로 적지 않는다** |
| UX·체감 | ⚠ 사람 확인 필요 |

- **`측정 방법`이 비어 있으면 ✗ gap이고 사유는 "측정 방법 미정"이다** — 테스트가 없는 게 아니라 **어떻게 잴지가 정해지지 않은 것**이다. `/flow:prd`로 돌려보낸다.
- **`법·정책`을 gap으로 적으면 리포트가 거짓말이 된다** — 고칠 수 없는 것을 결함으로 세는 셈이다.

- 상위 요구에 연결되지 않은 기능은 **"상위 미연결"(고아)** 로 함께 표시하고 **처리 선택지를 제시한다**(`traceability`).

```
⚠ 상위 미연결 2건
   src/NotificationService.java  ·  src/ExportUtil.java
   판단 기준: "이 기능이 없어지면 누가 곤란한가?"
     ① 요구를 소급 발급 (/flow:design)   ② 코드를 지운다 (/flow:run fix)
     ③ 고아로 유지 — 기한을 함께 적는다
```

- **리포트만 하고 두지 않는다** — 매 실행이 같은 것을 다시 적어 노이즈가 된다.
- **테스트 결과와 커버리지는 한 파일에 쓴다** — `14.integration` 템플릿의 `요구 커버리지` 절. 따로 만들면 어느 실행의 결과인지 끊긴다.
- 판정만 한다 — 코드·테스트를 여기서 고치지 않는다.

## 가드레일

- **테스트를 약화·mock 처리해 통과시키는 것 절대 금지.**
- **돈이 드는 호출을 상한 없이 반복하지 않는다.** 초과하면 멈추고 리포트한다.
- **LLM 기능을 1회 돌려 판정하지 않는다** — 우연히 통과하거나 우연히 실패한다.
- 코드 수정은 `verifier` 일이 아니다 — 실패는 보고, 수정은 `/flow:build`(builder).
- 명시된 시나리오만 실행. 임의의 무거운 테스트 추가 실행 금지.
- **gap을 임의로 닫지 않는다.** 요구를 삭제·축소해 커버리지를 맞추는 것은 금지 — 리포트가 결론이다.
- 자동 검증 불가 항목을 통과로 표기하지 않는다 — `사람 확인 필요`로 남긴다.
