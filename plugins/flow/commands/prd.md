# /flow:prd — 요구사항 정의

무엇을·누가·왜 필요한가를 확정하고 **요구마다 ID 를 발급**한다.
이 ID 가 설계·구현·검증을 관통하는 **추적 축**이 된다.

> **설계하지 않는다.** 구조·기술 선택은 `/flow:design` 의 일이다. 여기서는 "무엇이 필요한가" 만 정한다.

## 연결

| 싣는 것 | 무엇 |
|:--|:--|
| 스킬 | `traceability`·`usecase`·`doc-template`·`plain-writing`·`default-reference` |
| 조각 | `traceability/level`·`traceability/id-system`·`traceability/conflict`·`traceability/coverage`·`usecase/granularity`·`usecase/rule-level`·`usecase/figure-scope`·`doc-template/diagram`·`doc-template/template-gap`·`default-reference/delegation` |
| 조건부 — **legacy 역추출일 때만** | `traceability/reverse-extract` · `traceability/reverse-check` |

기존 요구·코드를 넓게 확인할 때는 `explorer` 에 위임한다. **판정은 `default-reference` 의 `delegation` 조각이 정본이고 여기서 다시 정하지 않는다** — 그 조각은 *결론만 필요하면 위임, 원문이 필요하면 직접* 이고 범위 기준은 유닛이다.

> **`legacy` 에서 무조건 위임이라고 적지 않는다.** 역추출은 하드코딩된 값과 `파일:심볼` 앵커를 **원문 그대로** 집어야 하므로 직접 읽는 쪽이 맞을 때가 있다 — 유닛을 넘는 범위일 때 위임한다. 실측에서 작은 리포는 직접 읽었고 그것이 정본과 맞다.

## 게이트

정본은 `${CLAUDE_PLUGIN_ROOT}/flow.topology.json` 의 `commands.prd` 의 `entry`·`exit` 다. **여기서는 선언만 한다.**

| 등급 | 조건 | 누가 판정 |
|:--|:--|:--|
| 약속 | `workflow.config.json` 이 있다 | **아무도** — 훅이 커맨드 호출을 못 본다 |
| 내용 · 퇴장 | `level-decision` — 요구의 레벨(시스템·도메인·기능)이 맞나 | **`gatekeeper`** — 진행하는 쪽이 아니다 |
| 약속 | 요구 ID 는 불변·append-only — 번호를 재편하지 않는다 | 아무도. 규약 정본은 `traceability` 다 |

**`level-decision` 은 퇴장 조건이다** — 시작할 때는 요구 초안이 없어 레벨이 맞는지 볼 대상이 없다.
**착지 전에 `gatekeeper` 를 부른다.** 판정할 것은 그 내용 조건과 **외부 쿼터 대조가 비어 있지 않은가** 다.
자기가 정한 레벨을 자기가 승인하지 않는다 — 그것이 v1 에서 게이트가 이름만 남았던 자리다.

## 입력 (`$ARGUMENTS`)

| 인자 | 동작 |
|:--|:--|
| (비움) | 대화형 — 레벨부터 묻는다 |
| `sys` | 시스템 레벨 — 제품 전체·횡단 제약 |
| `domain {도메인}` | 도메인 레벨 — 한 도메인의 요구 |
| `func {도메인}/{NN.유닛}` | 기능 레벨 — work-unit |
| `{레벨} legacy` | **역추출 모드** — 기획서 대신 코드를 읽어 현행 요구를 뽑는다 |
| `REFERENCE @파일` | 기획서·회의록·기존 요구 |

**`legacy` 는 레벨의 수식어다 — 단독 인자가 아니다.** 레벨이 읽을 범위를 정하기 때문이다.
`legacy` 만 오면 레벨을 묻는다. 지어내면 어디를 읽을지가 안 정해진다.

## 절차

### 먼저 읽는다

**시작하기 전에 아래를 읽는다.** `## 연결` 의 표는 배선 선언이라 지시로 읽히지 않는다 —
실측에서 한 커맨드가 선언한 조각을 **하나도 안 읽고** 끝냈다(`build`, 0/7).
경로는 `${CLAUDE_PLUGIN_ROOT}/skills/…` 아래이고, 각 조각이 무엇의 정본인지는 그 파일 첫 줄에 있다.

- `traceability` — `references/level.md` · `references/id-system.md` · `references/conflict.md` · `references/coverage.md`
- `usecase` — `references/granularity.md` · `references/rule-level.md` · `references/figure-scope.md`
- `doc-template` — `references/diagram.md` · `references/template-gap.md`
- `default-reference` — `references/delegation.md`
- *legacy 역추출일 때만* — `skills/traceability/references/reverse-extract.md` · `skills/traceability/references/reverse-check.md`

### 레벨을 정하고 대상을 선언한다

레벨 판별 질문과 라우팅은 `traceability` 가 정본이다 — **판별 기준을 여기 옮겨 적지 않는다.**

```
[/flow:prd] 레벨: {시스템|도메인|기능}  대상: {…}
            산출: {라우팅 경로}   ID 형식: {traceability 의 형식}
```

- 기능 레벨이면 상위(도메인·시스템) 요구를 먼저 읽고 **참조**한다. 없으면 고아로 진행하되 알린다.
- 애매하면 묻는다. 추측한 레벨로 ID 를 발급하면 되돌릴 때 ID 를 다시 매겨야 한다.

### 요구를 인터뷰한다 *(`legacy` 면 아래 역추출로 대체)*

한 번에 하나씩, **답이 범위를 크게 바꾸는 순서로** 묻는다. 이미 답이 인자·참조에 있으면 건너뛴다.
**레벨마다 묻는 게 다르다** — 시스템 요구에 액터·흐름을 물으면 답이 안 나온다.

| 스텝 | sys | domain | func | 질문 예시 |
|:--|:--:|:--:|:--:|:--|
| 목적 | ✓ | ✓ | ✓ | 무엇을 해결합니까? |
| 목표 | ✓ | | | 이루려는 것이 있습니까? 우리가 못 만드는 것도 |
| 액터 | | ✓ | ✓ | 누가·무엇이 씁니까? |
| 기능 | | ✓ | ✓ | 필요한 기능을 나열하면? |
| 흐름 | | | ✓ | 각 기능이 어떤 순서로 흐릅니까? 예외도 |
| 사전·사후조건 | | | ✓ | 시작하려면 무엇이 참이어야 하고, 끝나면 무엇이 남습니까? |
| 업무 규칙 | | ✓ | ✓ | 판정 기준·한도·예외 대상이 있습니까? 숫자로 |
| 적용 범위 | ✓ | | | 이 제약이 어디까지 적용됩니까? |
| 외부 의존 | ✓ | | | 남의 서비스에 매달린 게 있습니까? **쿼터·상한**은? |
| 완료 기준 | ✓ | ✓ | ✓ | 무엇이 되면 완료입니까? 측정 가능하게 |
| 측정 방법 | ✓ | ✓ | ✓ | *(`종류` 가 있는 요구가 나왔을 때)* 이걸 어떻게 잽니까? |
| 의존 | ✓ | ✓ | ✓ | 먼저 끝나야 하는 게 있습니까? |
| 범위 밖 | ✓ | ✓ | ✓ | 이번에 하지 않을 것은? — **요구로 등록한 것을 여기 적지 않는다** |

- 묻는 순서와 **모르는 칸을 어떻게 두나**는 `usecase` 의 `granularity` 조각이 정본이다.
- 업무 규칙을 **어느 레벨에 두나**는 `usecase` 의 `rule-level` 조각이 정본이다. 올린 규칙은 번호로만 가리킨다 — 내용을 복사하면 고칠 곳이 둘이 된다.

### 역추출한다 *(`legacy`)*

기획서가 없고 **코드가 유일한 진실**일 때. 코드에 구현된 사실을 요구로 등록한다.

- **절차의 정본은 `traceability` 의 `reverse-extract` 조각이다 — 뽑기 전에 읽는다.** 여기 옮겨 적지 않는다.
- **역추출 요구에 신규용 게이트를 걸지 않는다.** 무엇이 면제인지는 `traceability` 의 `coverage` 조각이 정본이다.
- 뽑은 뒤 **근거가 코드에 실재하나를 대본다** — `traceability` 의 `reverse-check` 조각을 읽고 그 절차를 돈다. 표본 판정은 `verifier` 에 넘긴다.

### ID 를 발급하고 기록한다

ID 형식·발급 순서·유닛 이름 규칙은 `traceability` 의 `id-system` 조각이, 브랜치가 갈린 상태의 중복 발급은 `conflict` 조각이 정본이다. **발급 전에 읽는다.**

- 요구마다 ID 를 준다. 기존 파일이 있으면 **이어서 발급**한다 — 재편하지 않는다.
- 상위 참조는 문서 상단에 한 번 선언한다. 각 요구에 중복 기재하지 않는다.
- **기능 레벨은 요구를 유스케이스로 쓴다** — 액터·흐름·예외가 곧 요구다. 별도 번호 체계를 만들지 않는다. 입도·표 칸 규칙은 `usecase` 의 `granularity` 조각이, 표와 그림의 분담은 `figure-scope` 조각이 정본이다.
- 그림 표기는 `doc-template` 의 `diagram` 조각이 정본이다.
- **템플릿에 요구하는 절이 없으면 지어내지 않는다** — `doc-template` 의 `template-gap` 조각을 따라 선택을 받는다.

**`종류` 가 있으면 `측정 방법` 을 반드시 채운다.** 비면 그 요구는 **영구 gap** 이 된다 — 잴 길이 없으니 영원히 검증되지 않는다.

| 종류 | 무엇을 적나 |
|:--|:--|
| 성능 | **도구 · 부하 조건 · 뽑을 값** — "부하 측정" 만으로는 부족하다 |
| 원가 | **무엇을 합산하나 · 데이터 출처** (실행 로그·청구서·계량 API) |
| 법·정책 · UX | **"사람 판단 — 자동화 불가"** 라고 적는다. 이건 비운 것이 아니다 |

- **측정 방법을 모르면 요구를 확정하지 않는다** — `확인 필요` 에 적는다. "원가 500원" 만 있고 무엇을 합산할지 모르면 그건 요구가 아니라 바람이다.
- **적은 도구가 실제로 있는지 확인한다.** 없으면 설치하거나 있는 도구로 방법을 바꾼다.
- **원가는 도구로 안 잰다.** 우리가 토큰·용량·전송량을 로그로 남겨야 잰다 — 그 로깅은 `/flow:design` 에서 **설계 요소로 나와야** 한다.

**외부 쿼터를 요구에 대고 계산한다** — `쿼터 ÷ 1회 사용량 = 하루 상한`. 요구가 그 안인지 **여기서 확인**한다.

`외부 의존` 표의 대조 칸에 셋 중 하나로 적는다: `OK — {계산}` · **`충돌 — {계산}`** · `확인 필요 — {무엇을 모르나}`.

- **`충돌` 이면 여기서 멈춘다.** 요구가 처음부터 불가능하다 — 요구를 줄이거나 쿼터를 올린다. **사람이 정한다.**
- **비워두면 `gatekeeper` 가 다음 국면을 차단한다.** 설계·구현을 다 한 뒤 드러나면 되돌릴 게 너무 많다.
- **설계로 넘기지 않는다.** 우회 방식이 답이면 그것도 요구 변경이라 여기로 돌아온다.

### 시스템·도메인은 설계와 자리를 나눈다

여기서 **요구만 쓰고 나머지는 손대지 않는다.** 한 파일을 두 커맨드가 나눠 쓰기 때문에, 남의 절을 건드리면 상대가 덮어쓴다.

| 레벨 | `/flow:prd` 의 자리 | `/flow:design` 의 자리 |
|:--|:--|:--|
| sys | 아키텍처 요구 문서 — **별도 파일** | 아키텍처 설계 문서 |
| domain | 도메인 파일의 **`요구`·`확인 필요` 절만** | 같은 파일의 `배포 단위`·`경계`·`용어`·`업무 흐름` |

- 도메인 파일의 `하위 기능` 색인은 `/flow:sync` 가 채운다 — 손으로 쓰지 않는다.

### 요약하고 넘긴다

- 발급한 ID 목록 · 범위 밖 · `확인 필요` 항목을 보여주고 검수를 받는다.
- 착지 전에 **`gatekeeper` 에게 레벨 판정과 쿼터 대조를 넘긴다.** 통과해야 다음 국면으로 간다.
- **판정 뒤에 산출물을 고쳤으면 그 판정은 무효다 — 다시 부른다.** 실측에서 대조 층이 요구 하나를 내리고 다른 하나의 문장을 고친 뒤에도 앞선 PASS 를 그대로 들고 갔다. *"요구가 줄었으니 판정이 뒤집히지 않는다"* 는 **진행하는 쪽의 추론**이고, 그 추론을 하지 않게 판정을 분리한 것이다.
- 다음 국면은 위상 정본(`flow.topology.json` 의 `commands.prd.next`)이 정한다.

## 가드레일

- **설계 금지.** 기술 선택·구조·API 형태는 산출물에 넣지 않는다.
- **ID 재편 금지.** 삭제는 폐기 표기, 분할은 하위 ID 로.
- 측정 불가능한 완료 기준을 그대로 두지 않는다 — 되묻거나 `확인 필요` 로 표기한다.
- 기존 요구를 덮어쓰지 않는다. 충돌하면 중단하고 보고한다.
- **`legacy` 역추출은 사람 검수 전까지 정본이 아니다.** 전부 `확인 필요` 이고, 코드도 고치지 않는다.
- **유닛 번호를 지어내지 않는다.** 없는 유닛에 `func` 를 쓰려 하면 거부하고 도메인 레벨을 안내한다.
- **시스템·도메인 파일에서 요구 절 밖을 건드리지 않는다.**
- 추측과 확인을 구분해 표기한다.
