# /flow:publish — 결과 발행 국면

개발이 끝난 산출물을 **외부(주로 Notion)로 발행**한다. 새 내용을 지어내지 않고 `doc/`에 이미 있는 것만 구조화해 옮긴다.

> **외부 발행 주의**: 이 커맨드는 내용을 외부 서비스로 내보낸다(공개·인덱싱될 수 있음). **반드시 무엇을·어디로 발행할지 확인받고 실행**한다.

## 연결

- **에이전트**: `explorer` (`project` 전체·유닛 다수 — 산출물 원문을 메인으로 끌어오지 않는다)
- **스킬**: `plain-writing`(발행문 문장) · `default-reference`
- **템플릿**: 없음 — 이미 있는 산출물을 옮긴다
- **도구**: Notion MCP (아래 절차 2)

## 입력 (`$ARGUMENTS`)

| 인자 | 동작 |
|:--|:--|
| (비움) | `doc/`의 완료 산출물 전체(`project`)를 발행 |
| `{도메인}/{NN.유닛}` | 그 유닛만 |
| `→ Notion DB/페이지` | 발행처 지정 (없으면 `publish.notionParent`, 그것도 없으면 최초 1회 질문) |

## 절차

**1. 대상 선언** (작업 전 필수)

```
[/flow:publish] 대상: {유닛 경로 또는 project 전체}
           소스: 00.ref(용어·시스템·도메인) + 0.requirement · 1.design · 2.task
                 · 3.contract · 5.verify · 7.summary + 02.decisions(ADR) + 03.integration
           발행처: Notion {DB 또는 부모 페이지}   갱신/신규: {판정}
           다이어그램: {이미지 업로드 | .svg 경로 참조 | 코드블록 그대로 — 그림 안 보임}
           민감정보: {발견 없음 | 아래 항목 제외 후 발행}
           → 외부로 내보냅니다. 진행할까요?
```

- **유닛을 넘으면 `explorer`에 위임**해 항목만 받는다(`default-reference` 위임 판정).

**2. 발행처 확보**

- **Notion MCP 연결**은 머신·계정당 **한 번, 수동**이다. OAuth(설정→커넥터→Notion) 또는 `claude mcp add --transport http notion https://mcp.notion.com/mcp`. **인증은 AI가 대신 못 한다** — 미연결이면 방법을 안내하고 중단.
- **발행처(닻)**: Notion 통합은 **공유된 부모 안에서만** 쓸 수 있다. `publish.notionParent`가 없으면 **한 번 물어 config에 저장**한다(다음부터 자동).

**3. 자료 수집** — 문서에 있는 것만. 추측 금지.

| 발행 섹션 | 출처 |
|:--|:--|
| 개요 | 유닛 경로 · 기간 · 브랜치 |
| **용어** | **`00.ref/01.domain/00.common.md`** — **가장 먼저 온다.** 없으면 받는 사람이 나머지를 못 읽는다 |
| **시스템 요구·구조** | **`00.ref/00.architecture/`** — `SYS-*` · 배포 단위 · 의존 방향 · **화면 지도** |
| **도메인** | **`00.ref/01.domain/{도메인}.md`** — 도메인 요구 · 경계 · **업무 규칙(`DR`)** |
| **요구** | `0.requirement.md` — 요구 ID·유스케이스·완료 기준 (**정본**) |
| **설계** | `1.design.md` — 구조·다이어그램(**절차 3-1**)·결정 |
| 작업 | `2.task/` — 분할·File Map |
| API 계약 | `3.contract/` — 엔드포인트·DTO·에러코드 |
| **검증** | `5.verify/` · `03.integration/` — 결과·결함 |
| 구현 요약 | `7.summary/` — 변경 사항·파일 |
| 결정(ADR) | `02.decisions/` — 택한 안·기각 사유 |
| 설명 노트 | `00.ref/05.explainer/` — 있으면 |
| 후속·제약 | 각 문서의 `확인 필요`·`안 본 것` |

**`00.ref/`를 빼면 발행물이 읽히지 않는다.**

| 범위 | `00.ref/`를 어디까지 |
|:--|:--|
| `{도메인}/{유닛}` 하나 | **용어** + **그 도메인 문서**만. 시스템 전체는 링크로 |
| `project` 전체 | `00.ref/` 전부 |

- **용어를 맨 앞에 둔다** — `doc/README`의 읽는 순서 3단계가 그것이고, 발행물도 같다.
- **`00.ref/`는 정본이다** — 발행할 때도 **읽어서 옮기기만** 한다. 고치는 것은 각 폴더의 담당 커맨드다.
- **화면 지도는 `13.architecture`에 있다** — FE가 있으면 함께 발행한다.

**3-1. 다이어그램 처리** — 그대로 옮기면 그림이 사라진다

**우리 다이어그램은 PlantUML 코드블록이다**(`doc-template`). 발행처가 그걸 렌더하지 못하면 **코드 덩어리만 남는다.**

| 발행처 | PlantUML | mermaid |
|:--|:--|:--|
| **Notion** | ❌ 코드 텍스트 | ✅ 렌더 |
| **docx·pdf** | ❌ | ❌ |
| markdown | 읽는 사람 환경에 달렸다 | 같음 |

**이미지로 렌더해 올린다.** 순서대로 시도하고 **어디까지 됐는지 결과에 적는다.**

| 순 | 방법 | 조건 |
|:--|:--|:--|
| ① | **로컬 jar로 `.svg`(또는 `.png`) 생성** → 발행처에 **이미지로 업로드** | `plantuml.jar`가 있고, 발행처 MCP가 **이미지 업로드를 지원**할 때 |
| ② | `.svg`를 **저장소에 저장**하고 발행물에는 **경로·URL을 적는다** | 업로드가 안 될 때. 저장소가 공개면 URL이 보인다 |
| ③ | **코드블록을 그대로 두고 알린다** | 렌더 도구가 없을 때 |

- **발행 시점에 MCP 도구 목록을 확인한다** — 이미지 업로드를 지원하는지 미리 단정하지 않는다.
- **②에서 `.svg`를 어디에 둘지 묻는다.** 생성물을 저장소에 커밋하는 것이라 사용자 판단이다.
- **③이면 그림이 안 보인다는 사실을 발행 결과에 명시한다.** 조용히 코드블록을 남기면 받는 사람이 문서가 깨졌다고 본다.

```
[/flow:publish] 다이어그램 8개 — 방법 ②
   plantuml.jar ✅ · Notion 이미지 업로드 ❌ (도구 없음)
   → doc/.../diagrams/ 에 .svg 8개 생성, 발행물에 경로 표기
   ⚠ Notion에서 그림이 링크로 보입니다. 이미지로 넣으려면 직접 업로드하세요.
```

- **`.svg`를 만들 때 `!pragma layout smetana`가 있으니 Graphviz는 필요 없다**(`presets/tools`).
- **원본 코드블록을 지우지 않는다** — `doc/`의 정본은 텍스트다. 발행물에만 이미지를 넣는다.

**4. 민감정보 점검** (발행 전 필수)

외부로 나가면 되돌릴 수 없다. **내보내기 직전에 훑는다.**

| 무엇 | 처리 |
|:--|:--|
| 크리덴셜·토큰·키 | **제외** |
| 내부 호스트·IP·DB 접속 정보 | **제외** |
| 개인정보(실명·연락처·계정) | **제외** |
| 비공개 경로·사내 시스템명 | 사용자에게 **확인** |

- 하나라도 걸리면 **목록을 보여주고 승인받는다.** 임의로 마스킹해 내보내지 않는다.

**5. 발행** — 신규/갱신 판정은 **기록된 URL**로 한다. `project`는 **`doc/README.md` 맨 위 줄**, 유닛은 **`7.summary/`** 다(절차 6).

**`7.summary/`는 회차로 쌓인다** — 최신 회차만 보면 URL이 없어 **같은 유닛의 페이지를 또 만든다.**

```
7.summary/00.구현.20260729.md   발행 URL 있음
        01.수정.20260805.md   URL 없음 (새 회차)   ← 최신만 보면 "미발행"
```

**전 회차를 뒤져 URL을 찾는다.** 유닛당 페이지는 하나다.

| 상황 | 처리 |
|:--|:--|
| **어느 회차든 URL이 있다** | 그 페이지를 **갱신**. 최신 회차에 없어도 마찬가지다 |
| **여러 회차에 URL이 다르게 있다** | **묻는다** — 어느 페이지가 정본인가. 임의로 고르지 않는다 |
| URL이 없는데 같은 제목의 페이지가 부모 아래 있다 | **묻는다** — 갱신할지 새로 만들지 |
| 둘 다 없다 | 부모 아래 **새 자식 페이지** 생성 |

- 실패하면 **중단하고 사유를 보고한다.** 다른 위치에 임의로 만들지 않는다.
- 일부만 발행됐으면 **어디까지 됐는지** 밝힌다.

**6. 기록** — 발행 URL을 남긴다. **어디에 남기나는 범위가 정한다.**

| 범위 | 어디에 | 무엇을 |
|:--|:--|:--|
| `{도메인}/{유닛}` | **이번에 발행한 내용의 `7.summary/` 회차 파일** | 그 유닛 페이지 URL |
| **`project` 전체** | **`doc/README.md` 맨 위 한 줄** — `발행: {루트 URL} ({YYYYMMDD})` | **루트 페이지 URL**. 유닛별 자식 페이지 URL은 각 유닛의 `7.summary/`에 |

- **`project`에는 회차 파일이 없다** — 여기 안 적으면 다음 발행이 **루트 페이지를 또 만든다.** 절차 5의 갱신 판정이 이 줄을 먼저 본다.
- **회차마다 같은 URL이 반복된다** — 그게 맞다. 어느 회차를 봐도 어디로 발행됐는지 알 수 있다.
- **이전 회차의 URL을 지우지 않는다** — 이력이다. `doc/README.md`의 줄은 **한 줄만 유지**하고 날짜를 갱신한다(인덱스라 쌓지 않는다).

## 대안 출력 (Notion을 안 쓸 때)

`workflow.config.json`의 `publish.target`으로 기본 발행처를 지정(`notion` | `docx` | `markdown`).

| target | 무엇 | 다이어그램 | 민감정보 |
|:--|:--|:--|:--|
| `notion` | 페이지로 발행 | **절차 3-1** — 이미지 업로드 또는 경로 참조 | **외부로 나간다** — 절차 4 필수 |
| `docx`·`pdf` | `docx`/`pdf` 스킬로 문서 생성 | **이미지로 렌더해 넣는다**(절차 3-1 ①). **코드블록으로 두면 안 보인다** | 파일을 어디로 보내나에 달렸다 — **절차 4를 그대로 한다** |
| `markdown` | `doc/`의 문서를 그대로 묶어 전달 | **원본 그대로** — 받는 사람 환경에 달렸다 | 파일 전달이라 통제가 사람 몫 |

- **`markdown`이 가장 정직하다** — 원본을 주는 것이라 변환 손실이 없다. 다만 **"발행"이 아니라 파일 전달**이다.
- **`docx`는 다이어그램에 가장 취약하다** — mermaid도 안 되니 **이미지 렌더가 사실상 필수**다.
- **어느 target이든 민감정보 점검(절차 4)은 한다.** 파일로 나가는 것도 되돌릴 수 없다.

## 가드레일

- **문서에 있는 것만 발행.** 추측·과장 금지. 완료 기준·변경사항은 실제 산출물 기준.
- **민감정보는 절차 4에서 걸러 승인받는다.** 임의 마스킹으로 내보내지 않는다 — 외부 발행은 되돌릴 수 없다.
- **확인 후 발행.** 대상·발행처를 사용자가 승인하기 전에 외부로 내보내지 않는다.
- **페이지를 임의로 새로 만들지 않는다** — 갱신 판정은 `7.summary/`의 URL 기준. **최신 회차만 보지 않는다.** 애매하면 묻는다.
- **용어(`00.common.md`)를 빼고 발행하지 않는다** — 받는 사람이 나머지를 읽을 수 없다.
- **다이어그램이 코드블록으로 남았으면 그 사실을 알린다**(절차 3-1). 조용히 넘기면 받는 사람이 문서가 깨졌다고 본다.
- 발행은 **읽어서 옮기는 것** — 코드·설계 문서를 수정하지 않는다(URL 한 줄 기록만). **`.svg`를 만들 때만 파일을 쓴다.**
