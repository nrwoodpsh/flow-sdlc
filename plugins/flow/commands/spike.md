# /flow:spike — 검증 (앞단 de-risking)

미검증 핵심 알고리즘·기술 리스크를 **버릴 코드(`spike/`)**로 확인한다.
남기는 건 코드가 아니라 **지식(ADR·ref)**. 계약·완료 기준 없음(학습 모드).

> **왜 별도 문인가**: 불확실 구간은 계약을 아직 모르고 완료 기준을 못 정한다. 그래서 `/flow:design`의 계약 게이트·완료 기준·drift를 **끈다**. 불확실성이 풀리면 `/flow:design`(자산 모드)으로 넘어간다.

## 연결

- **에이전트**: `builder` (학습 모드 — 계약게이트·drift·테스트 루프 끔)
- **스킬**: `default-reference` · `plain-writing` · `tdd-verify` (가설 실행 판정)
- **템플릿**: `08.adr` (판정을 ADR로 남길 때)

## 입력 (`$ARGUMENTS`)

| 인자 | 동작 |
|:--|:--|
| 가설 (필수) | 무엇이 되는지 검증할 것인가. 없으면 되묻는다 |
| `REFERENCE @파일` | 참고 자료·데이터·기존 코드 |
| 검증 기준 (필수) | 채택/기각을 가르는 관찰 가능한 선. 없으면 되묻는다 (끝없는 실험 방지) |

## 절차

**1. 가설·기준 고정** (step Q&A — 인자에 없는 것만)

한 번에 하나씩 묻는다. 이미 인자·참조에 답이 있으면 건너뛴다.

| 스텝 | 질문 예시 (플레이스홀더) |
|:--|:--|
| 가설 | `무엇이 되는지 확인하려는 겁니까? (예: 결재선 규칙엔진이 500건/초를 견디나)` |
| 검증 기준 | `무엇을 보면 채택입니까? (예: p95 200ms 이하 · 오판정 1% 미만)` |
| 상한 | `어디까지 해보고 멈춥니까? (예: 접근 2가지 · 반나절)` |

```
[/flow:spike] 가설: {한 줄} · 검증 기준: {무엇을 보면 채택/기각}
         작업 공간: spike/00.{주제}/ (버릴 코드 — 게이트 대상 아님)
```

**2. 최소 실험 코드** — `spike/00.{주제}/` 아래에만

- 폴더를 만들 때 **`README.md` 한 장을 먼저 둔다** — 나중에 이게 버릴 코드인지 아무도 모른다.

  ```markdown
  # spike/00.{주제} — 버릴 코드
  가설: {한 줄} · 검증 기준: {무엇을 보면 채택/기각} · 시작: {YYYYMMDD}
  **프로덕션에 승격하지 않는다.** 결과는 doc/02.decisions/{ADR}에.

  <!-- 판정 후 채운다 (절차 5) -->
  판정: {채택 | 기각 | 조건부} · ADR: {경로} · 남기는 이유: {없으면 지운다}
  ```

- 프로덕션 구조·계약·테스트 규약 따를 필요 없음 — 빠르게 답을 얻는 게 목적
- 접근이 갈리면 각각 짧게 시도해 비교

**3. 관찰·측정** — 검증 기준에 대고 실제로 돌린다. 추측과 측정을 구분 표기.

**4. 판정·승격 제안** (사람 확인 후)

**판정은 채택이든 기각이든 반드시 ADR로 남긴다** — 템플릿 `08.adr`. 기각을 안 남기면 같은 실험을 반년 뒤에 또 한다.

| 판정 | ADR `상태` | 무엇을 적나 |
|:--|:--|:--|
| 채택 | `채택` | 검토한 안 · 왜 이걸 골랐나 · 감수하는 것 |
| 기각 | `기각` | **무엇을 해봤고 왜 안 됐나** · 측정값 · 다시 해볼 조건 |
| 조건부 | `제안` | 어떤 조건이 충족돼야 채택인가 |

- ADR 위치: `doc/02.decisions/NN.내용.YYYYMMDD.md` (+ `README.md` 색인 갱신)
- 확정 제약(성능 상한·기술 선택) → `doc/00.ref/00.architecture/`
- 도메인 경계·용어 초안 → `doc/00.ref/01.domain/` (소유·확정은 사람)

**ADR이 자족해야 한다.** `spike/*`는 **gitignore라 지우면 완전히 사라진다** — git에도 없다.

**옮길 자리는 `08.adr`의 `## 측정` 절이다.** `검토한 안`의 장단점에 섞어 적지 않는다 — 수치인지 의견인지 구분이 안 된다.

| ADR에 반드시 옮길 것 | 어디에 | 왜 |
|:--|:--|:--|
| **측정값** (수치·조건·환경) | `## 측정` 표 | 폴더가 사라지면 이것만 남는다 |
| **재현 명령** (있으면) | `## 측정` | 다시 재려면 무엇을 돌리나 |
| **시도했다 접은 것** | `## 측정` + `## 기각 사유` | 기각 이유가 없으면 반년 뒤에 또 해본다 |
| spike 폴더 경로 | `## 측정` | **참고용**이다 — 폴더가 없을 수 있다고 함께 적는다 |

**5. 폴더 정리** (판정 후)

**기본은 지운다.** 버릴 코드라 남길 이유가 없고, 쌓이면 무엇이 무엇인지 알 수 없다.

| 상황 | 어떻게 |
|:--|:--|
| **판정이 끝났다** | **지운다** — ADR에 지식이 옮겨졌는지 먼저 확인 |
| 아직 실험 중 | 남긴다 |
| 측정을 다시 돌릴 일이 곧 있다 | 남기고 **`README.md`에 언제까지 남길지** 적는다 |

```
[/flow:spike] 판정: 채택 (WebSocket)
         ADR: doc/02.decisions/03.websocket.20260730.md
         → spike/00.websocket/ 을 지울까요?
            (측정값·기각 사유가 ADR에 옮겨졌습니다. gitignore라 지우면 복구 불가)
```

- **묻고 지운다.** 사용자 확인 없이 지우지 않는다.
- **ADR에 지식이 안 옮겨졌으면 지우지 않는다** — 먼저 옮긴다.
- **안 지우기로 했으면 `spike/00.{주제}/README.md`에 판정 결과와 ADR 경로를 적어둔다** — 나중에 이게 뭔지 알 수 있어야 한다.

**README가 두 개다 — 헷갈리지 않게 구분한다.**

| 파일 | git | 무엇 |
|:--|:--|:--|
| `spike/README.md` | **추적된다** | "이 폴더는 버릴 코드" 안내. `/flow:setup`이 만든다 — **건드리지 않는다** |
| `spike/00.{주제}/README.md` | **무시된다**(`spike/*`) | 그 실험의 가설·기준·판정. **폴더와 함께 사라진다** — 그래서 정본은 ADR이다 |

## 가드레일

- **spike 코드를 프로덕션에 그대로 승격 금지.** 검증된 건 *지식*. 실제 구현은 `/flow:design`→`/flow:build`로 다시 짠다.
- **`spike/` 밖에 코드 쓰지 않는다.** 이 경로가 throwaway 격리선·drift 오탐 방지선.
- **끝나는 조건 없는 실험 금지.** 기준 도달하면 멈춘다 — "더 다듬기"로 새지 않는다.
- **기각도 기록한다.** 판정 없이 끝내지 않는다 — 남는 건 코드가 아니라 지식이다.
- **ADR에 지식을 옮기기 전에 폴더를 지우지 않는다.** `spike/*`는 gitignore라 **복구가 안 된다** — 측정값·기각 사유가 ADR에 있는지 먼저 확인한다.
- **폴더를 사용자 확인 없이 지우지 않는다.**
- 측정 안 한 걸 측정했다고 하지 않는다. 커밋·push는 `/flow:spike` 일이 아니다.
