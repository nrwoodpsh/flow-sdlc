# /flow:build — 구현

설계(`2.task`)·계약(`3.contract`)을 정확히 따라 코드를 구현한다.
핵심 가치: **설계 충성도 > 클린 코드 > 테스트 통과.** 구현↔테스트 루프의 오케스트레이터.

## 연결

- **에이전트**: `builder`(구현, 쓰기) ⇄ `verifier`(테스트, 최대 3회) · `explorer`(영향 파악)
- **스킬**: `contract-gate` · `impact-analysis`(기존 [Mod] 수정 시) · `test-spec`(테스트 명세·위치) · `tdd-verify`(실행 판정) · `code-audit` · `plain-writing`(이탈 사유 문장) · `default-reference`
- **템플릿**: `04.build` · `05.verify`(루프가 돌린 단위 테스트 기록)
- **도구**(있으면 씀): **ponytail**(플러그인 — 코드 쓰기 전 "안 만들어도 되나" 판단 주입) · LSP(타입·참조로 정확도 상승) · Context7(MCP — 쓰는 라이브러리의 최신 문서, 낡은 API 방지) · Joern(회귀 표면) · 화면 테스트가 있으면 브라우저(`/flow:verify`와 동일)

## 입력 (`$ARGUMENTS`)

| 인자 | 동작 |
|:--|:--|
| (비움) | 미완료 task 자동 식별 — **`2.task/NN`이 있고 `4.build/NN`이 없는 것**(`traceability`). 후보 2+·모호하면 확인 (임의 "최근" 금지) |
| `도메인/유닛` 또는 task 경로 | 그 대상으로 바로 구현 |

## 절차

**1. 대상 선언** (작업 전 필수)

**인자가 없으면 파일을 세어 재개 지점을 찾는다** (`traceability`) — README의 `상태`는 캐시라 낡을 수 있다.

```
[/flow:build] 대상 task: doc/01.work/{domain}/{NN.unit}/2.task/NN.name.md
         계약: .../3.contract/  → 이 설계로 구현합니다.
```

**여러 task가 남아 있으면 진행 상황을 함께 보여준다.**

```
[/flow:build] user/00.login — 파일에서 계산한 진행
    00.login-api   구현 ✅  검증 ✅
    01.session     구현 ✅  검증 —      ← /flow:verify 가 필요하다
    02.lockout     구현 —              ← 여기서 이어갑니다
```

- **번호가 빠져 있으면 알린다**(`00`·`02`만 있고 `01` 없음) — 스파인이 깨졌다는 뜻이다.
- **계산한 상태가 README와 다르면 알리고 `/flow:sync`를 권한다.** 여기서 README를 고치지 않는다.

**2. 사전 게이트** — `contract-gate`로 계약 검증. 규약은 그 스킬이 정본이다.

**실패 원인을 먼저 가른다.** 셋으로 갈리고 처리가 다르다.

| 에러가 말하는 것 | 무엇을 하나 |
|:--|:--|
| `command not found`·`Cannot find module`·네트워크 | **환경 문제다.** `/flow:setup`을 안내하고 멈춘다 — 계약을 고치려 시도하지 않는다 |
| **문법이 안 맞는다**(`'}' expected`) · **오타라고 컴파일러가 지목**(`Did you mean …?`) | **고치고 task `History`에 이탈로 적는다.** 뜻이 안 바뀐다 |
| **무엇인지 모른다**(`Cannot find name`) · **어느 쪽이 맞는지 골라야 한다**(`not assignable`) | **멈춘다** → `/flow:design`(구조가 맞나) → `/flow:spec`(계약 재작성) |

- **계약은 `/flow:spec`의 산출물이다.** `build`가 뜻을 바꾸면 그 계약을 쓰는 다른 task가 조용히 깨진다.
- **모르겠으면 멈춘다.**

**3. 영향 분석** — File Map에 `[Mod]`(기존 수정) 있으면 `impact-analysis`(1차 `code-graph`)로 회귀 표면 추출. 순수 `[New]`면 생략.

**`1.design.md`의 `엣지 케이스`를 함께 읽는다.** task는 규약상 **설계·화면을 복사하지 않고 ID로 가리킨다** — 가리키는 쪽을 안 열면 **엣지 케이스가 구현과 테스트에서 같이 빠진다.**

- 읽는 절은 `엣지 케이스`·(FE면)`화면 구조`뿐이다. 분석·데이터 구조는 `/flow:spec`이 이미 소화했다.
- **엣지 케이스마다 테스트를 만든다** — 정상 흐름만 통과하면 검증이 아니다.

**3-1. 스키마 변경이 있으면 먼저 처리한다** *(설계에 마이그레이션이 있을 때만)*

테스트가 DB를 쓰면 **마이그레이션이 먼저 들어가야** 돌아간다. 순서를 뒤집으면 테스트가 없는 컬럼을 찾는다.

| 순서 | 무엇 | 누가 |
|:--|:--|:--|
| ① | 마이그레이션 파일을 **소스 트리**에 쓴다 (그 도구가 정한 자리 — `db/migration`·`prisma/migrations` 등) | `builder` |
| ② | **개발·로컬에서 실제로 돌려 검증**한다 — 안 돌려보면 스크립트가 맞는지 모른다 | `builder` |
| ③ | **`doc/00.ref/02.db-schema/`를 지금 상태로 갱신**한다 | `builder` |
| ④ | 운영 적용 | **사람** — 배포 시스템으로. 여기서 하지 않는다 |

- **③을 빠뜨리면 아무 장치도 안 잡는다.** `02.db-schema`는 `doc/` 아래라 **드리프트 판정에서 문서로 취급**된다 — 마이그레이션만 들어가고 `doc/01.work/`가 갱신되면 훅·CI가 통과시킨다. 다음 세션이 **없는 컬럼을 믿는다.**
- **운영·스테이징 DB는 읽기만.** 접속 대상이 개발인지 확실하지 않으면 **실행 전에 묻는다**(`CLAUDE.md`의 `가드레일`).
- **되돌릴 수 없는 것**(데이터 삭제·비가역 변환)은 개발에서도 실행 전에 알린다.

**4. 테스트 우선(TDD)** — 로직·계산·분기는 task `Verification` 기준을 **실패 테스트로 먼저** 만든다. 단순 배선·설정·UI 텍스트는 생략 가능.

**어디에 무엇을 두나** — 규약은 `test-spec`, 실행 판정은 `tdd-verify`.

| 무엇 | 어디 |
|:--|:--|
| **실행되는 테스트 코드** | `tests/scenarios/` (소스다 — `doc/` 아님) |
| **명세와 결과** | `{유닛}/5.verify/NN.md` — **task와 번호·이름 1:1** |

- `/flow:build`가 돌린 단위 테스트도 **`5.verify/`에 기록한다.** 안 남기면 테스트를 돌렸는데 기록이 없어 `/flow:verify project`가 gap으로 잡는다.
- 같은 task를 다시 돌리면 **덮지 않고 in-place로 결과에 날짜를 더한다.**

**5. 구현↔테스트 루프** (`builder`⇄`verifier`, 최대 3회)

**ponytail이 있으면 `builder`에 판단 순서가 자동 주입된다** — *안 만들어도 되나 → 있는 걸 쓸 수 있나 → 기본 기능인가 → 그때 만든다*. 차단이 아니라 주입이라 루프를 방해하지 않는다. 없으면 `builder`의 수술적 변경 규칙으로 대체된다.

```
builder 구현 → verifier 실행
  Exit 0            → 통과
  Exit ≠ 0 (1·2회차) → 분석 → builder 재수정 → 재실행
  Exit ≠ 0 (3회차)   → 중단·사람 리포트  (자율 무한루프 금지)
```

- 계획 이탈(엣지케이스·설계 누락)은 보수적 선택 후 task `History`에 **Deviation**으로 즉시 기록 — *계획이 말한 것 / 코드가 드러낸 것 / 택한 선택 / 사유*. 이 로그가 `/flow:sync` 입력.
- 이탈이 **설계 결함**을 드러내면 멈추고 리포트.

**6. 전체 빌드** — `workflow.config.json`의 `build.command`로 1회 빌드한다. 테스트는 건드린 파일만 컴파일할 수 있어 **전체 컴파일 오류는 여기서만 드러난다.** 키가 비어 있으면 건너뛴다. 실패는 3회 루프에 넣지 않고 **즉시 리포트**.

**7. 기록** — task 번호와 1:1로 둘 다 남긴다.

| 파일 | 무엇 | 템플릿 |
|:--|:--|:--|
| `4.build/NN.md` | 구현 요약 · 변경 파일 · 계약 준수 · 이탈 **한 줄**(상세는 task `History`) | `04.build` |
| `5.verify/NN.md` | 테스트 명세 · 결과 · 결함 | `05.verify` |

최종 `code-audit` + `CLAUDE.md` 가드레일 점검.

## 종료 조건

- 계약 게이트 + 테스트 + 빌드 통과(Exit 0) · `4.build/`·`5.verify/` 기록 · task History 갱신
- **커밋·push 안 함** → `/flow:sync`로 동기화

## 가드레일

- **막히면 자율로 헤매지 말 것.** 3회 초과 실패·설계 결함·기존 테스트 깨짐 → 즉시 멈추고 원인·영향·권장을 리포트, 승인 대기. **테스트 약화·우회 절대 금지.**
- **설계 규격 임의 변경 금지.** 변경 필요하면 멈추고 `/flow:design`으로.
- **프로젝트 수준 결정은 ADR로** — `doc/02.decisions/`에 제안(사람 확인).
- **테스트 코드를 `doc/` 안에 만들지 않는다.** 실행 코드는 `tests/scenarios/`, 문서는 `5.verify/`다.
- 쓰기는 `builder`만. 커밋·push·merge는 `/flow:build` 일이 아니다. 운영 DB 직결·민감정보 하드코딩 금지.
