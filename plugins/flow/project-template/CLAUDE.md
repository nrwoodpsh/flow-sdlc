## 워크플로우

`flow` 플러그인을 따른다. 진입점은 상황에 맞게 고른다.

- **코드를 바꿨으면 `/flow:sync`로 문서를 맞춘다** — 드리프트 방지.
- **커밋은 요청이 있을 때 `/flow:commit`으로만** 한다.
- 진입점·흐름 상세는 플러그인이 갖고 있다 — **여기 옮기지 않는다.** 매 턴 실리는 파일이다.

검증 명령·계약 형식은 `workflow.config.json`에 정의한다.

## 가드레일 (절대 금지)

- **운영·스테이징 DB는 읽기만.** 쓰기·스키마 변경·삭제를 실행하지 않는다. 되돌릴 수 없다.
- **운영 MCP 이름에 `prod`를 넣는다** — `db-prod`·`api-prod`. 개발은 `db-dev`. **훅이 막아 주지 않는다** — 이름은 사람이 헷갈리지 않기 위한 것이고, **막는 것은 읽기 전용 계정이다.**
- **터미널 접속은 훅 밖이다** — `psql`·`mysql`로 직접 붙는 것은 못 막는다. **읽기 전용 계정으로 붙이는 것이 유일한 방어다.**
- **개발·로컬 DB는 전권.** 마이그레이션을 실제로 돌려 검증하고 시드·초기화도 한다 — 안 돌려보면 스크립트가 맞는지 모른다.
- **환경을 헷갈리면 사고다** — 접속 대상이 개발인지 확실하지 않으면 **실행 전에 묻는다.**
- **운영에 적용하는 것은 사람이.** Claude는 마이그레이션 파일을 작성하고 개발에서 검증까지 한다. 운영 적용은 배포 시스템·관리자 권한으로 격리.
- **마이그레이션은 소스 트리에** 둔다(그 도구가 정한 자리). **`doc/00.ref/02.db-schema/`는 지금 상태의 정본**이라 **같은 커밋에 함께 갱신**한다 — 안 하면 AI가 없는 컬럼을 믿는다.
- **`git push`·`merge`·`rebase`·`reset --hard`·`clean -f`·`filter-branch`·`filter-repo`·force-push 금지** — push·merge는 사람이 외부 툴로. **flow 훅(`guard-danger.sh`)이 Bash 도구 호출을 차단한다** — `gh pr merge`·`release create`·`repo delete`·`api` 쓰기도 같이. 다만 `eval`·변수 쪼갬·스크립트 파일로는 뚫리니 **무심코 치는 것을 막는 장치**로 읽는다.
- **민감 파일 커밋 금지** — `.env`, `*.key`, `*-prod.*` 등.
- **자동 커밋 금지** — 커밋은 사용자가 요청할 때 `/flow:commit`으로만. `/flow:sync` 등 다른 커맨드는 커밋하지 않는다.

**무엇이 기계로 막히나** — 나머지는 약속이라 어기면 아무것도 안 막는다.

| 금지 | 장치 |
|:--|:--|
| `push`·`merge`·`rebase`·`reset --hard`·`clean -f`·`filter-branch`·`filter-repo` · `gh pr merge`·`release create`·`repo delete`·`api` 쓰기 | ✅ **flow 훅** `guard-danger.sh` — **Bash 도구만.** `eval`·변수 쪼갬·스크립트 파일·python subprocess·MCP 로는 뚫린다 |
| **운영 MCP 쓰기** | ❌ **훅 없음** — SQL 내용 판정이 못 미더워 걷어냈다. **읽기 전용 계정이 유일한 방어다** |
| 코드↔문서 드리프트 | ✅ **git 훅** `drift-hook.sh` — **커밋 차단**(`pre-commit`). `--no-verify`로 넘길 수 있다 |
| 계약이 컴파일 안 됨 | ❌ 훅 없음 — **`/flow:spec`·`/flow:build`가 검증한다** |
| 자동 커밋 | ❌ 약속뿐 — `/flow:commit`이 커밋하므로 훅으로 못 막는다 |
