## 워크플로우

`flow` 플러그인을 따른다. 진입점은 상황에 맞게 고른다.

- **코드를 바꿨으면 `/flow:sync`로 문서를 맞춘다** — 드리프트 방지.
- **커밋은 요청이 있을 때 `/flow:commit`으로만** 한다.
- 진입점·흐름 상세는 플러그인이 갖고 있다 — **여기 옮기지 않는다.** 매 턴 실리는 파일이다.

검증 명령·계약 형식은 `workflow.config.json`에 정의한다.

답변 형식(판단형 5칸 · 보고형 6하)은 **플러그인 훅이 세션마다 주입한다** — 여기 옮기지 않는다.

## 가드레일

**차단 명령 목록을 여기 적지 않는다** — 정본은 플러그인의 `guard-rules.json`이고, **막는 것은 훅이지 이 문서가 아니다.** 매 턴 실리는 파일이라 사본을 두면 그만큼을 계속 내면서 플러그인이 목록을 늘려도 안 따라온다.

여기 남는 것은 **이 프로젝트에서만 뜻이 있는 것**이다.

- **운영·스테이징 DB는 읽기만.** 쓰기·스키마 변경·삭제를 하지 않는다. 되돌릴 수 없다.
- **개발·로컬 DB는 전권.** 마이그레이션을 실제로 돌려 검증하고 시드·초기화도 한다 — 안 돌려보면 스크립트가 맞는지 모른다.
- **환경을 헷갈리면 사고다** — 접속 대상이 개발인지 확실하지 않으면 **실행 전에 묻는다.** 운영 MCP 이름에 `prod`를 넣는 것은 사람이 헷갈리지 않기 위한 것이고, **막는 것은 읽기 전용 계정이다.**
- **운영 적용은 사람이.** 마이그레이션 파일 작성과 개발 검증까지가 AI 몫이다.
- **마이그레이션은 소스 트리에** 두고 **`doc/00.ref/02.db-schema/`를 같은 커밋에 갱신**한다 — 거기가 지금 상태의 정본이라, 안 맞추면 AI가 없는 컬럼을 믿는다.
- **민감 파일 커밋 금지** — `.env`·`*.key`·`*-prod.*` 등.
- **자동 커밋 금지** — 커밋은 요청이 있을 때 `/flow:commit`으로만.

**무엇이 기계로 막히나** — 층 수를 세지 말고 경로를 본다. 나머지는 약속이라 어기면 아무것도 안 막는다.

| 무엇 | 장치 |
|:--|:--|
| task 문서·요구 태그 없이 소스에 `Write`·`Edit` | ✅ **flow 훅** — 못 우회한다. `Bash` 경유 쓰기는 가드가 닿는 범위까지, MCP 파일 도구는 밖이다 |
| 되돌릴 수 없는 · 방어를 끄는 · 외부 상태를 만드는 명령 | ✅ **flow 훅** — **`Bash` 도구만.** `eval`·변수 쪼갬·스크립트 파일로는 뚫린다 |
| **운영 MCP 쓰기** · 터미널로 직접 붙는 DB 접속 | ❌ **훅 없음** — **읽기 전용 계정이 유일한 방어다** |
| 코드↔문서 드리프트 | ✅ **git 훅**(`pre-commit`) — 사람은 `--no-verify`로 넘기고, AI 경로에서는 그 플래그도 가드가 막는다 |
| 서버측 드리프트 게이트 | ⚪ **옵트인** — CI 파일 확장자를 벗겨야 돈다. **안 켰으면 이 층은 없다** |
| 계약 컴파일 · 자동 커밋 | ❌ 약속 — 커맨드가 검증하고 커맨드가 커밋한다 |
