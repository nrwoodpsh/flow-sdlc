- **근본 원인에 닿는 조치가 하나도 없으면 회고가 끝난 게 아니다.**
- **`어디로`를 비우지 않는다.** 안 적으면 조치가 이 문서에 갇혀 다음 스프린트에 아무도 안 본다.

**조치는 성격에 따라 갈 곳이 다르다.**

| 조치의 성격 | 어디로 |
|:--|:--|
| 제품이 지켜야 할 새 제약 | **`SYS-*` 요구** — `/flow:prd sys` |
| 모든 도메인이 지킬 기술 규약 | **`13.architecture` 크로스커팅 규칙** |
| 한 도메인의 판정 기준 | **`09.domain` 업무 규칙**(`DR번호`) |
| 지금 있는 결함을 고치는 것 | **버그 수정** — `/flow:run fix {유닛}` |
| 사람이 따라 할 절차 | **`04.ops/` SOP·런북** — `ops-doc` |
| 구조를 바꾸는 결정 | **ADR** — `02.decisions/` (`/flow:design`) |

- **여기서 요구·규칙을 직접 쓰지 않는다.** 회고는 기록이고, 실제 등록은 그 커맨드가 한다 — **가는 곳만 적는다.**
- **`P1`은 이 회고를 닫기 전에 착수한다.** 기한만 적고 넘기면 재발한다.
- **적어둔 것이 등록됐는지 확인된다** — `/flow:review doc 04.ops/`가 `어디로`의 ID를 요구 등록소와 대조한다. **미등록이면 리포트에 뜬다.**
