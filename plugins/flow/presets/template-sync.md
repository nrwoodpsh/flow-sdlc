# 템플릿 동기화 (업데이트 모드 전용)

`/flow:setup`이 **이미 세팅된 프로젝트**에서 읽는다. 새 프로젝트에는 해당이 없다 — 그래서 `setup.md` 본문에서 빼 두었다. **컨텍스트에 매 턴 실리지 않는다.**

**플러그인이 올라가면 템플릿도 바뀐다.** 이걸 안 맞추면 **커맨드는 새 규칙을 말하고 템플릿엔 그 절이 없다** — 새 규칙이 반만 작동한다.

```
03.templates/VERSION 의 flow:  값  ↔  plugin.json 의 version
   같다  → 건너뛴다
   다르다 → 아래를 파일별로 제시한다
```

| 상태 | 무엇 | 기본 |
|:--|:--|:--|
| **새 템플릿** (플러그인에만 있다) | 복사한다 | **복사 제안** |
| **바뀐 템플릿** | 무엇이 달라졌는지 요약해 보여준다 | **선택을 받는다** |
| **`고친 것`에 적힌 템플릿** | 프로젝트가 일부러 고친 것 | **건너뛴다** (`VERSION`의 목록) |
| 프로젝트에만 있는 템플릿 | 프로젝트가 만든 것 | **건드리지 않는다** |

## 출력 형식

```
[/flow:setup] 템플릿 동기화 — flow 0.8.0 → 0.9.0

  새 템플릿 (2개)
    + 16.runbook-check/     복사할까요?

  바뀐 템플릿 (5개)
    ~ 00.requirement/   `종류` 칸 추가 · AC → 완료 기준 · 유스케이스 상세 조건부
    ~ 09.domain/        업무 규칙 절 신설(DR번호)
    ~ 13.architecture/  화면 지도 절 신설
    ~ 05.verify/        기대값 출처 칸
    ~ 01.design/        mermaid → PlantUML
      → 각각 [덮기 / 건너뛰기 / 고친 것으로 표시]

  건드리지 않음
    = 02.task-doc/   (VERSION의 `고친 것`에 있음)
```

- **파일별로 선택받는다.** 한 번에 다 덮으면 프로젝트가 일부러 고친 것이 날아간다.
- **덮기 전에 `.bak-{날짜}`로 백업한다.** 되돌릴 수 있어야 한다.
- **`건너뛰기`를 고르면 `VERSION`의 `고친 것`에 추가할지 묻는다** — 다음 업데이트에서 또 묻지 않게.
- **선택이 끝나면 `VERSION`의 `flow:`·`복사:`를 갱신한다.** 건너뛴 것이 있어도 갱신한다 — 목록에 남아 있으니 추적된다.
- **이미 쓴 문서(`01.work/**`)는 건드리지 않는다.** 템플릿만 바꾼다 — 기존 문서를 새 템플릿에 맞추는 것은 `/flow:review doc`이 지적하고 사람이 판단한다.

## 용어가 바뀐 변경은 따로 알린다

기존 문서 전체에 걸리기 때문이다.

```
⚠ flow 0.9.0에서 `AC` → `완료 기준`으로 용어가 바뀌었습니다.
  기존 문서 12개에 `AC`가 남아 있습니다.
  → 템플릿만 바꾸면 새 문서와 옛 문서의 용어가 갈립니다.
     일괄 치환할까요? (조사도 함께 바뀝니다)
```

## 경계

- **새 프로젝트에서는 읽지 않는다** — `VERSION`을 새로 채우면 끝이다.
- **`01.work/**`의 기존 산출물을 고치지 않는다.** 템플릿만 다룬다.
